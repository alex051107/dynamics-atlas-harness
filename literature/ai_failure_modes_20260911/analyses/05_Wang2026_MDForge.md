# MDForge：稀疏模拟反馈下的智能体分子动力学管线设计 MDForge: Agentic Molecular Dynamics Pipeline Design under Sparse Simulator Feedback

## §0 一页说清

这篇论文问的是能不能用 LLM agent 自动化 MD 管线设计这件专家活，把管线设计当成开放式代码生成，让 agent 直接写 Python 代码，而不是从一个预先做好的固定工具箱里选调用。同时要在极稀疏、极昂贵的反馈条件下学习，每次试验（trial）要花 GPU-hour 级别的真实生产模拟才能拿到一个反馈信号，且这个信号只在整条管线跑完后出现一次。

做法是构建 MDForge：一个用"言语强化学习"（verbal RL，靠改写上下文而不是改模型参数来学习）驱动的代码 agent，核心机制叫 PRISM（Process-Reward Interpretation via Subsystem Mediation）。PRISM 把单一的终端标量奖励拆成两路密集信号：一路是从模拟器直接抽取的逐阶段物理诊断（准备、平衡、生产采样、分析四个阶段各有结构化诊断字段），另一路是三名专家（力场、采样、分析）组成的小组，两轮辩论后给出一条带主体归因的类型化点评（typed critique）。评测用 SAMPL 系列的主体-客体（host-guest）结合自由能挑战（CB[7]、OAH、CBClip），并做了一次前瞻性湿实验验证。

论文自己的答案：MDForge 在 CB[7] 上留出集 Kendall τ 达到 0.56，CBClip 上 0.47，明显高于 Trial-level feedback 基线的 0.24 和 0.20（§5.2）；在 SAMPL4 CB[7] 上，MDForge 自主设计的管线和人类专家的经典 pAPRika 管线留在同一方法论家族里，只在工程可靠性细节上偏离，恢复了专家排序效用的 78–82%（§5.4，Table 2）；部署到十个未见过的候选客体上，排名第一的候选经竞争性核磁共振（NMR）湿实验证实为皮摩尔级高亲和力 CB[7] 结合物（Ka≈8×10¹² M⁻¹，§5.5）。

最脆弱的假设有三层：全篇用的是"廉价 MD"配置（约 2 GPU-hour/guest），作者自己承认更高保真度下排序结果是否依然成立"留给未来验证"（Limitations）；湿实验只测了十个候选里的第一名，不代表整个排序都被验证过；三个基准都是主体-客体系统，没有蛋白柔性，只是蛋白-配体结合的一个必要但不充分的代理场景。

对 Dynamics Atlas 的用处：论文里"静默的 MBAR 假收敛"这个具体机制，以及"逐阶段诊断加上类型化点评能把这类沉默错误变成显式拒绝"的量化效果（分析阶段拒绝率从 0 变为非零，同时中途崩溃率从 51% 降到 0%），直接对应我们最核心的关切，判断某个系综量到底有没有收敛证据。它不能替我们决定的是：MDForge 本身在设计新管线，不是在审查已有数据是否可信，它用的重叠度阈值（0.03/0.05）是这篇论文自己设定的经验值，不是普适物理定律，能不能直接搬到 Dynamics Atlas 的场景需要我们自己检验。

## §1 为什么会有这篇论文

Introduction 和 Related Work 交代了动机：设计一条新体系的 MD 管线历来需要训练有素的科学家投入大量时间，因为跑一次模拟本身很贵，试错空间被严格限制。一个真正的专家会先看体系的化学性质、电荷分布、刚性、结合模式，这些观察决定所有下游选择，包括力场家族、平衡schedule、采样协议、restraint方案、estimator；跑完之后专家读诊断信息（divergence traces、自由能收敛图、restraint-release artifacts），定位是哪个子系统出了问题，再针对性地修改。既有的 MD agent（MDCrow、MDAgent、DynaMate）都走工具编排路线，从一个预定义的固定工具箱里选调用，这类似专家挑选管线零件的动作，但只能从固定库里选，窄化了专家实际可以组合的空间；更关键的是，这些系统都没有用上工作流返回的反馈，尽管这个反馈虽然稀疏，正是专家依赖的迭代依据。真正的技术难点在于：每个 trial 都要付出 GPU-hour 的成本，一个任务的 trial 预算很小，远远不足以支撑典型意义上逐步迭代更新行为所需的样本量。

## §2 任务、数据与评测怎么建

任务单位是 SAMPL 系列的主体-客体结合自由能挑战：CB[7]（来自 SAMPL4）、OAH（来自 SAMPL4）、CBClip（来自 SAMPL5）。刚性大环主体扮演蛋白口袋的角色，任务是计算小分子客体相对已知实验参考值 ΔGexp 的结合自由能。这个设定保留了蛋白-配体结合的热力学机制（水置换、离子溶剂化、非谐客体采样），去掉了蛋白柔性，因此在这里做得对是full-protein场景的必要前提和公平压力测试（§5.1）。每个主体的客体集合切分成四个客体的训练集（对 verbal RL 反馈可见，选取覆盖实验 ΔG 分位点位置）和其余客体作为留出测试集，具体划分见附录 Table 3。docked pose 事先给定，实验参考值 ΔGexp 对 agent 保密。使用廉价 MD 配置，每个客体在单个 A40 节点上约跑 2 GPU-hour。

Gold 参考没有单一"正确管线"这种东西，用的是留出客体上的排序指标（R²、Spearman ρ、Kendall τ）相对实验 ΔG 打分，从 N=5 次成功试验中选训练集 τ 最高的那次作为该主体的最佳结果（§5.1）。评测特意用排序类指标，因为 MD 预测本身带有方法特定的系统性偏差，比如 GAFF 力场对阳离子型 CB[7] 客体存在广为人知的过度结合偏差，用绝对误差会把这种系统偏差和真实排序能力混在一起。

关于 evaluator 会不会放过错误答案，论文的基线阶梯设计本身就是第一层过滤：No-feedback（一次性代码生成，无点评无执行信号）和 LLM-critic（只审阅不执行）两种基线在每个主体上都是 0/5 可运行，Step-level feedback（工具调用返回中间结果但没有跨 trial 记忆）也只有 1 到 2/5 可运行，只有引入跨 trial 记忆的 Trial-level feedback 和 MDForge 能稳定做到 5/5 可运行（Table 1）。这说明"跑不出来"不会被误判成"跑对了"，但也说明排序指标只在能跑通的 trial 里做比较。更值得注意的是 Figure 3c 揭示的一个真实的放过案例：不装逐阶段诊断的消融版本（"w/o Stage diagnostics"）报告了 56% 的干净成功率，但论文明确写道这 56% 里包含了本该被收敛 guard 拒绝的结果，也就是说没有装 guard 时，agent 会把 MBAR 重叠度不足、没有真正收敛的自由能计算当作干净成功报告出来，直到装上 PRISM 的分析阶段 guard 之后，这类情况才从"clean success"变成显式的"analysis-stage refusal"。这是"evaluator 会放过错误答案"的一个直接、论文自己承认的例证。

## §3 失败逐条讲

**静默的 MBAR 假收敛（silent false convergence），本篇最核心的失败**（§4.2、Figure 3c/3d）。定义是：在没有逐阶段结构化诊断和显式收敛 guard 的情况下，分析阶段可能在 MBAR 重叠度不足的情况下依然给出一个数值上的自由能结果，呈现为一次"clean success"，但实际上并没有真正收敛。论文给出一个完整的案例链条（Figure 3d）：`04_analysis.py` 在某次 trial 里报出 `mbar_overlap_above_0p03: False` 这个结构化字段；分析专家读到这个诊断后给出的判断是"MBAR false convergence – no overlap guard"；Code agent据此在指定文件的指定位置加了一行修复（`if min_adj < 0.05: raise ...`），不是大范围重写。数字上，Figure 3c 显示"w/o Stage diagnostics"消融的中途崩溃率从 51% 降到 MDForge 的 0%，同时"analysis-stage refusal"这一失败类别只在装了逐阶段诊断之后才出现，因为这个拒绝分支本身就是新引入的行为，此前根本不存在这条路径。论文认为的根因是：单一的终端奖励（一次 trial 跑完只给一个标量误差）无法定位到具体是哪个子系统出了问题，不装结构化的中间诊断，agent（或者任何观察者）就完全没有信号能识别"数值上给出了结果但物理上不可信"这种情况。

**缺乏类型化诊断时，agent 无法区分"改进"和"退化"，导致有效管线被丢弃**（Figure 3a）。定义：没有子系统归因的点评时，agent 不能可靠判断一次修改究竟是变好了还是变差了。数字上，"debate-only"消融（保留多专家辩论但去掉逐阶段诊断）在第 3 次 trial 达到 τ=0.47 的峰值，随后崩溃到 0.16，而完整的 MDForge 单调爬升到 τ=0.56。论文认为的根因是：没有针对具体子系统、类型化的信号，agent 无法区分一次改动是真正的改进还是回退，最终把一个原本能用的管线换成了更差的版本。

**AI+非专家管线偏离方法论家族**（Table 2，这个案例本身不算数值错误，但揭示的是防护缺失而不是计算错误）。定义：一名化学非专家借助 LLM 编码辅助拼出的管线，在方法选择上偏离了专家默认路线，比如用 z-PMF umbrella 而不是标准的 Attach-Pull-Release（APR），且没有 MBAR 重叠度/收敛 guard。数字上，这条 AI+非专家管线在 SAMPL4 CB[7] 上拿到 ρ=0.61、τ=0.47、R²=0.44，而 MDForge 自主运行达到 ρ=0.68、τ=0.56、R²=0.58，人类专家的 pAPRika 参照是 ρ=0.83、τ=0.68、R²=0.74（§5.4 正文明确给出 MDForge 恢复了专家排序效用的 78–82%）。论文认为的根因是：LLM 编码辅助会把非专家引向一条"defensible 但方法论上不同"的路线，这条路线本身未必不合理，但系统性地缺少专家会默认加上的收敛防护措施，属于防护缺失而不是单纯的计算错误。

**基线层面连可运行代码都产不出来**（Table 1）。定义：完全没有执行反馈或跨 trial 记忆时，agent 连代码层面的可执行性都无法保证，这是比"数值是否正确"更基础的一层失败。数字：No-feedback 和 LLM-critic 在三个主体上都是 0/5 可运行，Step-level feedback 只有 1 到 2/5，只有引入跨 trial 记忆的方法（Trial-level feedback 和 MDForge）才能做到 5/5。论文认为的根因是：缺少执行反馈或缺少跨 trial 记忆时，agent 没有办法从此前的失败里学习，甚至连基本的代码可执行性都无法收敛。

## §4 补救和效果

PRISM 的两个组成部分（逐阶段诊断、多专家辩论）分别都有量化的消融对照。完整 MDForge 在 CB[7] 上达到 τ=0.56，去掉逐阶段诊断只保留辩论的"debate-only"版本先冲到 0.47 再崩溃到 0.16，两个都没有的方法停留在 τ≈0.20 附近（Figure 3a，§5.3）。成本上，四种方法在第 5 次 trial 时的累计花费都落在 68 到 78 美元区间，MDForge 早期的每 trial token 开销在编辑变得局部化之后被摊销，说明 τ 的提升没有付出明显的额外成本（Figure 3b）。失败类型的转变是最直接的补救证据：中途崩溃率从 51%（两个组件都没有）降到 0%（MDForge），但同时新出现了"analysis-stage refusal"这个此前不存在的类别，因为这个拒绝分支本身是收敛 guard 才带来的行为（§5.3，Figure 3c）。对专家对齐程度，Table 2 显示 MDForge 留在专家的方法论家族内（GAFF2+AM1-BCC、APR、MBAR），只在工程可靠性细节上偏离，恢复专家排序效用的 78–82%，同时在三项排序指标上都超过 AI+非专家管线。前瞻性湿实验验证是最强的效果证据：应用到 10 个未见候选客体上，排名第一（Bromantane）提交竞争性 ¹H NMR 检测，krel 平均值 4.26（三个不同摩尔比样本），换算得到 KaBrom≈8×10¹² M⁻¹（ΔGexp≈−17.6 kcal/mol），落在已发表 CB[7] 结合物的皮摩尔高亲和力区间（§5.5，Figure 4）。

未测的部分要写清楚：更高保真度 MD 配置（更长的生产采样、更精确力场、显式极化）下这套排序比较是否依然成立，论文自己说"留给未来验证"（Limitations）；十个候选客体只测了排名第一的那个，其余九个的排名没有经过湿实验验证；不同 backbone 模型下 PRISM 机制的鲁棒性未测，全文统一用 Claude Opus 4.7 作为 backbone（附录 C）。

## §5 证据支撑到哪里、没覆盖什么

**Observed**：Table 1、Table 2 的排序指标数字，Figure 3 的消融曲线，湿实验 NMR 的测量结果，这些都是论文直接报告的实验数据。

**Inference**："MDForge 的管线是专家会认可的那种管线"这个判断依赖于作者选定的单一参照物（经典的 pAPRika 管线），是一种典型性论证而不是穷举式验证；"逐阶段诊断加类型化点评是解决静默假收敛的正确机制"这个因果解释建立在 N=5 trial、3 个主体的小样本消融之上，样本量不大。

**最脆弱的假设**：廉价 MD 配置（约 2 GPU-hour/guest）下得到的排序结果是否在更高精度 MD 下依然成立，未经验证，只是作者的预期；三个基准都是主体-客体系统，没有蛋白柔性，是蛋白-配体结合的代理场景而非替代品；训练客体的选取（按实验 ΔG 分位点覆盖）本身也是一种向 agent 注入的先验知识，如果换一批训练客体排序结果是否稳定，论文没有测试。

**一个最强反例**：论文自己在 Limitations 里写明，MDForge 仅在能获得成熟 MD 工具栈和已确立 SAMPL 基准的主体-客体系统上得到验证，"没有同等成熟的蛋白-配体结合、膜蛋白插入等公开基准"，导致经验触达范围明确受限（Limitations，Benchmark scope）。这提醒我们不能把这里的成功泛化到真实蛋白靶点的自由能计算场景。

## §6 映射到 Dynamics Atlas

对静默 MBAR 假收敛（Figure 3c/3d）：[论文事实]。[分析推断] 这和我们目录里"应用一条规则但规则不适配这个数据类型"（6 例）以及"跳过计算"（2 例）都有一定亲缘性，但更精确的描述是我们没有专门记录过的一类，即"缺少显式收敛判据时，agent 把未收敛结果当作已收敛结果报告"。这直接落在 Dynamics Atlas 的核心决策点上：我们判断"40 个一微秒跑能否给出一个 state population"，本质上问的正是同一类问题，是否有足够的采样或 round trip 支撑这个量的收敛声称。MDForge 这个案例给出了一个可操作的机器可检判据模板（重叠度阈值加显式 raise），值得我们参考其"把判据结构化成可执行 guard"的思路，但阈值本身（0.03/0.05）是这篇论文自设的经验值，需要我们自己针对蛋白系统重新标定。

对 Table 2 里 AI+非专家管线"方法论上偏离但依然 defensible"的现象：[论文事实]。[分析推断] 提醒我们，我们目录里"应用一条规则但规则不适配数据类型"这一类失败不仅可能来自 agent 判断错误，也可能来自 agent 选择了一条"看似合理但和标准做法不同"的路线，而这条路线本身缺乏应有的防护（比如收敛 guard）。这是"规则缺失"和"规则误用"两种不同子情形，我们目前的分类可能没有明确区分。

对缺少类型化诊断导致有效管线被丢弃（Figure 3a）：[分析推断] 这类似我们的"revision losing content"（1 例），但机制层面更具体，问题出在判断依据不足导致把好的版本换成了差的版本，而不是修订动作本身丢内容。这提示我们在做基于修订的迭代时，判断"这次修改是否变好"本身需要独立、类型化的信号，不能只靠一个综合分数。

对 MDForge 用排序指标而不是绝对误差规避力场系统偏差这一设计思路：[项目提议] 我们判断"两个来源的量是否可比"时，可以借鉴这里的思路，即当两个数据来源之间存在已知的系统性偏移（比如不同力场对同一体系的系统偏差）时，判断是否可比或许应该优先看排序或趋势一致性而不是绝对数值吻合度。这是一个可以在我们协议里讨论的提议，不是这篇论文已经在蛋白系统上证明过的普适方法。

## §7 可以直接进规则表的候选

1. **任何自由能或收敛类分析步骤，必须显式检查并记录重叠度或收敛判据（如 MBAR overlap），该字段缺失时默认视为未收敛，不得默认接受数值结果**。来源：§4.2、Figure 3d 的 `mbar_overlap_above_0p03` 字段与 guard 设计。防止：静默假收敛被当作有效结果接受。阈值参考：论文用 0.03/0.05 作为重叠度分界（`if min_adj < 0.05: raise ...`），可作为我们自己判据的起点，不宜直接照搬到蛋白体系。

2. **涉及重新生成或修订某个中间产物或结论的操作，修改前后必须各自附带独立、可对比的诊断信号，不能只凭一个综合分数判断改动方向**。来源：Figure 3a debate-only 消融从 τ=0.47 崩溃到 0.16 的机制说明。防止：revision losing content 类失败，把好版本换成差版本。

3. **涉及自由能或结合亲和力类计算时，优先报告和比较排序或趋势一致性指标（如 Spearman/Kendall），而非只比较绝对数值**，尤其当已知存在方法特定系统偏差（如力场偏差）时。来源：§5.1、Table 2 关于 GAFF 阳离子过度结合的讨论。防止：把带系统偏差的绝对数值差异误判为"不可比"或"计算错误"。

4. **对多阶段、多子系统的分析流程，要求每个阶段边界都产出一个结构化、机器可读的诊断记录，而不是只在流程末端产出一个综合结果**。来源：§4.2 逐阶段诊断设计（Dπ 的 K=4 阶段结构）。防止：把复合性判断错误压缩成单一终端信号，导致中间问题不可追溯。
