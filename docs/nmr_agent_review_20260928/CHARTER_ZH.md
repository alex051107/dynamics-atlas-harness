## 2 这一阶段要达到的效果（用户）

- **问题在哪里。** Agent 默认的做法是拿到数据、跑分析、验证结果。它和科学家的差别在卡点，尤其是边缘情况：科学家能敏锐地判断这时该做哪些分析。
- **目标一：沉淀科学家的做法。** 把蛋白动力学科学家在卡点上的做法整理成 Agent 可用的工作流。来源不限于五篇论文。工作流规范的是 Agent 在卡点上怎么想，不把每一步定死，也不切成细条目让它查表。规则表已经试过，效果不好。
- **目标二：体现 Agent 自己的思考。** 在 ReAct 过程上比较几种模式，看科学家的经验在什么时候、以什么方式进入 Agent 的推理。这和 Soojung 提的"比较小规则和大规则"是同一个问题。
- **近期要证明的。** 用几篇论文证明：有了整理好的工作流，Agent 在卡点上的判断更接近科学家。参照是论文作者的做法和结论。作者的做法不是唯一正确答案：与作者等价或论证更好的做法也算对，分歧交给 Gina 判断。
- **长远。** 沉淀本身也自动化：由更高一级的 Agent 读论文和运行记录，改写工作流。工作流和模型无关，任何能调 API 的模型都能用。LangGraph 这类框架最后才用，用来把验证过的工作流固定下来。
- **和数据库的关系。** 工作流是建数据库的方法。数据库条目是以后的产出，不是这一阶段的检验对象。

## 3 三个词各指什么

- **工作流**：科学家的分析方法。重点是卡点上的思考方式：说清预期和实际看到的差在哪里；先列平凡的原因（数据处理、校准、样品、模型假设），再列有意思的原因；选一个能把这些原因分开的分析，动手前说清每种结果意味着什么；按结果更新判断，确有必要才增加复杂度；结论只说到证据支持的程度。再加上从论文提炼的方法经验和真实卡点的范例。工作流是要改进、要沉淀的对象。
- **Agent**：执行者，即一个模型加一套分析工具。它按工作流分析数据，在卡点上自己判断。
- **框架**：把验证过的工作流固定下来的程序外壳，最后再做。

工作流有没有用，要在同一个卡点上比较：有工作流和没有工作流，以及科学家经验进入推理的时机不同，Agent 的判断差在哪里。

## 4 怎样算做成

- **卡点判断。** 在论文作者遇到过的卡点上，有工作流的 Agent 提出的检查，比没有工作流时更接近作者的做法，或经 Gina 判为等价或更好。题目要能排除模型背答案：去掉蛋白名、残基号和引文；先测模型能不能直接说出作者的做法，能说出的题单独统计；另加几道改过结果、任何论文里都没有答案的反事实题。
- **真实数据。** 在有原始数据的案例上，Agent 真的去执行分析，自己发现卡点，得出有证据支持的结论。至少要有一个案例是写工作流时没用过的论文。
- **结果如实报告。** 如果工作流没帮上忙，这也是一个结论。
