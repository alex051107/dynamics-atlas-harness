# 方案 v7：流水线每一步为了什么

2026-09-28。Claude 起草，与 Fable 讨论两轮后定稿。取代 v4–v6；回到原任务书：从五篇论文沉淀科学家处理卡点的方法，让不看答案的 Agent 按它分析真实数据，按失败改进，再换案例。

## 1 三样东西各是什么

**工作流**是一本卡点条目库，外加一本只追加的失败账本。每条条目写：数据里出现什么情况、可能是哪几种原因、做什么分析能把它们分开、结果怎么读、什么时候该停或弃权，另记来源、状态和作者。条目只写数据里看得到的情况，不写蛋白名、状态数和具体数值。条目的状态分三种：候选、确认、退役。这本条目库跟用哪个模型无关，是要积累、要复用的东西。六段流程只是条目的目录。

**Agent** 是拿着条目库去分析数据的模型，做三件事：
- 从数据里认出眼下是不是某条卡点，按条目去做。
- 碰到条目库里没有的卡点，自己反思：预期和结果哪里对不上，可能是哪几种原因，做什么检查能分开；解决不了就弃权。这是运行中的反思。
- 案例跑完、拿到反馈后，自己检查错在哪里，写进账本，并提出候选条目。这是运行后的反思。

**人**给出参照答案，对 Agent 提的条目只做三种处理：接受、拒绝、追问，不替它改写。每条条目都记作者。

**框架**等条目确认得够多了，再把它们固定下来。

**怎么分清是工作流的功劳还是 Agent 的功劳。** 运行轨迹里每个卡点归入三类：
- 照着条目机械执行就能做对。这是工作流的功劳，写程序也能做到。
- 有条目，但要看具体数据才用得上。这是两者合作。
- 条目库里没有，靠 Agent 自己解决。这是 Agent 的功劳。

Agent 的价值，就是后两类卡点的数量和质量，再加上它提出、并且后来在别的案例上被确认的条目。如果所有卡点都属于第一类，诚实的结论就是"这些案例写程序就够了"。设计上必须允许这个结论出现。

## 3 RfaH 怎样检验反思

RfaH 2025 的 8 条片段不放进 v1。现有工作流里对应的那条"冻结参数去预测另一类数据"也摘掉。这篇论文的核心卡点是：CEST 拟合出的两态参数解释不了 CPMG。它在 v1 里没有对应条目。

- **组 1，用 v1（没有这个卡点的条目）。** 带流程和带反思的两组各跑 3 次，这本来就是任务书里的 B/C 比较。看 Agent 能不能从数据里自己发现参数解释不了另一类数据，并做区分性检查。跑完让它做运行后反思、提候选条目，再拿封存的论文做法对照，比三项：触发是否相同，检查是否相同，停止条件是否相同。另查候选条目有没有通过去答案检查。对照标准在拆封前定死，由没写过片段的会话来比。
- **组 2，用 v1 加回这些条目。** 跑 2 到 3 次，作能力上限的对照。组 1 失败时，用它区分"反思没发现"和"工具做不到"。
- 只给工具的一组（A），按任务书最后跑 3 次。每组 3 条运行，逐条报告，不报均值。

## 4 能力上限，跑之前就写明

- 有原始数据的论文只有两篇，真正的迁移检验只有 RfaH 这一次。
- RfaH 2012 和 2025 研究的是同一个蛋白，2012 那篇很有名，模型的先验知识压不掉。打分时每个卡点都要区分：是数据驱动的（引用了具体残基上参数对不上），还是先验驱动的（引用"RfaH 会换折叠"）。
- 现有工具最多拟合三态。RfaH 论文里"逐个加隐藏态、最后拓扑不唯一"那一步，这轮测不了。能测的是：发现两态不够，不硬定状态数，承认工具不足。
