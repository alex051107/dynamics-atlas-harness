# 方案 v6：沉淀科学家在卡点上的额外分析，证明 Agent 能靠它把分析做出来

2026-09-28。Claude 起草，Fable 两轮反驳后定稿。取代 v5；v5 的八步判断清单降为最后"写条目"一步的格式要求。

## 1 我们在做什么

科学家分析 NMR 构象交换数据，真正的功夫不在第一遍拟合，在卡住之后：拟合对不上、参数分不开、信号消失、次态可能是样品问题。这时他们会想到几种解释，挑一个额外分析去区分，看结果，再决定下一步。我们要做的是把这些"卡点上的额外分析"整理成一套可以反复使用的流程，让 Agent 按它分析真实数据，并且在卡住时自己认出来、自己选下一步。数据库条目是分析做完后的产出。

## 2 假设

拆成三条，分别检验，免得一条失败时分不清是谁的问题。

1. **卡点能写成有限的一套卡片。** 每张卡：触发现象、几种竞争解释、要做的额外分析、每种结果的含义、下一步。在没参与整理的新病例上，实际遇到的卡点大部分能在卡片里找到。
2. **Agent 的判断有用武之地。** 有些卡点的触发条件能写成阈值（χ² 超过多少就加一个态），程序就够了；有些写不成（残差是不是有系统结构、几种解释先查哪个），或者根本不在卡片里。在这类卡点上，带卡片的 Agent 应该比同一张图写成的程序做得好。如果做不到，结论就是"写程序"，这也是有效结果。
3. **按卡片分析出的结果可信。** 与作者一致的，是在各种模型拓扑下都稳定的量；作者自己也分不清的地方，Agent 也要并列或弃权，而不是硬选一个。

## 3 沉淀的是什么

- **卡片库。** 来源三个：五篇论文拆出的 37 条片段；我们自己在 K-Ras 运行里撞到、论文里没有的卡点（如高信号残基没进拟合、CEST 符号初值陷入局部解、分区平均掩盖区域差异）；三份长计算的结论（例如三态模拟说明"三态与两态拟合优度相近时，拓扑要弃权"）。触发条件写成抽象条件，不带蛋白名。
- **图。** 卡片连成一张图：节点是分析，边是卡点触发条件。先写成确定性程序，它既是对照组，也是以后 LangGraph 的骨架。Agent 接入后，只在需要判断的节点上替代程序。
- **工具。** 真计算：拟合、冻结参数跨实验预测、参照比较、提交 ChemEx。探索阶段用本地快引擎，终值才送 Longleaf 跑 ChemEx，否则每个分支要等四小时。
- **失败账本。** 每次失败归入五类，每类有固定去处：没认出卡点、认出但选错分支，改卡片的触发和解释；分支对但工具失败，改工具；分析对但读错结果，改卡片的"结果含义"；遇到图外卡点，新增一张卡。

可复用分四级：只有文字卡；每张卡有机器能判的触发条件和工具调用规格；在卡片作者没见过的病例上不改卡就能跑通；Gina 自己拿一个病例跑通，不需要我们。现在处在第一级。

## 4 验证的是什么，怎么判

- **覆盖**：只在非设计病例上算，也就是卡片作者没读过的论文。第一个这样的病例要向 Gina 要，她本来就计划手工做 5–10 例。
- **Agent 的判断**：同一病例跑三组。确定性程序一条；带卡片的 Agent 三条；不带卡片、只有工具的 Agent 三条。看分支轨迹，不看最终数字。判据是"是否出现过"：三条里至少一条在某个卡点上认出并选对分支，记为这组能做；三条都没有，记为没观察到。三条不够谈比例，只够谈有没有。只有 Agent 在程序"写不成阈值"的节点上赢，才算 Agent 的价值；在有阈值的节点上赢不算。阈值由我们先写好冻结，不看 Agent 的结果再调。
- **反思**：每个节点记"预期、观察、选了哪个解释、做了什么分析、结果"。单独数两件事：Agent 因为自己跑的检查改了结论的次数；Agent 提出卡片里没有的新卡点的次数。因为提示而改结论不算。
- **结论**：按稳定量和弃权一致性判，不按"和论文一样"判。

## 5 到目前为止的结果

- **K-Ras（开发病例）。** Agent 加工具算回了论文的交换参数。它确实做了几种额外分析：CEST 符号多起点扫描、三态拟合加 BIC 比较、GDP 对照样品、逐区参照比较。有的是它自发做的，有的是提示给的。带反思的一组抓到两个真实错误，只跑了一次。流程本身的贡献没有被检验。
- **之前的长计算在干嘛。** ChemEx 交叉验证、三态可辨识性模拟、RfaH 方法复现，都在回答"工具和数据靠不靠得住"，是必要前提，但没有一个在检验卡片或 Agent 的反思。它们的结论也没有转成卡片，只躺在报告里。RfaH 复现只做到定性：CEST 两态拟合出的 kex 是 5.8，论文是 3.3；pB 是 14%，论文是 25%。原因很可能是只用了主态峰。八步判断清单和第三轮评分，是真正偏离主线的开销。
- **卡片库**目前以 37 条论文片段的形式存在，没有编成图，没有在非设计病例上用过。

## 7 两个问题的回答

**为什么不直接写程序。** 程序要先写，它就是图，也是对照组。Agent 的价值只在两处，而且可以被实验推翻：一是触发条件不是阈值而是模式的节点；二是图上没有的卡点，程序会停下或者悄悄算错，Agent 应该能解开，或者带理由弃权，并提出一张新卡。预测是：卡点都在图上时，程序和 Agent 差不多；有图外卡点或触发模糊时，Agent 更好。两种情况下 Agent 都不比程序好，就改成写程序。

**搭 LangGraph 的意义。** 图一旦定下来，就可以用 LangGraph 固定成可重复运行的流程，任何能调 API 的模型都能接到判断节点上。所以第 5 步写确定性运行器时就按图的结构写，Agent 节点在第 6 步之后再接入。
