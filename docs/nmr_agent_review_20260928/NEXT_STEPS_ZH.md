# 下一步计划与判断理由（2026-09-28）

## 1 判断

主线从"从原始弛豫色散曲线重拟已发表蛋白"改为"BMRB 条目分诊"：给 Agent 一个 BMRB 条目和关联 PDB，不给论文，让它判断这个蛋白是否存在慢交换的替代态，产出一条数据库候选条目或明确弃权。

理由三条，出处见 `IDEA_AND_FIT_ZH.md`：
1. 合作者要的产品是数据库本身。Soojung 在 9-17 会上说主交付物是数据集，做法是用 Agent 过一遍 PDB 和 BMRB，把没人标注的替代态找出来标上。
2. 判据是 Gina 的定义：APO、运动慢到 NMR 上出现两个分开的峰。这是"有没有、在哪些残基"的判断，不是交换速率的数值。
3. K-Ras 的结果说明数值靠工具就能拿到，Agent 的价值在判断、检查和弃权。这正是分诊需要的能力，而且 BMRB 有成千上万条条目，原始色散曲线全球只有约十个蛋白。

K-Ras 这套（19 个工具、封存答案、打分、行为检查）不丢。遇到有原始色散数据的条目，它作为分诊第三段的深分析分支被调用。

## 2 今天：分诊试点，6–8 条

- **模型**：DeepSeek（deepseek-chat，OpenAI 兼容接口，支持函数调用）。key 放环境变量，不进仓库、不进对话。现有 OpenRouter 循环的接口地址在 `agent.py` 写死，加一个环境变量覆盖，约半小时。
- **样本**：3–4 条正例（论文报告慢交换替代态的蛋白的 BMRB 条目），3–4 条负例（同类蛋白、论文说单一态）。从五篇源论文与 Gina 的论文清单里选。先把"论文说了什么、哪些残基"写进封存的答案表，再跑。
- **Agent 能用的**：条目号、BMRB 条目读取、PDB 查询、沙箱 Python、提交工具。题面写"判断是否存在慢交换替代态，允许弃权，必须引用具体数据特征"。
- **成功标准**：≥6 条判定（有/无/弃权）与论文一致；每个"有"都指向条目里真实存在的数据特征（同一残基重复指认、第二套位移表、连片缺指认），没有编造；负例上弃权多于硬报。
- **主要风险，也是这次要回答的问题**：很多论文里的"两个峰"可能根本没沉积进 BMRB，只写在正文和图里。如果正例召回很低，说明 BMRB 的沉积内容本身不够支撑分诊，数据库要从别的来源补（文献全文、原始谱图存档）。这个结论对建库同样有用。
- **产出**：每条一个候选条目 JSON 和报告，一张 8 行的人机对照表。明天请 Gina 判级。
