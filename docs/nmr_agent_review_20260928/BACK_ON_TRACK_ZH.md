## 1 我们在验证什么

## 4 Workflow 怎样被检验

每条运行六项打分，前三项对参考答案，后三项对论文与流程正本：

1. 数值：kex 中位数偏离参考 ≤25%。pB 与 |Δω| 只在数据能把二者分开时打分（多场强或慢交换）；单场强快交换下二者不可分，正确答案是报告可辨识的组合量并明确弃权，弃权计满分，硬给数字计零分。CPMG 数据不含 Δω 符号，不打符号分。
2. 状态数：Agent 自选的态数与参考一致，并给出选择依据。
3. 残基覆盖：拟合残基集合与参考一致，丢弃的每个残基有记录理由。
4. 结构解释：指认的交换区域与论文指认的结构元件一致（AQADK：LID 与 NMP 结构域铰链）。
5. 检查步骤：是否做了流程正本第 4–6 段规定的检查（场强依赖、快交换残基处理、全局与逐残基拟合比较、可辨识性）。
6. 负对照：打乱数据后是否正确报告无交换或不可拟合。

**"流程有没有用"的最小设计。** K-Ras 已有 A/B/C 各 1，只能说差异存在。Hypo 跑 A×3、B×3，AQADK 跑 A×1、B×3。若 Hypo 上 B 在第 4、5 项得分高于 A、第 1 项相同，加上 K-Ras 同向的结果，就够说"流程不改变数值，改善解释与检查"，两个蛋白、两种数据来源。

**跑完后能说的**：在三个蛋白（一个开发用、两个新）上，不知道答案的 Agent 恢复了两态交换参数；六段流程对解释与检查有可复现的贡献；确定性检查能区分工具正确与 Agent 正确。

**不能说的**：跨方法（CEST、多态）泛化；批量能力，因为全球公开原始弛豫色散数据只有十来个蛋白；AQADK 是独立验证；对科学家未分析过的数据库构象有发现能力，那需要至少一个无参考答案的蛋白被后续实验证实。

## 5 给 Codex 的规则

1. 只有在论文正文、SI、存档 README 三处都查过之后才能标 blocked，并写下查了哪三处、缺哪个字段。实验条件默认在 Methods 里。
2. 交付不是终点。每次交付后直接开始清单上的下一步，只在两个人工门前停：参考答案封存、结论用词。
3. 未提交的改动当天处理，提交或丢弃，分支上不留隔夜 diff。提交信息不加 Co-Authored-By。
4. 不新建文档。进展写进任务目录固定文件集，计划只有本文件一份。
5. 案例包交付前离线跑通验证脚本和打分脚本各一次，失败的不交付。
6. 有疑问时提出一个问题并附默认选项；默认选项无风险就先按默认做，不等回复。
