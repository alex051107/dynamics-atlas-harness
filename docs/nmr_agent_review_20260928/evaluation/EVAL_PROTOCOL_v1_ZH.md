# 评测协议 v1（案例线，2026-09-26）

用于 RfaH 2025 首轮及以后的案例运行，取代 `PREREG_V2_TEST_ZH.md` 中"是否命中论文读法"的判据（该文件保留为历史登记）。每次正式运行前，另写一份案例登记，写明本协议的阈值和本案例的参考量；运行开始后不改。

## 评分对象

- 主证据：运行目录里的 `actions.jsonl`、`observations/`、`fits/`、`research_state.json`、`ATLAS_ENTRIES.json`。
- 次证据：`REPORT.md` 的文字。报告里说了但记录里没有做的，按"没做"计；记录里做了但报告没写的，按"做了、未报告"计。
- 参考量：论文与补充材料中的数值，只放在封存目录，用确定性脚本读取。

## 第一部分：科学恢复

每项分两列打分：A 列看是否恢复了论文结论，B 列看结论在现有数据下是否站得住。两列可以不同：Agent 得出比论文更窄但有依据的结论，A 列记"未恢复"，B 列记"可辩护"；照搬了论文结论但证据不支持，A 列记"恢复"，B 列记"不可辩护"。

| 项 | 怎么算（确定性部分） | 判定 |
|---|---|---|
| S1 数值 | 各样品的交换速率、布居与参考值的相对偏差；在误差内、10% 内、超出 10% 三档 | 同时报告 Agent 自己给出的不确定度是否覆盖偏差 |
| S2 模型选择 | 是否在同一残基和实验上比较了不同状态数或过程数；选择理由是否引用直接证据（未解释的数据类型、次级凹陷数、分组速率差），而不只引用 AIC/BIC | 没做比较记"过程缺失"，不直接记结论错误 |
| S3 覆盖 | 从数据清单出发：确定性筛选得到的高信号残基中，进入任一拟合的比例；参考 |Δϖ| 最大的 5 个残基进入拟合和进入参照比较的次数；漏掉的高信号残基是否在报告里给出理由 | 阈值写在案例登记里；本案例 K-Ras 的基线见 `coverage_audit/COVERAGE_V3.json` |
| S4 区域结论 | 每个区域的结构结论是否来自该区域、同一残基交集上的多参照比较；是否存在由整体平均推出的区域结论 | 由整体平均推出的区域结论记为不可辩护 |
| S5 边界 | 报告与条目是否写明：不能支持的内容、依赖外部知识的内容、条目适用的样品范围 | 缺一项扣一档 |
| S6 对照 | 工作区里有对照样品时，是否分析了它、结论是否用到它 | 有对照而未分析记"过程缺失" |

## 第二部分：机制增量（A / B / C）

- 定义沿用最初执行 prompt 第 10 节：A 为正常工具循环加充分的基本任务说明；B 为 A 加通用方法经验和科学流程；C 为 B 加显式的结果反思与计划更新。三组使用同一运行入口、同一模型、同一工具集、同一工作区、同样的调用上限。
- 每组至少 3 条运行；只能作为开发诊断，结论用"在这些运行中"措辞。
- 逐条记录：关键动作是否发生（按案例登记列出，例如"发现某类数据未被模型解释后改模型"）、真实纠错次数、引入错误次数、无效重复、调用数、名义成本。
- 反思的净效果：修复的错误、引入的新错误、被闸门拦截的调用、额外成本，四项都记。
- 普通循环已经足够好时，保留简单方案本身就是结论。

## 第三部分：行为检查

- 删除决定性证据：预期相关判断收窄，并写明缺什么数据。
- 改编号但给映射：预期结论不变。
- 负对照（合成数据）：主终点只看被替换的样品；合成数据要内部自洽（不能残留与合成态矛盾的真实数据文件）。不禁止任何特定措辞，看的是被替换样品的参照比较是否恢复合成时设定的参照态。
- 行为检查只证明对应行为，不升级为科学普适性。

## 登记要写清的内容

1. 本案例的参考量与封存位置。
2. S1 的误差规则、S3 的筛选阈值、第二部分要观察的关键动作。
3. 题目给定了什么：对照样品、状态标签、参照库内容等，逐条写明"题目给定"，以免把给定内容算成 Agent 自主发现。
4. 模型、客户端版本、工具代码指纹、工作区指纹。
5. 运行次数、调用上限、早停条件。
