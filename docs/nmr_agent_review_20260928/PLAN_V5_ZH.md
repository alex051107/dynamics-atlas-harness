## 1 三层分清：什么是资产，什么可替换

**工作流**是谱学家从一份证据判定一个构象状态的方法：看什么证据、在哪一步做什么判断、什么情况下弃权、最后写出一条什么样的状态断言。它是要沉淀、要将来全自动跑遍 BMRB 的东西，是项目的核心方法资产；数据库仍是交付物，证据与验证过的工具也是可复用成果。**Harness** 是让一个模型按这套工作流走的外壳：证据包构建、工具、隔离、研究状态记录、打分脚本。它服务于工作流，换模型不必换它，换工作流版本它跟着改。**框架**是 harness 的实现细节：`agent.py` 里的工具调用循环、LangGraph 外壳、OpenRouter 或 DeepSeek 的接口。它本身没有意义，任何一个都能替换。

现有产物按层归位：`workflow/fragments/` 的 37 条决策片段、Gina 的"APO 且慢到两套峰"定义、PLAN_V4 的五层断言结构，属于工作流层的原料；`SCIENTIFIC_WORKFLOW_ZH.md` 和 `codex_prompts/SYSTEM_PROMPT.md` 是工作流的现行正本，但形态有问题（下段）。`src/dynamics_atlas_harness/nmr_agent/` 的 19 个工具、MCP 服务器、封存与沙箱、`grading/grade_run.py`、评测协议，属于 harness。LangGraph 壳、Compass、三层提示的装配方式、A/B/C 三组对比，属于框架和 harness 机制检验。过去三天的精力分布倒过来了：harness 和框架各有完整文档和代码，工作流正本只有一页，而且没有被当作被检验的对象。

**现有工作流正本的缺陷。** 它的标题就说明了它是什么："通用科学流程：从观测到可辩护结论"。六段（问题、盘点、基础分析、区分解释、构象解释、提交）是按分析阶段组织的，回答的问题是"怎样把一套 NMR 弛豫数据分析得可辩护"，核心动作是拟合、模型比较、残差、参照比较。"这个蛋白有没有第二个 APO 态"这个问题只在最后一段以"Atlas 候选"出现。37 条片段的索引方式同样是按论文、按分析段，没有一条索引是"作者凭什么证据断言了一个 state"。K-Ras 已经证明了这套流程的偏向：数值恢复靠工具，流程的贡献在判断和检查。所以它偏在两处：一是以"有原始色散数据、要拟交换参数"为默认场景，而 BMRB 里绝大多数条目只有指认位移表；二是把 harness 关心的事（C 组反思、封存、A/B/C 增量）写进了工作流正本，让工作流和执行外壳再次混在一起。

## 2 "工作流确定下来"指什么

**输入**是一个病例的证据包。病例是一个待判断的样品或构建体问题，可以包含多个相关 BMRB 条目（RfaH 2025 的主次态分别在 52718、52719），条目间来源关系保留、不自动合并。证据包含：构建体与序列、配体状态、样品条件（温度、pH、浓度、寡聚态若有）、指认位移表（可能不止一套，可能同一残基有两个值）、常规弛豫（若有）、色散或 CEST 曲线（若有）、关联的 PDB 条目。论文正文是独立的第二来源，只在人类走完整资料时给，Agent 评测时不给。

**输出**是一条状态条目，五层断言分开写，每层可以单独弃权：（1）观察：在哪个构建体、什么条件下看到了什么信号特征；（2）归属：这些特征是同一样品的两个态，还是不同条件、链、样品或纯度造成的；（3）状态：哪些残基、时标类别（慢到两峰 / 中间展宽 / 快）、布居若可估；（4）结构对应：与哪个 PDB 或参照相符、或无对应；（5）功能相关：有无独立证据。最后是总判定"有 / 无（限所测条件）/ 弃权"，每条断言引用具体记录，列出未排除的竞争解释和最能解除歧义的下一项测量。

**判断点。** 下面八个是工作流的正文，每个写明看什么、怎么判、何时弃权、出处。出处编号沿用 `workflow/fragments/`。

| 判断点 | 看什么 | 怎么判 | 何时弃权 | 出处 |
|---|---|---|---|---|
| J1 对象是否成立 | 构建体、配体、条件 | 确认对象；配体结合照常分析，J8 标不属首批；孤立域不写成全长 | 构建体查不清；配体不明只把首批资格标待定 | RfaH2025-1、AdK-3、K-Ras-1 |
| J2 证据有哪几类 | 位移表数目、弛豫、色散、PDB | 登记每类有无与覆盖；缺指认只作候选线索 | 不弃权，只限制后面能答什么 | IL-2-1、AdK-2 |
| J3 有无额外状态或交换的候选证据 | 同实体同原子的两套观测（可跨条目）、CEST/色散、间接线索 | 分三条去向：两套信号候选、交换候选、线索；作者标签不算发现 | 只有间接线索且包内无补充 | RfaH2025-2、K-Ras-2、AdK-1 |
| J4 能否归为同一构建体的两个构象 | 实体/原子/残基对应、条件、交换联系、样品伪影 | 条件一致只建立比较资格；还需交换联系、跨残基一致、伪影检查 | 写"共存／归属未决"，不升级 | K-Ras-5、RfaH2012-3/4、RfaH2025-2 |
| J5 时标与布居 | 强度比、曲线 | 归属成立后两套可见信号才指向慢交换；强度比不直接当布居；有曲线先查无交换解释，加态或预测失败前先查归属、误差、模型、收敛 | 只有位移表不给速率 | K-Ras-2、RfaH2025-3/4、IL-2-2 |
| J6 结构对应 | 关联 PDB、参照位移、随机卷曲预测 | 参照覆盖需要区分的解释；单一参照只报有范围的相似；相似不等于身份 | 共有残基太少或无合适参照 | K-Ras-3/4/7、IL-2-3 |
| J7 功能相关 | 结合、活性、扰动证据 | 与目标状态有明确联系、写明改变了哪个变量才写；否则标假设 | 默认弃权 | AdK-4/5/7、IL-2-5/7、K-Ras-8 |
| J8 写条目并选下一步 | 以上全部 | 五层分开；每个未决判断回答：哪两个解释没分开、下一步能查或算什么、什么结果会改变判断、无动作时保留什么 | 程序中断和证据不足分开报告 | RfaH2012-6 |

**版本化与修改规则。** 工作流是一份源文件 `WORKFLOW_STATE_ID_v1.md`，同一份源生成两种渲染：给人的一页清单（每个判断点一格，填看到了什么、判了什么）和给 Agent 的提示。两者内容一致，改一处两边同改。版本冻结后，只有被某个病例暴露的问题才能改它：修改记录必须写"病例号、卡在哪个判断点、原文怎么写、改成什么、为什么这样改能让该病例通过而不伤其他病例"。感觉上更合理、或者为了迎合某篇论文的结论，都不是修改理由。"确定下来"的判据：一位谱学家和一个 Agent 拿同一个证据包，都能按这份文件走完；结构相同只说明格式统一，还要看关键断言有依据、歧义被保留、该弃权的层次没有被强填。

## 3 怎样检验工作流本身

检验分两步，先人后机，两步证明的东西不同。

**第一步，人走。** Gina、Soojung 或用户按一页清单手工走病例，每例先只看证据包（参照 B），再看完整资料（参照 A），并在清单最后一行记下清单之外实际用到的判断。人走用于形成同输入参照、检查工作流是否可操作。成功说明在所测病例上可以完成解释，不证明方法普遍正确；失败要区分证据不足、工作流缺口、读取问题和人工判断分歧。熟悉论文的人走熟悉病例，是开发走读，不能当作不知道答案的参照。

**第二步，机走。** Agent 在同一批证据包上按同一版工作流走，与人走的条目逐判断点比对。排查分歧先看三处：工作流写得含糊、harness 读取或打包丢失、模型判错；原因不能确定时标"待归因"，不强行归类。不等全部人走结束：一到两个病例的参照 B 冻结后就开始机走，其余病例并行准备。

PLAN_V4 的八病例设计保留，它同时是人走的病例集：两例证据充分的正例、两例论文说有但证据包缺关键证据、两例条件范围内的可靠阴性、两例多套列表来自不同条件或链。两层参照保留，参照 B 由人走产生。确定性基线保留：程序只列多列表、重复指认、条件差异、缺失区段，不下结论，Agent 相对它的增量才算工作流加模型的贡献。配对测试（拿掉关键证据结论应收窄，改编号结论应不变）留两例。冻结不做的：A/B/C 三组增量比较（它检验的是提示机制，不是工作流）、K-Ras 新运行、RfaH 第三次方法复现、AQADK/Hypo 数值恢复、LangGraph 外壳。

## 4 Harness 最少需要什么

工作流只要求 harness 做四件事：把一个病例（可含多个条目）打成证据包；给模型工具去读它；把模型的输出收成五层条目；把条目与参照 B 逐判断点比对。现有的够用部分：19 个工具里的 `bmrb_entry`、`reference_shifts`、`compare_references`、`pdb_ligand_distances`、`python`、研究状态接口、`finish`；封存与沙箱；`agent.py` 的工具调用循环。要改的三处：第一，`bmrb_entry()` 用"原子加残基加编号"作键，同一残基第二套指认覆盖第一套，样品条件按类型合并只剩最后一个，它抹掉的恰好是 J3、J4 要看的东西；改为按位移列表分组返回原始记录，保留实体、链、样品、条件与列表的关联，关系未知就标未知。第二，`finish` 的候选记录要能输出五层条目。`grade_run.py` 保留，作为 J5 拟合分支的数值评测；本轮新任务用一张小型逐判断点对照表，程序只检查记录引用、字段和执行状态，科学断言由人审。第三，`agent.py` 写死了 OpenRouter 地址，加环境变量覆盖，DeepSeek 即可用。拟合类工具不动，作为 J5 的分支保留。框架一句话：现有循环够用，不换，不加。
