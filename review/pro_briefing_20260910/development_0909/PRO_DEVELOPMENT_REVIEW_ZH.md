# Decision：CHANGES_REQUESTED_BOUNDED

**保留 Luna，结束这批开发运行，暂不启动正式比较。这个决定基本正确，但报告对“为什么停”和“Rules 没有发挥作用”的解释，还需要改得更准确。**

我读取了 PR #26 固定提交 `adba30a2eeececfd3612e7d89d603c69872175db` 中的开发报告、运行汇总、几份关键初稿与终稿、相关工具执行记录，以及修订前的运行器代码。没有重新调用模型，也没有重跑科学拟合；下面的数值判断主要依据这些保存记录，而非本轮重新计算。

用一句话说明现在的位置：

> **便宜模型已经展示了实际分析能力；你们自己写的运行程序破坏了部分答案交付；科学判断也仍有错误。由于这些问题，Rules 的增量还没有被清楚测出来。**

这三件事要分别处理，不能都变成“再加强 Rules”。

## 一、这轮确实回答了“便宜模型能不能做事”，而且证据比汇报里写得更具体

我认为最有价值的记录，不只是“Luna 算出了约 1.915”，而是 **A 组在没有额外七条指导的情况下，出现了实际的分析—检查—修正过程。**

在 Q05 A 的记录中，它首先把权重文件的两列一起纳入统计，得到不合理的权重总和。随后，它重新读取表头，看到第一列是时间、第二列才是权重，再修改代码只使用第二列。它也从最初的普通距离残差，转向检查 NOE 的单侧上界。这里可以直接观察到它读取反馈、重新检查资料和改变计算，而不只是调用开发者预先安排好的唯一函数。

这是一个有意义的正面结果：

**简单的工具 Agent，已经能够自主完成部分数据理解和错误恢复。**

但能力范围也应准确命名。本次 Q05 主要核查的是作者已经发布的拟合曲线、距离预测和权重文件；它没有自主重新建立候选系综，也没有重新完成 SAXS-only 或联合优化。核查已有结果同样是科学工作，不必因此降为“只是读文件”，但不能升级成“已经独立完成纳米盘整合建模”。

所以，**目前没有证据表明需要先换昂贵模型。** 这不是说 Luna 已经足够可靠，而是当前最明确的问题并不是“模型根本无法阅读和计算”。

费用汇总记录为约 **0.16578 美元**，其中模型运行和接口检查合计在内；人工准备、开发和审阅时间没有完整计量。因此可以说这轮模型调用便宜，不能据此说整个工作流已经低成本。

## 二、答案丢失是普通的软件缺陷，不需要包装成一个新的研究方向

这一点我核对到了直接记录。

T4L C 已经提交了长篇科学答复。随后模型返回“已提交基于论文、SI及方法材料的证据化分析……”这样的确认文字，运行器却把它记录成第二次提交，并配上：

```text
claims: []
conflicts: []
```

最终交付因此变成确认文字，而原来的科学主张记录被清空。

修订前代码也能解释这个问题：**没有工具调用的普通模型消息，会被自动转换成一次 `accept(...)`；最后保存的又是最后一次提交。** 这将“聊天中的最后一句话”和“用户应收到的科学答复”混为一谈。修订后的事件记录表明，这个行为仍然发生了。

因此，当前最小修法不是增加“证据保持 Agent”、长期记忆或新的结论框架，而是明确：

> **一份已提交的答案，只能被一次明确、有效的新提交替换；普通确认文字不能覆盖它。**

这里的“有效”只需要是提交协议有效，不是由程序判断新答案科学上更好。不能采用“保留最长答案”“让另一个模型挑最好的一份”来救结果，否则又会引入新的选择偏差。

还有一个细节值得纠正：T4L B 的最终文件并非完全没有科学内容，它仍保留了权重数字和部分限制，但丢失了初稿中的引用、分析细节和部分证据。T4L C 才更接近只剩完成声明。两者应分开描述，不统称为“答案全部丢失”。

**程序记录的五份 `COMPLETE`，确实不能解释成五份完整或正确的科学答复。** 你们没有用初稿偷偷替换终稿再报告成功，这个处理应保留。

## 三、关于 C，需要纠正一个容易误导方向的归因

报告把 NOE 上界数组拼错列为“规则没有防住具体的数据处理错误”。作为现象描述没有错，但**它不是对本轮那项确定性检查的有效反证。**

因为 C 本版实际只检查：

> 同一结果参与拟合的数据，是否被说成独立验证。

它没有承担“所有实验上界是否正确读取”“数组是否按原子对对应”或“所有算术结果是否正确”的职责。

因此，Q05 C 把最大超限写成约 4.35 Å，应该这样解释：

**模型的数据处理发生了错误；可读科学指导没有保证它避免该错误；本轮执行检查不覆盖这种错误。**

不能由此得出“这项拟合重用检查失败了”，更不能推出“应马上给 C 增加数值正确性规则”。

原始 C 答复确实写出了自己拼出的上界分组。开发者事后按原子对核对，记录的正确最大超限为 **2.75049 Å**；这项事后核对不能计入 C 自己的纠错成绩。

同样，**“没有产生冲突”不等于“检查证明答案正确”。**

至少要区分：答案中没有对应的错误、检查无法匹配、没有适用对象，以及检查真正完成后未发现冲突。T4L C 最后一条记录连结构化主张都为空，那里出现的 `conflicts: []`，显然不能被读成整段答案接受了科学审核。

本轮最准确的结论仍然是：

> **没有观察到这项窄检查的直接纠错收益；现有记录也不足以估计它在真实适用情景中的纠错率。**

不要为了让它“有被测试到”，现在再人为制造一个错误答案补进这批结果。检查器本身可以用离线输入测试，但那只是实现测试，不是自然任务上的增益。

## 四、除了运行器，已有答案还有两个真正值得保留的科学错误

### 1. “大多数约束满足”不自动等于“整体科学相容”

Q05 A 正确计算并报告了：292 项 HN NOE 中 47 项超出上界，40 项甲基 NOE 中 8 项超出上界；同时给出了较大的最大超限值。但它随后将结果概括为“总体相容”。B、C 也有类似概括。

这里**数值核对有价值，整体评价却仍需要依据**。仅凭“大多数没有超限”，不能决定剩余偏差在科学上是否可接受；SAXS 平均标准化平方残差约 1.9，也不是无需考虑误差模型就能使用的通用相容性阈值。

更稳妥、仍然有内容的回答应是：

> 作者给出的重加权结果在当前误差口径下取得了某种 SAXS 拟合程度，NOE 中多数记录未超出上界，但仍有具名的局部偏差。作者将其解释为总体吻合；本次核对确认这些数值特征，尚未独立确立整体系综的相容性或唯一性。

**不必把这一问题改成整体弃权，也不能把正确的计算全部判零。** 应分别评价计算结果与对结果的扩大解释。

### 2. B 把“状态占比”和“转换速率”限制得过于相似

Q05 B 最后写道：

> “若要回答构象占比或交换速率，还需要动力学或时间分辨证据，不能由当前静态平均观测补足。”

这句话对两种性质的处理过于笼统。

**转换速率需要时间或其他能够建立物理时间尺度的依据；状态占比并不一概需要时间分辨实验。** 在候选状态、前向模型和条件明确，而且不同状态的预测能够被测量区分时，平均观测也可能约束它们的比例。你们采用的博客就明确讨论了，固定候选构象后，实验怎样约束其权重。

这不意味着当前纳米盘数据已经唯一确定了真实占比。正确的说法是：

> 当前分析没有充分确定真实占比；需要检查观测对候选权重的约束能力及模型假设，而不是一律要求新增时间分辨资料。

这比“任何人口结论都不能说”更接近原始目标。

**这也是 Rules 必须允许失败的地方：提醒边界可能有帮助，但也可能被模型扩大成不成立的禁止性判断。** 当前只能记录这种过度推广发生在 B 中，不能由一次输出断定它必然是指导包造成的。

报告已经记录了另一个类似例子：把“重加权不能产生候选池外构象”扩大成“延长 MD 也不能产生新构象”。这些问题值得交给领域评审，但不应据此再改规则并启动第三批同题运行。

## 五、“停止正式比较”是对的，但不要说成必须先消灭所有科学错误

报告开头将“交付缺陷”和“部分科学判断有错误”一起列为暂不进入正式实验的理由。我建议区分：

**交付机制不可靠，确实会妨碍解释正式结果。** 模型做出的科学答复被程序覆盖后，最终输出分数混合了分析能力与意外的软件破坏。

**普通科学错误本身，不是必须先修完才能实验的理由。** 否则，模型永远只有在开发题上被修到正确之后才允许接受评价，实验又会回到原来的循环。

因此，本轮停下的充分理由是：共同运行程序尚不能稳定保存提交结果，且正式领域评分条件还没有落实。科学错误保留为需要测量的表现，不要求“Luna 六题全对”。开发报告已说明领域评分人员与新来源尚未落实。

另外，这十二次是**两个暴露案例、两个运行器版本下的会话记录**，不是十二份独立科学来源，也不是可以直接合并计算准确率的十二个样本。

我的投入判断是：

| 问题                | 本轮能够作出的决定                  |
| ----------------- | -------------------------- |
| 是否马上升级模型？         | **不需要。** 已有真实阅读、计算和修正行为    |
| 是否进入二十四份正式运行？     | **暂不。** 先解决交付可评价性和评分条件     |
| 是否宣称 Rules 有效或无效？ | **都不可以。** 增量仍未建立           |
| 是否保留本轮结果？         | **保留。** 它们是开发能力与失败记录，不是废数据 |
| 是否再跑第三批 Q05/T4L？  | **不跑。** 本轮达到既定终点           |

## 六、接下来最小的工作，不是再跑一轮模型

**现在先结束这次实验。后续若负责人决定继续维护原型，只做一次不调用模型的提交机制修复。**

已经保存的事件足够检查四种行为：

| 已有事件或离线测试输入        | 应满足的行为                       |
| ------------------ | ---------------------------- |
| 完整答案提交后，出现“已提交”确认  | 原答案和原主张记录不被覆盖                |
| 模型明确提交一份结构有效的新答案   | 可以替换，即使新答案更短；不由程序挑“科学上更好”的版本 |
| 提交为空、格式不合法或未提供检查对象 | 保留已有结果，说明提交／检查范围，不伪称检查通过     |
| 已有提交后发生预算或时间停止     | 保留已提交内容，同时标注运行未完整结束          |

这关闭的是一个已经观察到的答案保存错误。**不需要新增 Agent、数据库、规则族或长篇计划。**

离线回放也有明确上限：它只能证明程序现在如何处理这些保存事件，不能证明模型在修复后的真实对话中一定会作出相同反应，更不能把恢复出来的初稿补记为旧运行成功。

同时，对这批现有答案做一次开发性内容盘点即可：哪些数值有代码支持，哪些解释过强，哪些初稿内容在最终交付中丢失。使用现有文件，不挑“最好的一版”替代真实终稿，不生成新的正式题。

**如果下一阶段仍要开展 A/B/C 比较，再确定评分人员和新来源。不要因为软件修好了，就自动续跑二十四份。**

### 建议将这次汇报的核心结论改成下面这段

> 本轮低价模型在两个暴露案例上完成了真实的资料阅读、数值核查和部分自我修正，说明当前不需要先升级模型。运行程序仍存在提前停止与答案覆盖问题，科学答复也出现了数据对应错误和过度推广，因此尚不能评价 Rules 的独立增益。C 只检查拟合数据重用，本轮未观察到该检查的直接纠错；它不负责、也未验证全部数值正确性。本批开发到此结束，保留全部初稿、终稿和失败。后续仅在负责人决定继续时，先用保存记录修复和检查提交机制，不新增同题模型运行。

**这轮已经取得了一个清楚的进展：你不必先花更多钱，才能得到一个会实际分析的 Agent。现在需要补的是“让已有分析可靠地交到研究者手里”，再公平地问指导和检查有没有帮助，而不是继续证明 Rules 必须存在。**
