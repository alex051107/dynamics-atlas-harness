## 阅读段 D049：LAB-Bench、CORE-Bench 与 Harness-Bench：分别测哪一段能力

LAB-Bench 将文献正文与补充资料检索、图表理解、数据库查询、协议、序列和克隆场景拆成不同任务。一个表格值找对了，和实验协议设计对了，是不同能力。论文的一部分任务原本依赖工具，却也报告不带工具的模型表现；解读分数时要保留这个执行条件。多项选择以及选项中的弃权不能直接代表端到端研究能力。（L25（该链接目标未纳入本包），任务分类、构造与评测）

CORE-Bench 从90篇论文的 CodeOcean 材料构造270个任务，先由构造者确认可在本地重跑，再分别提供已有输出、带 Dockerfile 的代码数据，或只有 README 的代码数据。评分要检查与问题相对应的结果，部分还需读图。它的价值是把依赖环境、执行和结果解释分开；只看程序退出码不够。（L21（该链接目标未纳入本包），§2及任务构造）

该基准的历史 Agent 在不同资料条件下表现差异很大，但我们不将其旧模型分数当成当前能力估计。更关键的限制是“重现作者输出”仍可能重现作者的模型假设或错误；我们当前需要额外检查这些输出能否支持题目的科学判断。因此作者已验证可重跑的材料是工程参考，不是最终科学金标准。

Harness-Bench 在106个离线任务中固定外部环境、预算、时限和评分方式，比较完整模型—harness配置，并保存执行痕迹。论文自己明确指出这种比较是配置诊断，不是对某个单独机制的因果分解；不同 harness 中上下文、工具、恢复等机制彼此耦合。（L36（该链接目标未纳入本包），§3及评测解释，2026年v1预印本）

这一点直接约束我们的 Rules 实验。若一条路径拿到更完整的数据、使用更多人工提示或运行更久，再比较答复，不能把改善都归给 Rules。正确设计应让两边共享同一来源、方法和预算，另做规则开关或模块消融；最终科学答复与过程错误分别评分。Pro 的审查可以提供修正意见，不能同时充当唯一金标准、修改指导者和独立测试者。
