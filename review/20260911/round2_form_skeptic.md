# 立场：规则表不是帮助 agent 做科学判断的正确形式

2026-09-11 · 第二轮辩论 · 论题：形式与颗粒度 · 裁决由另一模型做，本文只把这一方说透

路径相对工作区根目录 `Soojung-Dynamic data/`。文献证据出自 `RELATION_EXTRACTION_20260911.md` 第 4 节分组 E，注明论文；未在证据文件里核到的标"推断"。

## 1. 对两个核心问题的直接回答

### 问题一：要做 rules table，整理什么才有真正的意义

该整理的是：每一个具体计算在什么条件下允许跑、它过了哪些正反对照、它的输出把结论停在哪一级。整理完之后，这些内容不该以表的形式交给 agent 阅读，该分别落进建包脚本的准入检查、算子的前置条件、题面里"这个子问题必须跑哪个计算"、以及报告脚本生成措辞的那段代码。真正需要保留文字形态又只能请专家写的只有一类：两个解释相持不下时，用什么观测把它们分开。

三条理由。已整理出的 42 条里有 20 条自己写着"No case"，其中两条还被错用到 HSP90 的核磁题上（`data/rules/RULES_TABLE_V2.md`"Rules with no case in this project"）——整理量和有效量之间没有关系。被实测证明改善了结果的东西全是代码：把每个数字绑定到产生它的计算，在 8 份历史答复上抓到 7 处错误里的 6 处，旧的"这个数字在工具输出里出现过吗"检查抓到 0 处（`RESULTS.md`"Checking numbers"）。34 处失败按"什么形式能防住它"统计，"文字提示"这一栏是 0 条；反方向的证据倒有一条，33 条规则原文整段进提示，HSP90 核心正确中位数从 4.5/5 掉到 2/5（`FAILURE_CATALOGUE_20260911.md` 第 18 行与第二节汇总表）。

### 问题二 (a)：什么形式更好，rules table 是好形式吗

规则表不是好形式。它的四个结构性假设都被本项目的数据推翻了。

一、它假设知识靠检索和阅读进入分析，实测是准入卡 4 次运行全部只在工具日志里出现文件名、0 次被打开（同上第 14 行）。二、它假设读到就是好事，实测是规则组确实读了也照办了，办的是把 FRET 建模的前提当成核磁题的必填项（`PROJECT_HANDBOOK_20260911_ZH.md` §3.4）。三、它假设组织维度和触发维度可以相同，而 V1 按论文和方法族组织，检索时 HSP90 只取到一张用不上的重加权卡，DHFR 和 ADK 各取 0 张（`FAILURE_CATALOGUE_20260911.md` 第 20 行）。

第四条最要命：它假设一行等于一个可验证单位。决定结果的单位实际有三种且互不相同——一个计算、一道题的分解、一个定义是否过了正反对照。一行规则同时跨这三种，既不能被机器执行也不能被人验证。表里那条"空间支持不同的量不能直接比较"存在了一个多月，没有被用到我们自己的邻域半径定义上，直到 OP5、OP6 撤回（`RESULTS.md` 末段；`DEFINITIONS.md` §3）。

### 问题二 (b)：偏宏观还是偏微观

这个维度问错了，该分的是"谁消费"。微观判据（阈值、违例文件读第几列、周期性距离怎么取）全部进代码，agent 永远看不到；宏观关系（这份数据能分开哪种差异、最多支持到哪一级）由人写进当次题面和报告模板，不做成可检索的库；只有"冲突时用什么观测区分"留在文字里给 agent 看。

定量依据来自文献：Chen 2024 在 102 个真实数据驱动发现任务上测过，给 agent 专家知识把最好成绩从 32.4% 提到 34.3%，而让它执行代码、看报错、迭代修正把 16.7–20.6% 提到 32.4–34.3%。调整知识颗粒度的收益落在不到 2 个百分点的区间，改变执行形式的收益落在 15 个百分点的区间。

## 2. 替代形式：六个决策点分别看到什么

原则：agent 每一步只看到"这一步能做什么、做了以后能说什么"，看不到任何跨步骤的知识库。每样东西都有产生者和验证方式，验证不过就不存在。

| 决策点 | agent 看到什么 | 由什么产生 | 怎么验证 |
|---|---|---|---|
| 拆题 | 题型卡一页：要区分的差异、子问题、每个子问题必须跑的计算、竞争解释 | 人写，文献供问题级关系 | 子问题覆盖率对专家写的分解；每个子问题必须指名一个计算 |
| 数据准入 | 什么都看不到 | 建包脚本，冻结前跑 | 植入缺陷包的检出率与干净包的误报率（现 6/6 与 0/3） |
| 选量选定义 | 算子卡，一张卡等于一个计算 | 文献判据写进代码，人审 | 卡上挂一份对照记录，正反对照都过了才放行 |
| 计算 | 只能调用卡上的算子，参数越界返回范围 | 冻结的代码 | 提交门：子问题缺必需计算就退回一次 |
| 结论措辞 | 什么都看不到，措辞由报告脚本生成 | 算子输出里的门，如往返计数 | 数字绑定：每个数字对上产生它的输出字段 |
| 冲突与提请求 | 冲突卡；一个有类型的请求工具 | 专家写 | 三包测试：干净包、标签互换包、预期不适用的体系 |

### 一张算子卡长什么样

文件 `operators/noe_reference_crosswalk.md`，是 agent 在选量选定义时唯一看到的东西。

```
名称      到达开态参照的判定
做什么    逐点比较开态与闭态两套原生 NOE 违例，判每条轨迹是"一致""部分一致"还是"只有相对方向"
输入      作者沉积的 80 份违例文件的第 2 列（原生违例）
前置条件  第 2 列均值须落在 0 到 15 Å；第 3 列是伪距离，读到它就拒跑，返回"列语义未核实"
参数      容差 τ ∈ {0.5, 1, 2} Å，三档都要跑，不允许只报一档
对照记录  controls/op2_control.json — 正对照：开态起始轨迹在 1 Å 下 18/20 一致，通过；
          0.5 Å 下正对照只剩 7/20，判为过严，该档只作敏感度
输出      per_trajectory.tsv（每条轨迹三档判定）、summary.json（三档计数）
结论上限  支持"是否与参照一致"；不支持占比、速率、完整转变。τ 是操作定义，不是标定过的态边界
冲突出口  三档之间判定翻转时调用 request_decision(kind=tolerance)，以"容差未定"提交
```

这张卡把 V2 里 P-01、P-02、C005-RULE-001 三条的内容全部吸收，而 agent 读不到任何规则文本。数据来自 `DEFINITIONS.md` §2 与 `RESULTS.md` §1。

### 一张冲突卡长什么样

文件 `conflicts/hsp90_toward_open_count.md`，是唯一真正需要文字也真正需要专家的东西。

```
冲突    作者把 20 条闭态起始轨迹里约 9 条归为"趋向开态"（Henot 2022）。
        按 CPMG 的 3.2% 占比和 2490 s⁻¹ 交换速率，两态近似下闭到开约 2410 s⁻¹，
        20 μs 总时长的期望事件数约 0.05 次，与 9 条差两个数量级。
        （此计算是项目推断，假设两态动力学且 CPMG 测到的就是 lid 开合，
         见 RULE_CONTENT_DISCUSSION_20260911_ZH.md §6）
候选解释 A 闭态起始构象在这个力场下不稳定，轨迹在从起始模型弛豫
        B CPMG 测到的过程和 lid 开合不是同一个运动
        C "趋开"只是部分移动，没有到达
怎么分开 A 对 C 看 helix-5 是否折叠；A 对 B 看闭态起始构象在 NMR 约束下是否稳定；
        C 由到达判定直接回答（1 Å 下 0 条一致）
怎么用   只在交卷之后的检查步用，冲突成立时以"与作者分类冲突"提交，
        触发容差校准或专家审。禁止为凑上作者的数字去改定义
```

它进不了代码，因为要判断两个物理过程是不是同一回事；也进不了提示，因为放进分析时的上下文等于把答案写进提示。它必须先过三包测试（怀疑者第一轮已提出此设计，`position_skeptic.md` §4）。

## 4. 三条最强反驳与回应

**反驳一：纳米盘题上整段规则拿了 5/5、协议组 4.5/5，说明规则文本在对的题上确实有用。**

数字属实（`RESULTS.md`"Tests of the rules, in numbers"）。每组 n=4，同一形式在 HSP90 上是 2/5，方差比效应大。Skarlinski 2024 的能力阈值和 Huang 2023 关于初始提示信息量的发现给出另一种解释：增益可能来自提示里多了与当前操作相关的信息，与"规则"这种知识形态无关。最关键的是，纳米盘那题被读到的规则内容恰好就是当时正在做的计算（最大熵重加权的前向模型、先验、误差模型），它是以算子卡的身份起作用的。替代方案保留这部分内容，只换容器。

**反驳二：V2 已经改了，规则不再进提示，只通过算子前置条件和结论上限接入，agent 根本不读原文。**

那正好是我的结论。如果所有内容最终都通过代码前置条件、提交门和对照记录接入，剩下的那张表就是登记簿，该改名并停止扩条目。保留"规则表"这个名字有具体代价，它把下一轮工作导向"再收 N 条"。实际状态是 42 条里 20 条无对应数据，13 条起作用的大多只是结论上限，真正写进代码前置条件的只有读违例第几列和周期性距离怎么取两条（`RULES_TABLE_V2.md` P-02、P-03 的 Status 列）。表的规模和系统能力已经脱钩。

**反驳三：科学判据总得有个地方存着，否则换一个体系就得从头来。**

迁移单位是算子加它的对照记录。ADK 给出过直接证据：脱离具体量写的通用检查迁移到新体系就是错的，蛋白本身 56 Å、盒 98 Å，分子内 62 和 70 Å 是真距离（`RESULTS.md` §4）。能安全迁移的是"这个计算在什么条件下跑过、过了哪些正反对照"这种带证据的单元，新体系上重跑一次对照就知道能不能用。文献方向一致：Campbell 2026 的有效系统是 40 个专用工具，Kambhampati 2024 的正确性保证来自外部验证器。

## 5. 删什么、留什么

**从 agent 可见范围删掉并停止扩充：** 那 20 条在本项目没有对应数据的 smFRET、冷冻电镜、DEER 规则。它们不是中性的，其中两条已造成实际损害（`FAILURE_CATALOGUE_20260911.md` 第 4、5 行）。作为文献笔记留存。同时删掉 `RULES_TABLE.md` 的 Use 分类和 Index、Card、HSP90 prompt 三个勾选列，它们记录的是两种已被证伪的接入方式（按方法族建索引、贴进提示）。

**保留为登记簿，不给 agent 看：** 每条内容的出处与来源类型（只靠综述和立场文章支撑的最多是候选）；停止路线的代码词表（`POPULATION_NOT_ESTIMABLE` 这一类是报告脚本的输出词表）；每条内容的状态与对照文件路径。读者是人，用途是审计和送专家审。

**转成别的东西，原行注销：** 占比要带不确定度、没有往返不报占比、速率要有验证过的动力学模型（S-01、S-02、S-04）转成算子的门与前置条件。读违例第几列、周期性距离怎么取（P-02、P-03）转进建包准入脚本。两条关于"两个数是不是同一个量"的内容（C005-RULE-001、C007-RULE-001）转成定义冻结前的核对清单，由人逐项对论文核——残基范围 40–97/137–220 对论文 11–97/137–223 那处偏差本该在这里被拦下（`DEFINITIONS.md`"Common setup"）。存在、占比、时间尺度、功能分行报告（C010-RULE-001、C012-RULE-003）转成报告模板的行结构；比较的基本单位（C012-RULE-001）转成题型卡的栏目。

**现在一条都没有、需要新写的：** 冲突卡。63 篇文献里这类关系只抽到 4 条，因为方法论文不写它。每个体系两三条，只能请 Soojung 写。

**验证预算：** 上述改动里唯一需要模型调用的是冲突卡的三包测试，3 个包 × 2 组 × 4 次 = 24 次运行，按首轮单次 0.019 美元估算（`PROJECT_HANDBOOK_20260911_ZH.md` §3.4）约 0.46 美元。其余全是代码与文档整理，零模型成本。
