# 规则表到底该收什么、该长什么样

写给负责人 · 2026-09-11 晚 · 这一版取代前一版"规则的内容应该是什么"

## 0. 先说我理解的处境

你要交的东西有两样。一张可信表，说明一组蛋白动力学数据里哪些系综量能信、信到哪一级。一套能在下一组数据上重复这件事的 agent 流程。规则表从头就是第二样的手段，用来让 agent 的判断更准。

两个月做出来的有 33 条规则，后来扩到 42 条，六步流程，六个算子，四个案例。测出来的事实有五件。规则原文贴进提示，HSP90 方法题从 4.5 分掉到 2 分。给 agent 的准入卡四次运行零次被打开。把每个数字绑定到产生它的计算，八份历史答复里 7 处错误抓到 6 处。自由分析组和算子组那次对比作废，因为读取被截断。两个自定义的"邻域"定义没过对照，撤回。

今天又做了一件事。34 处失败逐条重新核对，问每一处是 agent 不知道判据，还是知道没用上，还是输入或机制的问题。结果是不知道判据的 0 处，知道没用上的 18 处，输入或机制的 16 处。最典型的一处是 HSP90 规则组那份答复。它把 FRET 规则的术语一个不差地写对了，只是用在了核磁题上。它不缺知识，缺的是"这条该不该用在这道题"的判断依据。而这个依据是我们没给它的。

所以你的问题问到了点上。agent 不缺知识，那往表里收更多知识是在干什么。

## 1. 一句话答案

规则表值得留，但它是给人用的登记簿，agent 不读它。它该收的内容只有三类，收不收的标准只有一条，这条内容会不会改变 agent 在某个具体决策点上的动作。

后面按 HSP90 走一遍，看每个决策点上 agent 需要什么，再回头说三类内容分别是什么、放在哪、粗到什么程度。

## 2. 用 HSP90 走一遍

题目是"闭态起始的轨迹有没有到达开态"。agent 从拿到题到交卷，要做六次决定。

**第一次，拆题。** 这道题得拆成三问，方向有没有变，绝对读数吻不吻合，转变完不完整，每一问配一个必须跑的计算。哪一问配哪个计算是本项目的约定，模型猜不到。九月十日测过，人写的拆题让子问题覆盖从 2 提到 2.5，是全部测试里唯一出现在 agent 这一端的收益。同一次测试里核心错误从 1 升到 2，因为拆了题没有门，四份里两份第二问空着交。这里 agent 需要的是题面模板加提交门，缺一样都不行。

**第二次，读数据。** 沉积文件的第几列是原生违例，距离是不是跨了周期边界。这些 agent 一个字都不该看到。DHFR 那次 46 到 94 埃的假距离进了分析，一份答复还把它解释成构象切换。模型知道周期性镜像是什么，它没检查，因为没有东西要求它检查。建包脚本抽三帧重算，差过 0.01 埃就不冻结，这个检查已经实装并且通过。

**第三次，选定义。** 我们自己定的"参照邻域"半径取自核磁系综内部的两两离散，拿去量 MD 帧到最近模型的距离，两个量不是一个量，99.99% 的开态起始帧被判在参照之外。表里那条"空间支持不同的量不能直接比较"当时已经存在一个多月。规则是对的，位置是错的。它躺在表里等人记得看，没有挂在"新定义冻结前"这个位置上。这一处是人犯的错，说明这类判据的失效点从来不在知不知道。

**第四次，能不能报占比。** 40 条各 1 微秒的轨迹，往返 0 次。作者的 CPMG 给出闭态 3.2%，交换速率 2490 每秒，两态近似下闭态停留约 0.4 毫秒，20 微秒的闭态起始轨迹期望离开事件约 0.05 次。0 次往返正是实验动力学预期的结果，这批 MD 给不出占比。这里有两样东西。"没有转变就定不了相对占比"这个判据模型知道，Zuckerman 2011 写得很清楚。3.2% 和 2490 这两个数模型不知道，只能从数据包里来。这条规则是整个流程里唯一一次真正拦下过强结论的科学判据。

**第五次，写结论。** 每个数字绑定它的计算来源。模型知道要核对，不强制它就不核对。历史答复里六处转述错误全在这一步。

**第六次，冲突。** 作者把 20 条闭态起始轨迹里约 9 条归为趋开，我们 1 埃下判 0 条。按上面的速率，1 微秒内离开闭态的概率约千分之二，20 条里期望 0.05 条。所以作者说的"趋开"不可能是 CPMG 测到的那种交换。可能是闭态起始构象在这个力场下不稳定，轨迹在从起始模型弛豫；可能是 CPMG 测的过程和 lid 开合不是同一个运动；也可能只是部分移动。分开它们要看 helix-5 有没有折叠，看闭态起始构象在核磁约束下稳不稳。这是六次决定里唯一需要给 agent 文字的地方，也是唯一只有领域专家写得出的东西。

## 3. 该收的三类，和不该收的一类

走完一遍，agent 需要的东西分成三类。

**第一类，模型不可能知道的事实。** 体系专属的数值，作者的分类，论文里用的残基范围和接触对，以及项目自己的约定，包括哪个子问题配哪个计算，容差分几档，缺信息时请求长什么样。今天的审计里"模型不可能预先知道"的条目几乎全是这一类。它们进数据包和题面，不进规则表的正文。

**第二类，强制位置上的义务。** 判据本身模型知道，价值全在位置。没有往返不报占比，数字绑定来源，新定义冻结前过正反对照，距离按分子内分子间分支。这一类进代码，做成前置条件、提交门和绑定检查。agent 看到的只是一个动作被拒绝和一个标签。

**第三类，冲突卡。** 结果和作者预期冲突时，有哪几种解释，用什么观测分开。这是唯一以文字给 agent 的东西，只在交卷后的检查步出现，不进分析时的上下文，否则等于把答案写进提示。63 篇文献里这类关系只抽到 4 条，因为方法论文不写它。每个体系两三条，要请 Soojung 写。

**不该收的。** 模型本来就知道、没有系统能判定的触发条件、没有咬住任何一个案例的方法学转述。V1 的 33 条大多属于这一类，它们出自整合多种实验的论文，讲 FRET、SAXS、冷冻电镜、DEER，而 34 处失败没有一处发生在这些数据上。这些留作文献笔记，不进 agent 可见范围。

判据说成一句，一条内容要么咬住失败目录里的某一条，要么封住某个结论模板的某个前提，两样都指不出来就不进表。

**补一句关于"agent 最容易错的地方"。** 既然文献和我们自己的记录都能说出 agent 在这类任务上最常犯什么错，规则表就应该直接以这些错误为收集起点。做法是把每一类已知错误对应到一个决策点，问"在这个位置，什么检查能拦住它"，答案就是一条规则。53 篇 AI 失败模式文献的综合（同目录 `lit_ai_failures_20260911/`）给出六类我们没记过的错，其中无声失败、答案对机制错、agent 自己编判据这三类，各自对应一条新的检查。这样收出来的规则天然满足入表判据，因为每条都咬住一类已发生的错误。

## 4. 形式

**规则表是登记簿。** 每行记出处、来源类型、状态、对照记录的路径、咬住的案例。读者是人，用途是审计和送专家审。只靠综述和立场文章支撑的最多是候选。

**agent 看到的是四样东西。** 题面模板，写着这类问题拆成哪几问、每问配什么计算、最高答到哪一级。算子卡，一张卡等于一个计算，前置条件、参数范围、对照记录、结论上限都在卡上。有类型的退回，子问题缺必需计算就退回一次，退回信息不带数值。冲突卡，只在检查步出现。

**一件事两位辩手都认。** 微观判据全部进代码，模型永远看不到原文。分歧在宏观内容要不要沉淀成可检索的行。一方认为每道题人手写题面就够，另一方认为题面模板的栏位应该从表里来，否则换个体系又从头写。我的判断是后者，条件是这些行只作为题面模板的来源，不以原文进入模型的分析上下文。九月十日那次有效的拆题就在这个位置上，在用户回合里，模型跳不过。整段规则进提示那次失败和它的区别在位置，不在内容。

**名字。** 表可以还叫 rules table，但它的角色要写清楚。它是"哪些内容进了哪段代码、哪个模板、过了哪个对照"的账，它的规模和系统能力已经脱钩，42 条里 20 条在本项目无对应数据，真正写进代码前置条件的只有两条。

## 5. 颗粒度

宏观和微观这个问法，我建议换成"谁消费"。

题面模板里的内容是宏观的，说"这类问题在这种数据上拆成哪几问、封顶在哪一级"。它由 agent 用，验证信号是拆题覆盖率对照未参与建包的人写的题面，以及在标签互换过的数据包上能不能报出冲突。

代码里的内容是微观的，说"这一步的前置条件、参数范围、容差、失败返回什么标签"。它由代码用，验证信号是植入缺陷的检出率和干净数据的误报率，现在是 6 处检出 6 处、3 个干净包 0 误报。

两层不能合并，因为合并以后各自走进对方的失败模式。微观规则当文字进提示，就是 4.5 掉到 2 那次。宏观规则塞进代码变成死检查表，就是"距离超过半盒长即错"在 ADK 上把 62 和 70 埃的真实距离判错那次。

条目数由失败目录和结论模板封顶，和文献量无关。收集顺序反过来，先列结论模板，覆盖、占比、稀有态、动力学、实验辨识，每个列出成立所需的前提，只有还没覆盖的前提才去文献里取。第一轮超过 60 行就收紧到"必须咬住已发生的失败"。

## 6. 文献抽取的结果怎么用

63 篇里抽了 295 条"什么条件下什么证据能支持什么"。按上面的判据过一遍，能进候选的集中在三块，MD 采样够不够，MD 一侧的输入伪影，两个数是不是同一个量。带定量阈值的有 56 条，能直接写进代码的例子有有效样本量的下限、隐含时间尺度要出现平台、转动扩散的拟合滞后时间不超过轨迹长度的 1%、三点水模型下无序蛋白尺寸偏小 22% 到 36%、独立重复不少于 5 条。16 篇 agent 文献的 95 条讲的是评测和工具接地，它们最一致的一句是有外部验证器时修正有效，没有外部反馈的自我修正无效或更差。这一批另建 harness 规则表，不和科学规则混。

候选规则的整理版正在按 V2 的列格式生成，每行标决策点和咬住的失败编号，状态一律候选，今晚推到 GitHub。

## 7. 还没定的决定

按设计树往下走，下面这些是我能答的，后面标了我的建议。真正要你拍板的只有四条，放在最后。

- 一条规则的单位是什么。建议，一个决策点乘一种数据乘一步操作，对应一条义务和一个结论上限。一篇论文可以出零条。
- 入表判据是什么。建议，咬住一处失败或封住一个结论模板的前提。
- agent 在什么位置看到什么。建议，题面模板、算子卡、有类型的退回、冲突卡，其余不可见。
- V1 怎么处理。建议，保留为文献笔记，13 条在案例里用过的改写进算子卡或模板，两条已经造成损害的按操作而不按数据类型检索，其余不进 agent 可见范围。
- 宏观内容要不要沉淀成行。建议，沉淀，只作为模板来源。
- agent 文献的关系放哪。建议，单独的 harness 规则表。

要你决定的四条。

1. **交付物的主次。** 可信表是主，agent 流程是从，还是反过来。如果 agent 流程是主，"规则能不能改善 agent 自身的判断"这个问题必须做实验回答，四组对照每题每组四次，预算在一美元以内。如果可信表是主，固定流程加人写题面就够，实验可以推后。我的建议是前者，因为 Soojung 的三个问题问的都是 agent。
2. **冲突卡由谁写。** 我的建议是请 Soojung 每个体系写两三条，这是可以直接向他提的具体请求，比"规则表形式对不对"更容易回答。
3. **下一个体系。** 按 T4 溶菌酶那篇的基准标准选，有实验确认的瞬态、区分状态的坐标简单、PDB 结构够多。T4 溶菌酶自己满足这些条件，还有四态占比和增强采样参照。要查原始轨迹是否公开。
4. **要不要把表改名或拆成登记簿加候选表两张。** 只影响 GitHub 上怎么呈现，我建议拆。

## 8. 给 ChatGPT Pro 的问题

两个核心问题不变，下面是拆开以后能逐条回答的形式。

1. 规则表该整理什么。我们的主张是只收三类，模型不可能知道的事实、强制位置上的义务、冲突卡，入表判据是咬住失败或封住结论前提。请指出这个主张漏掉了什么类型的内容，以及入表判据是否过严。
2. 形式。我们的主张是表本身给人用，agent 只看题面模板、算子卡、有类型的退回和冲突卡。请给出一个反例，什么情况下 agent 直接读规则文本会优于这四样。
3. 颗粒度。我们的主张是按消费者分两层，宏观进模板，微观进代码，两层都不以原文进提示。请评价这个划分，以及"条目数由失败和结论模板封顶"是否可行。
4. 三十四处失败零知识缺口这个审计结论，是否足以支持"不缺知识、缺位置"的判断，还是样本偏了。
5. HSP90 的期望事件数计算，以及由此推出"作者的 9 条趋开不可能是 CPMG 测到的交换"，是否成立。
6. 文献覆盖。63 篇抽出的关系里，采样与时间尺度、伪影、等价性三块最多，体系预期值和区分性下一步最少。这是文献本身的分布，还是我们的检索偏了，还有哪些文献该补。

提示词和材料清单见同目录的 `PRO_PROMPT_RULES_FORM_20260911_ZH.md`。

## 9. 这份判断的边界

- 34 处失败的类型判定是一个模型按目录和原文做的，我复核了其中关键的几处，没有第二人复核。
- 295 条关系单次抽取，85 条只读了摘要。
- 期望事件数依赖两态假设和"CPMG 过程即 lid 开合"，约 9 条趋开是作者的分类。
- "规则能不能改善 agent 自身判断"仍然没有干净的实验回答，这份判断建立在失败分析和文献上。
