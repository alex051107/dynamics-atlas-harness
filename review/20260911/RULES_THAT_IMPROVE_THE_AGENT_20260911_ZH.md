# 什么样的规则能改善 agent 的行为：三方辩论的综合

2026-09-11 · 回答负责人要的核心问题 · 依据：三份辩论立场（方法学、agent 工程、怀疑者，均在 `debate_20260911/`）、四层实验与算子轮的记录、63 篇文献（`LITERATURE_GOAL_REVIEW_20260911.md`，已归入 Zotero）

## 0. 结论

一条规则要改善 agent 的行为，五个条件得同时满足。

1. 内容是一个有出处的科学判据，绑定到具体的量和具体的计算。
2. 适不适用由系统按"要区分的差异 × 量 × 当前操作"算出来，模型不做这个判断。
3. 在模型跳不过的地方执行：rubric 里的条目、必需的分析步骤、前置条件、提交门。
4. 拿模型之外的信号核对：对照、分析步骤的输出、作者发表的判断。
5. 用之前，在一个案例上过了它那一类的验证。

缺任何一条，它就只是给人看的文档。

按这个标准回头看，到 9 月 11 日为止，规则改善的是流水线，没有证明改善了 agent 自己的判断。agent 真正做决定的地方有三处：把问题拆成子问题，在新体系上选量和定义，缺信息时问什么。三处里只有拆题测过，而且有收益。下一步要测的就是这三处。

## 1. 三方一致的六件事

这六件三份立场都认，证据充分，可以当定论用。

| # | 共识 | 证据 |
|---|---|---|
| 1 | 规则原文贴进提示没用，还有害 | HSP90 方法题：七条协议 4.5，整段规则 2，方法卡 2.5（满分 5）；FRET 的染料和 RMP 条件被照办进 NMR 题 |
| 2 | 按数据类型挑规则是错的，要按当前操作挑 | 两条 FRET 规则被选进 NMR 题；HSP90 取到一张用不上的重加权卡，DHFR 和 ADK 一张都没取到 |
| 3 | 放在目录里等 agent 去读的规则不起作用 | 准入卡 4 次运行都列到了文件名，0 次打开 |
| 4 | 数字绑定计算来源，是目前最有效的单一机制 | 历史答复里 7 处数值错误抓到 6 处，7 条正确主张零误报；旧的"数字出现过"检查一处没抓到 |
| 5 | 没有外部信号的自我修订没用 | 12 次修订 0 次减少错误，3 次丢了内容；Huang 2023 和 Kamoi 2024 综述的结论相同 |
| 6 | 评分依据不能来自被评的流水线 | OP6 定义错了，4 份照实报告的答复在那一项全部满分 |

## 2. 三处分歧，怎么收

**分歧一：该投内容，还是投机制。** 方法学家认为规则必须是正确的科学判据，机制只是必要条件。工程师认为规则怎么进入运行决定一切，内容上的争论应该落到对照怎么设计上。OP6 同时证明了两边的话：机制到位了，agent 调用了、数字也绑定了；内容错了，半径和帧距离是两个不同的量；结果照样错。所以规则表的每一行要同时有内容字段和机制字段，缺一半就不算"在用"。

**分歧二：规则到底有没有改善 agent。** 怀疑者审计了 34 处失败，只有 6 处是规则能防的，其余出在输入数据、人拍的定义、运行器截断和评分循环上。方法学家说，S-02（没有往返就不报占比）在固定流程里起了作用，规则的价值已经显示出来了，只是没经过 agent。两边都对：规则目前的功劳在流水线上，agent 自己的判断是否因规则变好，还缺一个干净的实验。9 月 11 日算子组 98% 对自由组 58% 不能算数，自由组 8 份答复里 7 份被运行器截断，评分维度里还有两项按设计就偏向算子组。

**分歧三：负责人提的"体系预期规则"怎么用。** 例子是"HSP90 N 端在 apo 状态下闭态占比约 3.2%（CPMG），1 μs MD 看不到往返"。方法学家主张拿它当对照的期望值；工程师主张写成检查门；怀疑者提醒最大的风险是把答案写进 agent 的提示，只能当偏差探测器来测。三种意见合在一起：体系预期规则不进 agent 分析时的上下文，只在检查步使用。agent 交出结果之后，拿它去比，冲突了就要求 agent 或人解释。

它有没有用，用三个数据包测：一个干净的 HSP90 包；一个把开态和闭态起始标签互换过的 HSP90 包；一个预期不适用的其他体系。带规则的系统要在互换包上报出冲突，在不适用的体系上不套用这条预期。只在写这条规则的那个案例上得到确认，不算证据。

## 3. 规则分七类，按接入位置排

负责人描述的接入顺序是：用户问题 → rubric → 规则表协助分析和检查点 → 判断。工程师补了第五个位置：出错以后怎么恢复，缺信息时问什么。

| 位置 | 类型 | 规则长什么样 | 谁执行 | 证据现状 |
|---|---|---|---|---|
| 问题 → rubric | 1 框题 | 这类问题要拆成哪些子问题、每个子问题区分哪种差异、结论最高到哪一级、有哪些竞争解释 | agent 起草，人审定 | 唯一测出 agent 端收益的一类：子问题覆盖 HSP90 从 2 到 2.5，ADK 从 2 到 3；但 HSP90 核心错误从 1 变成 2，而且拆了题却没有门，4 份里有 2 份第二问空着交 |
| rubric → 分析 | 2 准入 | 数据能不能用：单位、帧数、列的含义、周期性几何 | 代码，冻结前 | 植入缺陷检出 6/6，干净包误报 0/3 |
| 分析 | 3 操作 | 某个量用什么方法算、前置条件、参数范围（例如占比的不确定度用分块平均） | 分析步骤的前置条件和参数 | 必需的分析步骤 8/8 被调用；方法来自采样质量文献，目前只有一部分做进了分析步骤 |
| 分析 → 检查 | 5 定义校验 | 一个定义要先过正反对照才能用：开态起始的轨迹应落在开态邻域里，闭态起始的前 20 个点应落在外面 | 代码 | OP2 过了（18/20）；OP5、OP6 没过，已撤回 |
| 检查 | 6 主张 | 每个数字绑定计算来源；结论措辞随证据收紧，例如没有往返就写"不能给出占比" | 代码 | 数字绑定 6/7；S-02 在用 |
| 检查 | 4 体系预期 | 某体系在某条件下某个量应有的表现，带不确定度和出处 | 代码，在 agent 交答案之后比对 | 未测，需要第 2 节的三包测试 |
| 恢复与信息需求 | 7 恢复 | 检查不过时怎么办；缺信息时发一个有类型的请求，例如"容差未定，请人选" | agent 发请求，系统记录 | 未测；拆题版那次"没算"和真正的"数据不够"，目前分不开 |

从这张表看，能让 agent 自己变好的是第 1 类和第 7 类，只有在这两处是 agent 在做决定。第 2、3、5、6 类让流水线更可靠，换谁来跑都一样。第 4 类介于两者之间。

## 4. 规则写成什么格式

每条规则一行，字段固定。前几个字段对应内容、触发和执行，最后三个对应验证和状态。

| 字段 | 含义 | 例子（HSP90 占比规则） |
|---|---|---|
| 编号、类型 | 七类之一 | HSP90-R1，类型 6 |
| 要区分的差异 | 统计、准确、覆盖三种用途之一 | 占比，属于统计 |
| 体系与条件 | 构建体、配体、温度、模拟设置 | 人 HSP90α N 端，apo，40 条 1 μs 无偏 MD，开态起始与闭态起始各 20 条 |
| 量与操作 | 具体的量，和正在做的计算 | 开态与闭态占比；从帧计数算占比 |
| 义务 | 必须算什么、查什么 | 数双向往返的次数 |
| 执行点 | 在哪一步、以什么形式强制执行 | 报告脚本读往返计数，自动决定结论等级 |
| 验证信号 | 用什么外部信号核对 | 往返计数来自分析步骤的输出；作者自述轨迹不遍历 |
| 结论后果 | 允许说什么，停在哪个标签 | 往返为 0，只能写"不能从这批 MD 给出占比"，实验值 3.2%（CPMG）单列为作者报告 |
| 来源 | 论文位置或项目证据 | Henot 2022；Grossfield 2019；7 月 28 日会议 |
| 状态 | 候选 / 已验证（在哪个案例、过了什么对照）/ 撤回 | 已验证：HSP90，40 条中 0 条往返 |

第 4 类（体系预期）另加三个字段：预期值及其不确定度、产生这个值的实验方法、适用边界。这类规则只给检查步用。

规则表 V2 已经有其中一半字段，还要补四列：要区分的差异、当前操作、执行点、验证信号；"状态"也要从一句描述改成三个固定值。补完以后，规则表拆成三张子表：

- MD 的量能不能信：采样质量、状态定义、动力学模型验证，出自 Grossfield、Prinz 这类文献。
- 多种实验怎么合：原 33 条里在四个案例中用得上的 13 条。
- 体系预期：从论文里提炼，只进检查步。

## 5. 按新格式改写的五条 HSP90 规则

| 编号 | 类型 | 触发 | 义务与执行点 | 验证信号 | 结论后果 |
|---|---|---|---|---|---|
| F1 | 1 框题 | 问题里有"是否到达某状态" | rubric 拆成三问：方向变化、绝对吻合、完整转变；每一问指定必需的分析步骤 | 拆题后的覆盖率，对照专家写的 rubric | 三问分行报告，"趋向"不能写成"到达" |
| A1 | 2 准入 | 读作者沉积的 NOE 违例文件 | 用第 2 列原生违例，第 3 列是伪距离；作为分析步骤的前置检查 | 第 2 列均值落在 0 到 15 Å | 检查不过，分析步骤拒绝运行 |
| R1 | 6 主张 | 从 HSP90 这 40 条轨迹读占比或速率 | 数往返次数；报告脚本按计数定结论等级 | 往返计数；作者自述不遍历 | 往返为 0，写"不能给出占比"，CPMG 的 3.2% 单列 |

## 6. 已经可以定下的，和还要实验回答的

下面这些可以直接定下，不用再测：规则原文不进提示；规则按当前操作触发；数字绑定计算来源；规则分候选、已验证、撤回三种状态；评分依据来自外部。

需要实验回答的只剩一个问题：规则能不能让 agent 自己的决定变好，也就是第 1、4、7 类有没有用。综合三方的设计，最小实验是这样：

- 标准答案全部来自外部。三个来源：按作者自己的判据复现的 HSP90 7/9/4 分类；三个植入了已知缺陷的数据包；一个项目里从没出现过的体系，比如 ATLAS 或 mdCATH 里的蛋白，或者有 EMD 参照和四态占比的 T4 溶菌酶。
- 先修好运行器，让自由分析组能正常读数据、做计算，然后把 9 月 11 日那 16 次原样重跑一遍。
- 分四组：不给规则；同样内容写成带标签的文字；同样内容做成 rubric 条目、分析步骤前置条件和提交门；固定流程。每题每组跑 4 次，判定规则在跑之前写死。
- 体系预期规则另外用第 2 节的三包测试。
- 请两位盲评，至少一位没参与建包。评分维度里去掉按设计偏向某一组的项，同时记录人工时间。

结果这样读：第三组比第二组好，说明规则的形式重要；第二组比第一组好，说明规则的内容本身对 agent 有用；第三组和第四组差不多，说明分析这一步 agent 没有增量，它的价值得去框题和恢复那两处找。

## 7. harness 方向（留作后话）

负责人提到四个方向，工程师立场给了判断，这里只记结论：

- 提示是最弱的约束。按能不能被跳过来排：提示 < 工具描述 < 必需工具和提交门 < 对外部数据的核对。
- 按题型固定工具路线是对的，但路线要按"要区分的差异 × 手头的数据"来选，不能按数据类型选。
- 出错后的自审，只在错误信号来自外部时才有效；退回信息里不带具体数值。
- "还需要什么信息"要做成有类型、能计数的请求，否则分不清"没算"和"数据不够"。

## 8. 可以直接对外说的一段话

规则有没有用，取决于五件事是否同时成立：内容是有出处的科学判据；适不适用由系统按当前操作判断；执行点模型跳不过；核对信号来自模型之外；使用前在案例上过了对照。按这个标准，我们的规则到现在改善了流水线，数字能核对了，错误的定义能被撤回，但还没有证明改善了 agent 的判断。agent 真正做决定的是三件事：拆题、选定义、缺信息时提出请求。下一轮实验就测这三处，标准答案全部来自作者发表的判断和已知缺陷，不再用我们自己流程的输出。
