# 自审与三方讨论：计划 v1.0 的处置

2026-09-22。审查对象为 v0.2，最终产物为 [计划 v1.0](PLAN_ZH.md) 和 [案例执行卡](CASE_CARDS_ZH.md)。

**结论：保持两案例、真实分析、领域反馈和同强模型 A/B/C 比较的主线。只补齐执行定义、过期状态和变更边界，不改成新研究项目，不增加处理组，也不在会前建设新平台。**

## 实际做了什么

先由当前执行者自审，再让三名用户明确要求的 subagent 分别检查科学工作流、评价设计和实施范围。三者独立读文后，相互提出问题并回应，完成一轮交叉讨论；当前执行者回到计划、来源状态和必要原文处置意见。

这不是三个领域专家的科学认可，也没有取得 ChatGPT Pro 的新回复。没有运行论文复算、正式模型对照或新的模拟。K-Ras 只定点核对了 Fig.3、Table 2 和 Data availability，尚未完成整篇深读。

## 讨论中的问题与取舍

| 问题 | 讨论后的判断 | 本版怎样处理 |
|---|---|---|
| 是否应该推翻现有路线？ | 三者均未提出需要重做研究设计的事实依据 | 保留原方向、两案例、A/B/C 及会后4+36的候选规模 |
| SI 不齐，有处理后数据是否能开始？ | 可以从足以解释的处理后输入做下游复算；缺少决定字段、条件或筛选的说明时，该步骤仍未就绪 | 案例卡说明数据层级与必需缺件；不要求无关原始谱齐备，也不冒称上游拟合已重做 |
| 每个案例是否必须找一个竞争解释？ | 有些案例更适合检查关键不确定性；普通稳定性检查不能冒充机制鉴别 | 统一为与主张相关的挑战检查，并明确检查本身的结论上限 |
| 怎样避免仅“下载了论文”就开始计算？ | 需要一页执行前协议；容差等必须来自真实输入与计算定义 | 增加目标、输入、方法、比较、挑战、产物和停止条件；K-Ras 从 Fig.3/Table2 取数检查起步 |
| 一篇两小时是否仍会无休止检索？ | 单例上限不足以约束8–10篇逐篇排查 | 8–10篇只轻筛；首轮两案取数/环境排查合计4小时，每案至多一次备选，到限保留缺口 |
| C 是否因为独占日志或计算工具才显得更好？ | 三组必须共有工具、外围日志和留存，C 只能增加模型可见的控制/状态干预 | 增加共同环境定义；额外调用计费，控制器不能读评分答案；仅解释组合处理效果 |
| 隐藏评分文件是否就等于无答案任务？ | 联网、文件名、其他运行输出等仍可能泄漏答案，预训练污染也不能保证排除 | 冻结共同访问范围；做不到时归为开放论文复现，不夸大独立推断 |
| 失败后重跑会不会把结果挑好看？ | 科学错误、执行失败、服务故障应分开；正常失败不能挑最好答复替代 | 固定36个正式slot；基础设施至多恢复一次、费用时间累计，首次与恢复后结果分报 |
| 是否应在会前实现控制器和记忆服务？ | 现阶段没有足够案例证明需要这些工程组件 | 使用现有脚本、文件和JSON；工程实现由实际重复动作或恢复问题触发 |
| 计划何时才需要改？ | 输入和协议补全可以局部完成，不能每见一个新建议就重写路线 | 新证据推翻前提、真实阻断、关键错误或明确人类纠正才触发必要修改；正式结果出现后不改题追分 |

## 没有采用的扩展

没有新增第四比较组、通用评分公式、跨蛋白统一容差、知识图谱/向量数据库、常驻多 agent、会前自动恢复系统或更大的样本量。它们目前无法解决“首个案例能否执行、结果能支持什么”的问题，可在真实证据需要时再评估。

4次试跑和36个正式slot保留为会后探索设计，需要数据、参考结果、评分和预算先就绪。若基础组已满足该轮必要项且无严重错误，保留简单方案；若难以区分方案，报告证据不足，不为制造差异增加模块。

## 仍未决定的内容

首例实际输入文件、字段/残基/变体对应、精确计算定义和合理容差；第二个MD案例；正式模型与资源上限；领域评分安排。它们有固定填写位置，缺失时不能开相应计算或正式试验，但不要求现在凭空猜定，也不阻止可以独立完成的来源整理。
