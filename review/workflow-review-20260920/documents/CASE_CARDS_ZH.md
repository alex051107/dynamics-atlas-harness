# 首批案例执行卡与完成标准

对应 [执行计划 v1.0](PLAN_ZH.md) · 2026-09-22。两张卡目前均未达到运行条件。填写卡片是接下来的执行动作，不代表分析已完成。

执行者负责补输入、方法和实际记录；用户及 Soojung/Gina 负责科学口径和解释的最终确认。已授权的本地取数、文件整理与可逆准备可继续完成，不因一个未知字段而停止全部工作；只暂停依赖该字段的计算或结论。

## 1. 开始计算前，先把这些内容写清楚

| 内容 | 填写要求 |
|---|---|
| 要回答的问题 | 一句话说明要区分的解释，不能只写“分析这个蛋白” |
| 重现目标 | DOI、图/表/段落、具体比较单元；不默认复现整篇论文 |
| 数据起点 | 原始测量、处理后数值、拟合参数或轨迹派生量；说明上游哪些步骤没有重做 |
| 输入 | 实际文件位置、数据范围、构建体/条件/单位/残基映射及必要 SI 定义 |
| 方法 | 所用计算定义、参数、筛选和缺失值处理；不清楚的地方标为未决 |
| 比较 | 本次输出与什么参照比较、容差是多少、为什么合理；运行前确定 |
| 挑战检查 | 一个可执行的竞争解释检查或与主张直接相关的敏感性检查；写明它能检验什么 |
| 交付与边界 | 输出文件、必要结论单元、严重错误和允许/不允许报告的内容 |

**就绪条件：** 输入确实能打开，关键字段和分析定义可解释，比较办法及结论边界已写明。没有数据时可以完成流程重建，不能把数值复算标为就绪。未拿到全部 SI 不自动阻塞，只有当前步骤必需而缺失的说明才阻塞该步骤。

## 2. 案例一：K-Ras 状态化学位移比较

**当前状态：候选取数与协议检查，未开始计算。**

| 项目 | 已知内容或下一步 |
|---|---|
| 来源 | Hansen et al. 2023，[论文](https://www.nature.com/articles/s41594-023-01070-z)；已取得主文 PDF 和文字衍生本 |
| 具体目标 | 先检查 Fig.3（PDF 第5页）和 Table 2（第6页）中的 Switch I 比较：GDP 与随机线团两个参照下的化学位移关系能否按作者定义复算 |
| 候选数据入口 | Data availability（PDF 第11页）给出 [Dryad DOI](https://doi.org/10.5061/dryad.j6q573nm0)；论文也提供 Source Data。入口已定位，文件尚未取得与验证 |
| 可接受的数据起点 | 作者提供的处理后化学位移/交换相关参数；若能解释来源和字段，可用于下游比较 |
| 必须取得的输入 | 目标比较所需数值、误差或精度信息、条件、残基编号与变体对应关系，以及当前步骤必需的方法/SI 说明 |
| 必须核清的定义 | signed Δϖ 与 unsigned &#124;Δϖ&#124; 的用途；筛选范围；WT/G12C/G12D 是否以及怎样合并；R² 与 RMSD 的定义；参照数据的来源和缺失处理 |
| 候选计算 | 按已确认的字段和作者比较单元生成散点及相应统计量；具体脚本和容差在输入核清后填写 |
| 挑战检查 | 检查两种参照是否因不同评价量、筛选或条件而给出不同支持；只运行数据允许且与该主张有关的检查 |
| 允许报告 | 本次实际完成的下游比较、对作者相应比较单元的复现情况、结果对状态相似性解释的有限支持 |
| 不能报告 | 上游 CPMG/CEST 重新拟合已完成；相关性唯一确定了结构；GTP 条件下的激发态就是实际 GDP 结合态；新状态发现 |

第一步只取得并检查来源文件、数据说明及对应的原始图表。若两小时内仍缺关键字段或协议说明，保存缺件与流程草图，按总取数预算决定一次备选，不持续尝试相同失败下载方式。

论文中已有的 Table 2 数字是开放论文复算的参考，不能直接填入“本次计算结果”。此案例已经暴露给规划助手，属于开发案例；不能稍后改名为未见测试题。

## 4. 每个案例只维护这一组最小文件

| 文件 | 用途 |
|---|---|
| case.md | 本卡、运行前协议与具体来源位置 |
| workflow.md | 关键阶段、判断依据、遇阻分支；明确作者记载/依赖推断/专家补充/本次建议 |
| sources/ | 原件或可重复取得的来源清单；大文件可仅留指向本地受控目录的索引 |
| analysis.py 或 notebook | 实际采用的代码及参数；复用现有工具时记录版本与调用 |
| results/ | 实际输出、图表与失败记录 |
| conclusion.md | 参照结果/本次结果/差异、证据来源、剩余解释与停止理由 |
| state.json | 当前阶段、有效结果路径、未决问题、已做动作、下一步与资源使用 |

这是目录约定，不要求先生成空文件，也不要求搭平台。结果大文件不写进聊天摘要；state.json 不存未经核对的“科学事实”。同一已有结果可以复用，输入或参数变化时标明哪些下游结果需要更新。

## 5. 交付时怎样判断完成

| 状态 | 必须能展示的证据 | 不能替代它的东西 |
|---|---|---|
| 流程已重建 | 关键步骤有来源、输入输出、判断依据与失败分支，未知的真实研究经历明确标出 | 方法名清单、只有顺序的方框图 |
| 数值已复算 | 输入和脚本可定位，有本次输出，按运行前比较办法判断一致或差异 | 作者表格原值、未运行的代码、只有文字推断 |
| 解释已检查 | 作者报告、本次计算、综合解释逐项区分，相关挑战检查有结果，不能推出的结论已说明 | 高相关性被直接写成机制或唯一结构 |
| 部分完成并停止 | 已完成部分和唯一/主要卡点可定位，说明缺什么、哪些结论因此不能写 | 把缺数据计作科学阴性或复现成功 |

挑战检查可以检验竞争解释，也可以检验与主张直接相关的不确定性；数值稳定只支持相应稳定性，不能自动排除另一种科学机制。

周四会议可以展示任何真实达到的状态，但“可以展示”与“数值复现成功”分开。原始来源、作者参考和本次结果并排放置，方便专家指出流程遗漏。
