# 规则提示保留来源范围：渲染层修复与仍未验证的效果

## 1. 修复结果

通用的本题检查现在先展示；来源论文的原条款随后展示，带论文身份、方法家族和原文适用范围。缺少匹配方法证据时，原条款的专用字段不再无条件显示为本题必填或弃权理由。

## 2. 为什么这样改

HSP90 两份 B 答案带入 RMP 条件。问题不在于原 FRET 条款错误，而在于把一个方法内的条件迁移成另一个问题的要求。保留原文，同时将项目归纳与文献原条款分开，才能让读者判断这种迁移是否合理。

## 3. 实际改动范围

只调整渲染函数，新增来源方法映射及针对性测试。33 条注册表、选择器和原运行输入未改。映射实际覆盖注册表中的 11 个 paper_id；编号延伸到 C012 不代表有 12 篇，不虚构缺失来源。

## 4. 测试和 v4 内部冲突的处理

既有分组、目标—检查配对、空选择及未映射路径通过。真实 HSP90 义务包仍有 7 个规则块；两处方法专用条款在缺少 FRET 适用证据时被标为适用性未确认。正向测试确认有匹配 smFRET 元数据时仍能显示原条件。

v4 一处要求普遍按方法匹配，另一处要求其余五条不变；这两项不完全兼容。代码遵循前者：没有方法元数据的非通用类都不会默认为适用，不只处理两个点名条款。通用类豁免按 v4 指定保留，不能因此扩大原文的 transfer_scope。测试保护文本与配对，不声称其他所有块完全相同。

## 5. 这是否已经改善 Agent 答案

尚未运行新 B 答复。当前完成的是提示表达与作用范围的代码修复，行为收益未验证。可选付费回归跳过，不改变首轮原答案、不作前后增益比较。

三种“规则”继续分开：标记数据方向的数值判据、提供给 Agent 的科学提醒、管理下一轮投入的继续条件。
