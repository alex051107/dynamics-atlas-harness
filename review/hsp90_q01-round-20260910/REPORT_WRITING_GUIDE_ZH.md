# 怎样写一份逻辑严密、别人看得懂的项目报告（Codex 执行版）

2026-09-10 · 适用于 Dynamics Atlas 所有给人看的报告：进度报告、轮末报告、组会 deck、给 Soojung 的简报 · 与 `POST_RUN_REPORTING_PROTOCOL_ZH.md`（产物与 skill 顺序）配套，本文只管"怎么写"

## 0. 先固定思路：一条主线，从 Rules Table 起步讲到现在和下一步

报告在动笔前先写一句主线（through-line），格式固定：**"我们从 X 出发，因为 Z，走到了 Y；下一步是 W。"** 主线写不出来就不要开始写正文。本项目当前这句是：

> 我们从"把文献里的科学检查规则整理成一张可选择的 Rules Table，让 Agent 在异质蛋白资料上少犯错"出发；因为要先证明这张表在真实数据上有没有用，我们把它接到一个能自主读资料、算数、交答案的 Agent 上，用 HSP90 的 40 条轨迹做了第一次同题对照；结果是拿到了一项可复核的科学回答（闭合起始轨迹一半在 1 μs 内出现持续开放方向读数），同时发现规则正文把别的实验方法的专用条件带进了答复；下一步是先核对这个方向读数和作者原生 NOE 观测的对应，再修规则的适用范围，然后用普通 Agent 去做第二个蛋白。

读者读完主线就该知道全文要讲什么。正文每一节都必须能回答"这一节把主线往前推了哪一步"。推不动的段落删掉。

## 1. 五拍结构：现状 → 张力 → 利害 → 转折 → 落点

每份报告按这五拍排，顺序不换：

| 拍 | 回答什么 | 本项目现在的内容（进度报告用） |
|---|---|---|
| 现状 | 我们当初要做什么、为什么 | G1–G4 目标；Soojung 7/28 与 8/24 的要求（先小后大、HSP90 第一）；Rules Table 从 8/05 文献卡试点到 8/12 的 33 条注册表、8/13 选择器 |
| 张力 | 什么地方卡住、什么还没被证明 | 表整理好了，但一直没有在真实蛋白数据上证明它让答案更好；8/25–9/04 大量原型与 PR，没有对外交付；12 次 Luna 开发运行显示 Agent 能算但交付会丢 |
| 利害 | 不解决会怎样 | 继续建系统而不回答科学问题，会把项目变成维护 Rules 的工程；Soojung 看不到原型帮她理解数据 |
| 转折 | 我们做了什么不同的事 | 缩到一个问题四份答复（v3.4），同一 Agent 有无规则提示各两次，评分独立于规则；9/10 跑完，$0.076 |
| 落点 | 结果是什么、证明了什么、没证明什么、下一步 | 科学结果（分区表）；Agent 表现（3 对 1 错）；规则问题（专用条件迁移）；三者互不吞并；下一步四条轨道 |

进度报告的落点必须以"我们接下来需要读者决定/知道什么"结束，不是"谢谢"。

## 2. 固定骨架（进度报告与轮末报告通用）

```text
标题：一句话说结果，不是话题（例：HSP90 的有限时间开放方向变化：科学结果与规则提示的开发观察）
0. 三句摘要（给只读三句的人）：做了什么 / 发现了什么 / 下一步是什么
1. 我们要回答的问题和为什么（现状）
2. 到目前为止走过的路（按时间，只留改变了判断的节点，每个节点一行：日期 · 做了什么 · 得到了什么 · 证据在哪）
3. 这一轮做了什么（转折）：输入、方法、边界、费用，用一张表
4. 结果（落点，一节一个问题）：
   4.1 科学上看到了什么（数字带 n、单位、窗口、统计单位）
   4.2 Agent 表现（逐份，对/错/过强/未完成）
   4.3 规则/系统暴露了什么
5. 这些结果证明了什么、没证明什么（三栏：Observed / Interpretation / Design proposal）
6. 下一步（每项：做什么、为什么值得、多久、停止条件、需要谁决定）
附录：术语表（每个缩写第一次出现处也要解释）、证据表（每个数字的来源文件）、人工介入清单、状态码
```

节数可以合并，顺序不能乱：**问题 → 路径 → 这一轮 → 结果 → 边界 → 下一步。** 不要按文件目录、按时间流水、按系统架构组织正文。

## 3. 每一段的写法

- 段首一句先给结论，后面的句子只做两件事：给证据，或者给边界。一段一个中心。
- 每个数字必须带：分子/分母、单位、时间窗口、统计单位（轨迹还是帧）、来源文件。写不全的数字不进正文。
- 三个标签分开用：**Observed**（结果文件里直接有）、**Interpretation**（有边界的科学解读）、**Design proposal**（还没做的设计）。一句话里不混两种。
- 先说现实中的对象、动作、结果，再考虑要不要内部名称。主文里不出现字段名、文件名、SHA、任务编号、状态码；确实需要时用"人话（`exact_name`）"，全文出现的内部名称不超过 5 个。
- 每个缩写第一次出现就解释（NOE、CPMG、RMP、ATP-lid、seed lineage）。术语表里再放一次。
- 因果连接词只在真有依赖时用："因为 NMR 结构集合是无序的，所以时间信息只能来自轨迹"可以；"因此"用来串两个无关句子不行。
- 不写"本报告旨在""值得注意的是""需要强调的是""这并不意味着""并非……而是……"。不堆三项并列。不用"系统发现了"描述确定性计算。

## 4. 本项目必须守住的边界句（原样可用）

- "以上是对已保存派生资料的再分析，不是新的实验验证。"
- "推进条件满足与否是管理决定，不等于 Rules 有效或无效。"
- "开发者核对不是独立科学评审。"
- "HSP90 是开发过程看过的案例，不能用来估计未见论文上的正确率。"
- "这些计数来自有限窗口、指定判据、按起始来源分组的轨迹，不是平衡占比或速率。"

## 5. 组会 deck 的对应写法

- 页数按时间：15 分钟 8–10 页。标题是完整的判断句（"闭合起始轨迹一半出现持续开放方向，开放起始零条反向"），不是标签（"结果""PCA"）。只读标题应能讲完整个故事（ghost-deck 测试）。
- 一页一个问题一张图；图上直接标出该看的地方；页脚标来源。
- 顺序：问题 → 为什么是这个蛋白/这篇论文 → 拿到什么数据 → 分析逻辑一页 → 结果两三页 → 与论文关系一页 → Agent 与规则的观察一页 → 边界与下一步一页。系统、Agent、Rules 出现在科学结果之后。
- 讲稿写在 notes 里（中文），正文英文短句。

## 6. 交付前的冷读检查（自己过一遍，写进 review_report.md）

1. 只读标题和每段第一句，故事是否完整？断在哪就补哪。
2. 主线里的 X、Z、Y、W 在正文里各出现在哪一节？缺一个就是结构问题，回到 §1。
3. 随机挑三个数字，能否在证据表里找到来源文件和行？
4. 删掉所有代码格式的名称后，正文还能不能读懂？
5. 有没有一句话同时在说结果和推测？拆开。
6. 结尾停在"需要谁决定什么"，还是停在客套话？
7. 用 `humanizer-zh-plus` 的 `scan_ai_prose.py` 扫一遍，只改它标出的散文句。

## 8. 节奏规则（防止"做了很多、交付很少"）

- 每周五必须有一份给人看的更新（进度报告或轮末报告的 HTML + 一页简报），不是内部状态快照。
- 没有交付物就不出新版本计划。计划改到 v3.4 用了一晚三轮审查，运行只用了 45 分钟；以后先跑再改。
- 内部任务目录每周新增不超过 3 个；治理文件只在结果改变判断时更新。
- 报告写不完先交三句摘要 + 证据表，不交空模板。
