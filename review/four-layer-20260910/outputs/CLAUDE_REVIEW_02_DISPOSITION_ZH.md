# 第二轮只读审查：逐项处置

来源：用户在当前任务粘贴的Claude只读审查全文。收到时E1a/E1b和ADK普通答复已完成，E2已完成24次，E3已开始。故不修改这些实验的冻结代码、卡片、术语清单和原始结果；审查转为解释边界、独立回放及旁注。

| 审查意见 | 核对与处置 |
|---|---|
| E1a 6/6只是参照一致性 | 采纳。逐项记录数值参照、来源元数据、行内结构检查分别承担什么；不把参照制作成本藏在检查器里。 |
| ③④属于参照无关 | 收窄：③预期行数来自受信来源，仍依赖外部事实；④单调性可内部检查，但时间对齐也依赖参照。用“是否依赖数值矩阵”和“仍依赖什么来源事实”两列说明。 |
| 七个checks名不等于七项科学审查 | 采纳，补覆盖审计。observation_window未单独实现；statistical_unit仅标签；不宣称自动验证物理语义。 |
| 干净包与参照相同，零误报不足 | 采纳。保留原实验0/3，注明这是自一致性控制。ADK独立GROMACS交叉核对提供外部数值证据，但不是另一次独立重建表的E1a误报试验。 |
| assert表集合不一致应转FAIL | 代码路径属实，列为未测输入边界；不在已完成的E1a上修代码再重跑。 |
| E0百分比两行可合并、同因加组 | 保留逐数值观察以便核对，另加same_cause_group视图，报告按输出与原因组区分；不把行数当独立错误样本数。初稿O3P归因已撤回，另新核出N18均值方向转述错误，修订记录单列。 |
| 对历史claims重放当前ceiling_check | 立即零费用执行，保留原稿，标明每个旧任务claim接口与上下文的可获得程度。技术flag命中与准确检出具体科学错误分开。 |
| ADK字段写精确范围和理由 | 当前ADK_plain、E2、E4的FIELD_DEFINITIONS已经逐字写出CORE1–29/68–115/168–214、NMP30–67、LID118–160及项目自定义说明，三份相同，无需修改冻结输入。报告补精确首末时间区间。 |
| 数字×10/100及任意a±b、a/b都算匹配 | 不按此方案采纳：无来源绑定的组合匹配会放过碰巧可由无关数字构造的错误。未来应按具体主张绑定原始量、单位和变换；本轮保留误报并统计。图像来源不能仅因未出现在文本中就判错，列为可预见误报。 |
| 上限和窗口正则太宽 | 采纳风险判断，按实际反馈审计敏感性与误报；不声称简单收紧正则就解决科学证据边界。 |
| E2 evidence_role分支无PUBLIC_FACTS输入 | 已核实三题均无该文件，只有E3 Q05有且不运行检查器。E2没有实际测试证据角色检查；不纳入有效检查器精确率分母，单列不可用。 |
| E3把BME等加入Q-H2不适用项 | 不能事后扩展已冻结清单。旧清单主结果保持，另以探索性逐句分析报告不必要的重加权前提；只在答复当成本题必需条件时算迁移问题，合理建议未来重加权不算错。 |
| TOKEN_LIMIT按实际正文评分 | 已采用。合法提交保留并另记状态；不从token上限独立推断提示文本导致失败。 |

同一实验首调用之后的反馈，不作为同题修改再验证的理由。当前试验可以暴露设计缺口，也可以得到不支持保留某组件的结果。
