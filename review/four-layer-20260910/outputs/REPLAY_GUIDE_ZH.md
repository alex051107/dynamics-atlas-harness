# 如何核查这次交付

先阅读总报告和逐题分数，再按需要打开原答与实际工具输出。归档用于复核已经发生的实验，不会默认启动新的付费调用。

## 文件与容器地址

公开包中使用相对路径；运行容器内的资料固定挂载为`/source`，工作结果固定写入`/work`。宿主机的个人Downloads或Desktop地址不是评价Agent的数据接口。原始轨迹较大，按来源链接与下载清单获取；实验用派生表、题面、工具、卡片、冻结文件和原答保留在各实验归档中。

`archives/*_frozen_evidence.tar.gz`分别对应准入纯代码测试、准入卡行为测试、ADK普通答复、结论反馈、方法卡和拆题比较。可在任意新目录解压查看，例如：

```bash
mkdir -p evidence
for archive in archives/*_frozen_evidence.tar.gz; do
  tar -xzf "$archive" -C evidence
done
```

归档的SHA-256和文件数记录在`ARCHIVE_MANIFEST.json`。这证明交付文件的身份；不以文件哈希代替科学正确性。

## 原答、评分和费用怎样对应

`blind/BLIND_INDEX.json`列出盲编号、问题和提交状态；`blind/blind_scores.csv`保留揭盲前评分及逐项理由；`blind/SCORE_SEAL.json`记录封存时间。`outputs/UNBLINDED_SCORES.csv`在评分封存后才连接条件与运行编号。沿运行编号可以找到归档中`runs/`里的原答、首次提交、工具事件、回执与工作文件。

每个实验的`outputs/paid_usage.jsonl`是逐次API请求费用；总账先按请求求和，再按实验核对回执。ADK两份答复的费用只在`ADK_plain`记一次，其他ADK科学目录仅引用，不重复累计。历史四批费用与本轮新增费用分列。

## 冻结与重跑边界

每个实验自己的`FREEZE.json`列出首次调用前的题面、评分依据、运行顺序、工具和提示身份。归档中的`runtime/readiness.json`保留关闭后的状态。不要为复核改成已授权运行，也不要直接启动`continue_campaign.py`或`run_experiment.py`；这些入口用于新的付费研究，重新启动不是只读复核。

本轮容器的内容ID记录在冻结文件与`ANALYSIS_ENVIRONMENT.json`中。它精确标识实际运行环境，但不是已发布的公共镜像地址。包内保存软件版本与运行代码；若另一台机器没有同一镜像，不能把未经核对的新构建称作完全相同环境。查看原答、费用、评分、派生表和报告不需要该镜像。

## 最值得核对的四件事

1. 对照ADK完整分子距离与GROMACS核对报告，看物理准入是否早于题目冻结。
2. 对照E1a逐缺陷标志与参考依赖说明，确认6/6没有被写成无参照自动发现缺陷。
3. 对照E2首次提交、实际提示和最终提交，看提示是否正确、是否引入新错误；不要只看提示数。
4. 对照E3/E4逐份评分，看收益是否来自少错、多回答，或只是改变措辞、增加题目要求。

原始评分封存后不覆盖。任何新的复核分歧应另写更正说明，保留原分、理由和新证据。
