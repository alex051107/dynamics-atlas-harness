### Claims to verify
C1. §8A 的六条判据 (a)–(f) 全部满足才 `proceed: true`，任一不满足即停。在这条规则下不存在"系统按自己的规则给自己打分"的路径，也不会把"B 引用了某条 rule_id"当作该规则造成改进的证据。
C2. §8A 判据 (a)(c) 读的是 `claims_check.csv` 的 `VERIFIED / MISMATCH` 标签，而这些标签由同一个 Codex 核对。这不构成"准备者自己判是否继续"的自证回路；若构成，最小修法不需要引入新的评审层。
C3. §8A 判据 (e)"人工介入清单里没有改动结论及条件、证据位置两节的介入"，足以排除"修好的报告被反记为 Agent 成果后推进"的情况。
C4. §14.2 的选择规则 (a) 同一构建体与条件下的可比较性质 (b) 可下载且含逐帧或逐残基数据 (c) 论文方法节已有分析即可回答，符合你 v1 审查里"围绕科学问题而不是注册表方便"的要求；"两个都合格取本机资产多的"不会把便利性写成科学理由。
C5. §14.2 要求第二体系的题面必须是论文自己陈述的可比较性质（作者报告，带 locator），按 Q01 写法"检查并综合已有资料"。这足以防止 Codex 自己出题自己判。
C6. §14.3 "预处理脚本只允许论文方法节已有的既定分析，每个脚本 ≤ 1 个，需要更多即 §8 第 5 行停"是可执行的边界，不会把一次合理的常规分析误判为"题目专用代码"。
C7. §14.4 第三体系的复用成本条件（`RT` 零逻辑改动、方法 proposal ≤ 1、案例包 ≤ 2 个工作日建成）是 Codex 可以自行判定的，不需要人。
C8. §14.5 的停止线与 §14.1 的每周一页状态，加上 PM 随时可叫停，足以覆盖你 v1 审查里"人力才是真成本"的担忧；没有遗漏必须写进去的停止条件。
C9. 授权第 9 项（Codex 不等 PM 确认即按 §8A 推进，PM 保留叫停与改判）与"是否继续投入由负责人决定"不矛盾：负责人在开工前已按写死的规则一次性决定。

### Output contract

- VERIFIED <指向附件的节号>
- WRONG <替换文字：直接可粘贴进附件对应节的中文，Codex 拿到不用再问人>

S1、S2 各给一个选项加一句理由。
标签之间不加议论。不用置信度词。不复述计划内容。
