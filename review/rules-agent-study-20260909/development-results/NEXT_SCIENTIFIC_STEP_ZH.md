# 用新的科学答案决定 Rules 是否值得继续

**建议继续做一个小型增量研究，并把每一步都落到科学回答上。** 原型应当接收真实蛋白体系的论文、实验与模拟资料，自主选择合适的既有分析，给出有数字、有来源、范围明确的结论。Rules Table 是实现这个目的的一种方法，其价值要通过与普通工具 Agent 的比较来判断。

本轮已经证明 Luna 会实际读资料、计算和纠正部分错误。我们仍不知道，加入七条规则后，它能否更可靠地回答新的问题。下一阶段最有价值的结果，是拿到可复查的新科学答案，以及指导包究竟改变了哪些结论。

## 对 Pro 回复的判断

Pro 对开发结果的纠正应采纳。模型错误、规则指导的过度推广、确定性检查的职责和程序破坏交付，必须分别归因。开发题答错是可以测量的结果；错误的交付程序则需要修好，否则评分会混入程序覆盖答案的影响。

Pro 建议结束本批开发也合理。纳米盘和 T4L 已用于开发和审阅，第三次同题运行继续消耗时间，却不能提供新的泛化证据。结束这批实验以后，项目仍可以准备下一项科学比较。没有必要把每个动作都重新变成一轮方案审查。

## 现在做什么，哪些工作不值得做

| 工作 | 是否必要 | 为什么，以及结束标准 |
|---|---|---|

| 修正报告并盘点已有答案 | 必要，本次完成 | 确认已有自主分析、数值错误、扩大解释和交付损失。完整保留历史版本 |
| 新增数值正确性规则挽救 C | 目前不做 | 本版 C 只检查拟合数据重用；一个数组错误不足以推出新的通用科学规则 |
| 升级模型或再跑开发题 | 目前不做 | Luna 已显示基础分析能力，同题修订额度已用完 |

| 增加复杂 harness | 等真实跨来源失败再决定 | 当前已有自主阅读、工具调用、执行反馈和答案保存。新增功能应解决重复发生的具体问题，并单独衡量成本与收益 |

## 第一步，把现有证据交给科学评审

本次已经修正开发报告，并准备一份[领域核对简报](DOMAIN_REVIEW_BRIEF_ZH.md)。它只请领域人员核对三项会影响评分的边界。

- 正确算出残差和超限记录，最多能支持哪一级相容性判断。
- 什么条件下平均观测能够约束状态比例，哪些结论还需要物理时间依据。
- 如何分别评价结构覆盖、模型估计的比例和实验观测预测。

纳米盘的 1.915、47/292 和 8/40 是有代码支持的数字；整体相容性与唯一性需要另外判断。这个例子用来校准评分方式，继续作为暴露的开发资料，不进入新实验成绩。评审不需要重新审 33 条规则，也不需要通读所有项目日志。

这一工作结束时，正确的计算、可接受的解释和过度结论有明确区分。领域人员尚未落实；简报已可以直接转交，当前未代发消息。

## 第二步，准备四个真正适合研究的新来源

保持原计划的四个来源组。每组是一个完整科学问题，不能把同一论文拆成四题来增加样本数。分别覆盖资料足够直接比较、需要既有工具补算、结构到实验信号需要前向模型、只能解决部分问题这四种情况。

一个合适的问题可以问，同一体系的两类观测是否支持同一种结构解释，以及资料能排除哪些其他解释。前向模型指把结构变成仪器实际测量的信号的计算关系。是否需要重加权、距离计算或其他分析，由受测 Agent 根据材料判断；题面不提供预定工具或步骤。

构造者依次完成以下工作。

1. 按已有二十题、规则来源、近期文献分析及 Pro 讨论记录排除暴露来源；共享主要数据的论文算同一组。这里的“新”指项目未用其设计或修复规则，无法保证模型预训练从未见过论文。
2. 下载原文、补充材料及实际数据，优先复用匹配的 Markdown。核对对象、条件、数据列和统计单位，不给受测 Agent 提供人工结论摘要。
3. 先确认现有工具能够处理所需资料。构造者可以计算参考值，但参考代码、选择理由和预期结果留在隐藏区，三组只得到相同原始工作区和工具。
4. 写一页评分依据，列出可回答内容、过强结论、关键证据、合理替代分析和真正未解决的部分。让领域评审确认这些边界后再运行。

预计需要一至两个工作日，取决于数据可下载性和评审时间。缺主数据、条件无法辨认或现有工具根本无法处理的候选，在看任何 Agent 答复之前换掉并记原因。不能因为预计普通 Agent 会答得好而换题。

四组中应自然包含拟合与后续验证的科学问题，给现有 C 检查合理的适用机会。不得人为往模型答案里植入错误，也不能要求模型故意宣称独立验证。若正式结果没有出现可匹配的目标主张，就如实报告 C 的适用机会不足。

## 第三步，先冻结，再一次性运行小型比较

继续采用同一模型、同一推理档位、相同源文件和完整工具权限。A 使用普通工具 Agent，B 增加现有七条指导，C 再启用现有拟合重用检查。三组都能自行阅读、编写代码、看图、选择分析和根据反馈修正。

规则、题面、工具说明、提交协议、评分依据、token 与时间上限、停止方式一起冻结。提交修复作为三组共有的维护变化，记录在新的版本中。普通确认文字不替换已有答案；明确有效的较短答案可以替换。程序不挑选科学上最好的一版。

按照原方案运行 **4 个来源 × 3 组 × 2 次独立会话，共 24 份答案**。两次重复帮助观察波动，仍只是小样本决策试验。每次会话保持新上下文，受测 Agent 看不到开发对话、隐藏评分依据或其他组答复。

模型算错、选择不佳或按共同预算提前结束，都保存为结果。若发生真正的工具故障或资料损坏，按冻结的故障处理约定记录，不临时提示模型如何分析。发现需要改提示、规则或科学工具时，该结果保留，修订进入下一版本和新的资料。

本轮没有启动这 24 份运行。开始条件是四组资料及评分依据可用、领域边界获确认、共同程序冻结、模型与预算再次写明。已知科学错误没有被列为禁止实验的条件。

## 第四步，按回答内容判断增益

先盲评，再揭示组别。每份答案分别记录正确且有用的回答、关键过度结论、不必要弃权、关键证据使用、分析选择，以及模型和人工成本。评审看实际终稿与允许审查的执行记录，不按语言漂亮程度或规则名称评分。

评分中的基本单位是一项具体可核对的科学判断。例如，“某些具名距离超过实验上界”与“整套 ensemble 不成立”分别计量。这样既保留正确计算的价值，也能识别把局部结果扩展得过远的错误。未完成计算造成的无答案与有依据的部分回答也分开记录。

原方案的两位独立评分者在揭示组别前完成评分，分歧单列后处理。领域人员先确认评分依据，主要投入放在边界和争议上；具体数值与引用可以用保存记录核查。不能用未经领域核对的模型评分宣称科学正确率。

先比较 B 与 A，判断这份显式科学指导包的增量。由于 B 多了一份整理后的指导，这项实验不能单独证明表格格式优于同长度的其他写法，当前也不需要为此增加第四组。再比较 C 与 B，判断有限强制检查是否真的改正错误。

保留原计划的投入门槛。至少两个新来源出现预先定义的重要正确回答增加或关键错误减少，且过度结论、不必要弃权没有相应恶化，才继续以 Rules Table 为主要研究方向。相关计数口径必须在运行前固定，不能看结果再挑有利指标。

C 只有在真实适用主张上改正错误，才计直接收益。若只增加日志，没有提高答案质量，就简化它。约 25% 人工纠正时间节省只能在本轮实际计时后评价，当前没有这项证据。四个来源的门槛用于决定投入，不等同统计显著性或通用正确率。

## 何时再发展 harness

目前的执行环境已经让模型完成读取、计算、反馈与交付，具备一个小型 scientific harness 的基本功能。下一阶段可以直接使用它。答案保存修复是共同程序维护，不能计成 Rules 的科学增益。

如果多个新来源都出现同一种输入对应或工具结果使用问题，再提出一项有明确职责的功能，说明它能修正哪类可观察错误。所有组都需要的通用功能先加入共同执行环境；只有来自规则的额外约束进入 C。每次只检验一个增量，避免工具、提示、知识与程序同时改变后无法归因。

最终交付是一张逐来源对照表和每个问题的完整答案。它应能让研究者看清目前支持什么、证据是什么、哪里仍未解决，以及保留 Rules Engine、仅保留指导表、或采用普通 Agent 加成熟工具，哪个选择更值得继续。

## 执行与检查预算

| 工作批次 | 检查及次数 | 何时结束 |
|---|---|---|
| 本次报告与保存修复 | 一次提交处理离线检查，使用保存事件及协议输入；一次合并文字、引用与链接检查；不新跑模型或科学拟合 | 观察到的覆盖缺陷关闭，历史证据未被改写，计划可供判断 |
| 新来源准备，尚未开始 | 每个来源一次资料及可执行性检查，共四次；只在实际缺陷修复后重查受影响项；一轮领域边界审阅 | 四份资料包和四页评分依据可冻结 |
| 新实验，尚未开始 | 一次共同运行前检查；24 次会话；两位评分者各一次完整盲评 | 输出、失败和成本全部收回，不中途调规则 |

本次不做独立 Agent 审阅或重复全文测试；普通文档和代码编辑不计算哈希。后续冻结输入每批只做一次身份记录，传输或异常覆盖风险出现时才追加检查。执行记录区分本次已完成的维护与尚未开始的新研究。
