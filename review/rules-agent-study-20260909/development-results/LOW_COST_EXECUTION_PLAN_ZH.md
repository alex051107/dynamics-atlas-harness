# Dynamics Atlas：先用低价模型的逐步执行计划

**版本日期：2026 年 9 月 9 日。状态：供负责人采用的研究计划，尚未执行。**

本计划替代上一版“默认使用旗舰模型、直接准备完整正式比较”的安排。保留三组比较和 Agent 自主分析能力，改为先在两个已暴露案例上进行低成本开发试跑，确认基础能力后才准备新来源。此前审阅指出的实验归因、规则误判、评分和停止条件问题，一并在本版修正。

本文件交给开发者和研究负责人，**不得整体放进被测 Agent 的工作区**。里面的组别设计、开发历史和评分说明不是被测 Agent 的任务资料。

## 先看这一页

**建议先用 GPT-5.6 Luna，推理设置 medium。够用就不换；确有基本能力不足，才考虑一次事先允许的模型升级。** 低价模型是否够用是本轮要观察的事实，不能预先认定科学分析很简单，也不能预先认定一定需要旗舰模型。

原始目标没有变化：帮助研究者从异质蛋白构象和动力学资料中得到有用、有依据、可复核且不过度的回答。Rules Table 和确定性检查只是待检验的辅助方式，不是必须证明成功的结论。[P1]

本轮分成两段：

- **开发段：** 两个已暴露案例，三组各一次，共六份完整答复。必要时只作一次合并修订，再跑六份。先判断 Agent 是否真的会自主读取资料、执行科学分析、使用结果，而不是只会解释开发者已经算好的答案。
- **前瞻比较段：** 开发条件满足、经费和领域评分人员到位后，再准备四个未参与本轮开发的新来源。每个来源三组各运行两次，共二十四份答复。

**通常六份开发答复后就能决定是否值得继续准备正式比较。不是一开始就花钱跑完，也不是每答错一次就回去修改。**

默认模型调用预算建议为 **10 美元总上限**。只有负责人事先允许条件升级时，才启用本文的 Terra 分支，将全轮模型预算上限改为 **30 美元**。这两个金额是建议的消费上限，不是已经授权或发生的开支；人工整理、科学计算和评审成本另记。

本轮不恢复 Q15 修复，不扩大旧规则库，不重新完成纳米盘论文，不启动新 MD，不建设新的多 Agent、数据库、知识图或调度框架。

## 1. 这次要回答什么

首先回答：**一个便宜、能够使用工具的模型，能否完成本阶段所需的基础科学分析？**

在它能够开展真实分析的前提下，比较三个条件：

| 组别 | 实际配置 | 要观察的区别 |
|---|---|---|
| A：Agent only | 自主 Agent、原始资料、共同工具、共同输出格式 | 当前条件下的基本表现 |
| B：Agent + Rules Table | A 的全部能力，加同一份七条科学指导及其来源 | B−A：这份指导包的增量 |
| C：Agent + Table + 有限检查 | B 的全部能力，加最多两项明确的确定性检查、反馈和结论级标记 | C−B：这套有限执行政策的增量 |

这里的 Agent 必须自己安排阅读和分析，不是先由开发者决定工具和步骤，再让模型填参数。数学求解、矩阵运算和绘图由成熟程序执行；模型负责决定是否需要这些分析、正确使用输入、读取结果并回答问题。

**B−A 不单独证明“表格这种形式”有效。** 它包括知识整理、提醒和阅读负担的共同效果。**C−B 也不证明完整 Rules Engine 有效。** 它只评价本次具体检查与反馈政策。三组共享同一个基础 harness，因此本轮不能评价整个 harness 相对于没有 harness 的价值。[P2]

## 2. 模型、价格与预算

### 2.1 默认模型与唯一的候选升级

以下价格为 2026 年 9 月 9 日核对到的 OpenAI 官方标准、短上下文文本单价。实际运行必须核对所用端点、缓存和工具计费。[W1–W3]

| 用途 | 模型 | 推理设置 | 每百万输入 token | 每百万输出 token |
|---|---|---|---:|---:|
| 默认低价模型 | `gpt-5.6-luna` | `medium` | $0.20 | $1.20 |
| 唯一候选升级，不默认调用 | `gpt-5.6-terra` | `medium` | $2.00 | $12.00 |

官方文档列明 Luna 支持图像输入、函数调用和结构化输出，medium 是其支持的推理设置。这只确认接口能力，不确认它已经能够正确分析本项目的科学资料。[W1]

优先沿用已经可靠的同一家模型服务和工具入口。若现有网关可以稳定提供所选模型、图像、完整工具往返和实际用量，不为这次试验迁移供应商。若使用第三方网关，按该端点实际单价重算费用，记录实际提供者，禁止自动切换后端。不能把历史使用过的 API key 当成本轮已授权消费。

若所选模型在当前账户不可用，先报告具体原因；只允许在开发前统一选择已批准的替代，不在正式运行中随机换模型。

### 2.2 不靠削弱 Agent 来省钱

默认保留上一版的单次资源空间：

| 限制 | 本版默认 |
|---|---|
| 累计输入 | 每份完整答复最多 160,000 token；反复发送的上下文、工具返回、可计量的图像输入都计入 |
| 累计输出 | 最多 30,000 token；包括服务端计费的推理 token，不要求暴露私有思维过程 |
| 工具调用 | 最多 40 次；这不是必须用满的目标 |
| 墙钟 | 最多 25 分钟，包含阅读、计算、自查和最终提交 |
| 单次科学计算 | 默认 90 秒、2 CPU、4 GB；无新 GPU 任务、无新 MD |
| 提交后修订 | 各组均最多一次，在同一总预算中完成 |
| 外部访问 | 科学工具离线；模型请求由受信任启动端发送 |

“六份答复”不是六次 HTTP 请求。每份答复内部可以有多轮模型与工具交互，费用必须按这些交互累计。

不默认使用 max，也不为省钱关闭推理、隐藏图像、只给 A 很小的上下文，或删掉必要工具。大文件可分页和按 Agent 选择检索；三组使用同样的截断和分页方式。不能由额外强模型免费压缩资料、提示关键页或替便宜模型写最后答案。

### 2.3 本轮可能花多少钱

按标准未缓存文本价格算，Luna 用满一次上述 token 上限约为：

`160,000 × $0.20 / 1,000,000 + 30,000 × $1.20 / 1,000,000 = $0.068`。

六份开发答复约 $0.408；二十四份正式答复约 $1.632；三十六份正常答复约 $2.448。这是相应 token 和价格条件下的算术，不是实际账单保证。

缓存写入、图像 token 换算、服务档位、网关加价及额外付费工具均须按实际服务计算。官方 Luna 页面列有缓存写入加价；即使把本预算全部输入按 1.25 倍未缓存输入价作保守计算，三十六份的文本费用约 $2.736。[W1–W3]

因此，**默认 10 美元上限是给计量差异、少量连接检查和失败尝试留下余量，不是要求花满 10 美元。** 不启用收费搜索、托管代码环境或其他付费服务，除非它们已纳入同一授权和费用估计；优先使用现有本地工具。

若第一批六份用 Luna，唯一修订批及二十四份正式答复统一改用 Terra，标准未缓存估计约为 $20.808；按上述缓存写入保守口径约 $23.256。另有少量连接和基础设施失败成本，所以可选升级分支建议采用 **30 美元全轮上限**。

上述费用估算只覆盖被测 Agent 的规定运行。开发者使用的订阅、资料整理和人工评审另列成本；整理者或第二意见额外调用收费 API，须事先计入本轮总上限，不能因属于“准备工作”而免记账。

只批准低价分支时，遇到需要升级的情况就停止汇报，不能自动花旗舰模型的钱。付款授权可以一次说明“只允许 Luna”或“满足本文条件时允许一次 Terra 升级”，不需要逐题找 Pro 批准。

启动端在每次请求前检查剩余累计 token、请求最大输出与可用金额；费用不清楚的请求先对账，不盲目重试。只有服务确实提供硬限制，才能称为服务端硬上限；普通预算告警不能当硬停止。正式运行前预留整批或对称区块的费用，不因 C 消费较多就只减少 C 的后续样本。

## 3. Step 1：先确认范围和最小运行入口

**由开发者完成，先不选择正式测试论文。**

阅读当前计划、上一轮研究审阅及项目状态，确认旧任务仍暂停。只核对与这次运行有关的入口和权限，不把整理全部历史文件变成新阶段。

在已有运行设施中确认一个真实循环：

`Agent 选择阅读或计算 → 工具执行 → 完整结果返回 Agent → Agent 决定继续、修正或提交`。

单一 Agent 加现成文件、Python 和图像工具即可。只允许作必要的小适配，不新增多 Agent、任务图引擎或通用算子注册层。旧的 Profiler/Planner 提案模块不是这个能力已经实现的证明。[P2、P3]

三组共同拥有文件列举和读取、全文检索、PDF 页面渲染和图像查看、Python/NumPy/SciPy、绘图及所需的已建立科学方法。Agent 可以写短分析代码调用现成方法；不能安装任意包、另造新科学方法、修改评分程序或调用其他模型。

工具说明只写输入、输出、方法前提和错误，不能写“遇到这题必须选哪个算子”。不能保留按题号安排分析、唯一合法行动卡或预写科学答案的后台分支。

实际模型入口按其官方工具协议实现完整往返；函数调用是模型提出动作、外部程序执行并返回结果，不是模型写出函数名就算执行完成。[W4]

**完成标准：** 工具返回确实回到同一分析会话；模型能够看图、运行代码和检查结果。用非科学示例核对图像及工具接口即可，不据此宣称科学能力通过。

**停止条件：** 半天左右仍无法在现有设施上提供这段基础能力，就交付具体技术缺口，不先伪造一个固定科学流程开始比较。

## 4. Step 2：把隔离和公平做成实际条件

每次运行只挂载当前公开来源、同一工具包、当前组允许的指导文件和空白输出目录。被测 Agent 及其 Python 进程不能读取项目根目录、AGENTS.md、旧答复、本计划、其他运行目录或隐藏评分材料。模型密钥留在启动端，不挂入科学工作区。

用现有沙箱或容器限制文件和网络；检查工作区外文件及符号链接不能被读取。新聊天窗口、worktree 或一句“不要看答案”不等于隔离。

原始论文和 SI 保留作者本来的结论。三组不读取本项目的审阅摘要、会议结论、带答案笔记或逐项参考结果。不能只给某一组挑好的关键页。

若需要公共事实索引，三组完全相同，只包含有原文位置的事实，不附“所以应该弃权”或正确行动。C 可读取的来源角色与计算记录，A/B 也可读取。整理这些事实的人工成本单独记录。

先完成一次针对本版的隔离、工具、计量和基本格式检查。发现明确缺陷可以在开发批前修正，不需要重复整套旧项目测试，也不为检查次数和文件数量设进展目标。

**完成标准：** 除七条指导和具名执行政策外，三组能获得相同资料、方法和正常反馈。当前配置、程序版本与输入清单能被记录和复查。

## 5. Step 3：固定三组处理，先把两项检查说清楚

### 5.1 共同答复要求

三组都交付一份可读中文答案，包含：具体结论及条件、实际使用的来源、实际完成的计算、未解决部分，以及确有必要的下一步。没有必要新增分析时，允许直接回答。

为检查具体主张，使用相同的小结论表或现有 JSON 表达。最少记录每条主张的文字、类型（结论／限制／建议）、科学量、证据位置；涉及模型验证时，明确被评价的结果与使用的观测。作者报告和本次计算是来源身份，拟合／条件预测／独立验证是证据角色，两者分开。字段不适用或无法确定时允许留空或 unknown。

这套共同格式本身会提醒 A 注意来源和科学层次。A 的准确名称是“有共同证据格式、没有额外七条指导的 Agent”。不为了让 B 获胜而削弱 A；合法 JSON 和更多字段也不给科学分。

### 5.2 B 与 C 读取同一份指导

采用附录 A 的七条短指导，保留原七个主题，修正候选池范围和“未完成不等于不可辨识”的表述。条目不是必须依次执行的流程，也不要求每题都逐条回复。

引用指向三组都可访问的原始方法资料。B/C 的增量是明确整理的指导；C 不从后台获得新的科学知识、阈值或隐藏答案。

### 5.3 第一项检查：同一次分析中的拟合与独立验证冲突

只有下列对应都明确时才返回冲突：当前主张声称某组观测独立验证某个具名结果；公开事实或真实运行记录显示，同一组观测参与该结果的拟合。

检查必须绑定**被评价结果、观测子集及对应分析**，不能只看整个文件以前是否参与过其他拟合。同一文件的不同子集和不同分析结果，不能一律合并。

事实或对应不足时，记为“不能由这项检查核对”，不推定独立，也不推定科学结论错误。只有模型自己说“没用于拟合”、没有可核查记录，不算已经验证该事实。

反馈只指出具名冲突和公共证据位置，不给正确最终答案。候选生成、早期方法选择或历史信息的影响仍需 Agent 解释；本检查通过不等于整个研究独立。

### 5.4 第二项检查：把无序静态集合直接当作新速率估计

只核对明确肯定的、本次新作出的物理转换速率估计，且它声明的证据与方法记录明确只有无序静态构象，没有额外动力学模型、时间标定或速率观测依据。

“当前不能确定速率”“建议补测速率”、转述作者速率、条件性的动力学模型预测，都不能因为含有“速率”二字而被拦截。是否可执行取决于明确的主张类型和分析记录，不使用关键词扫描充当科学判断。

资料关系、方法依据或文本意义不明时，不自动否决。反馈限于“当前列举的依据不足以支持这项新速率估计，请核对是否存在额外动力学依据”，不声称所有基于结构的理论速率预测都不合法。

### 5.5 反馈与最终展示

A/B/C 都有正常工具错误反馈和预算内自查能力。第一次提交后，各组都得到同样的可选修订机会，即使格式正确也可使用。C 另外收到实际检查冲突。修订包含在原有 token 与时间预算中，不额外赠送 C 调用次数。

C 最多进行一次这样的提交后反馈；修订后可以再运行同一检查。仍有明确冲突时，只对相关主张标为未获支持或暂不作为结论展示，保留其他答案，不默默删除整段。保存初稿、反馈、修订稿和最终展示稿。

没有检查机会、B 本来正确、C 初稿因预期检查而更谨慎、C 纠正了错误、C 仅限制了错误展示、C 误拦正确内容，都分别记录。C−B 是整套政策的效果，不能全部归因于后台函数。

**完成标准：** 用不涉及正式来源的小例子检查允许、冲突、不明确和局部答案保留；不把这些例子当科学测试样本。

**范围控制：** 在现有开发工时内若一项检查仍不能清晰实现，就在六份开发答复前将其固定为观察性项目，C 只执行另一项，并更名说明实际范围。两项都无法实现时，只能交付 A/B 开发结果，不能宣称完成 C 比较。不得为维持“两项”字样增加一个隐藏 LLM 审判器。

## 6. Step 4：准备两个开发题，不把旧答案交给 Agent

这两个来源均已反复暴露，永远不计入新来源效果。

**开发题一：Q05 纳米盘。** 提供作者原文、必要方法与已发布矩阵／实验文件、共同科学工具。问题要求 Agent 利用给定数据实际核对至少一项影响跨观测判断的比较，但不指定 SAXS-only、θ、目标数值或唯一方法。附录 B 提供可用问题模板。

旧权重审计、SAXS-only 报告和独立复核作为开发者评价参考保存，不进入被测工作区。原始论文自带的结果正常保留。Agent 可以在沙箱中自主选用成熟方法作必要计算，开发者不为“把 Q05 做完整”另加联合优化、参数扫描或形状任务。沙箱试验也不回写旧科学结果。

**开发题二：Bhakat 的 T4L 主文与 SI。** 提供完整主文和 SI，允许 Agent 自主查看任何页面。它可根据已有图表直接回答，不要求重跑轨迹或重建 MSM。

这两题分别检查计算与资料判断。工具运行只是证据之一；需要核对 Agent 是否使用了结果，以及有没有保留正确的正面判断。博客提供的是观测可区分性的概念，不是规则有效性的证明；T4L 提供覆盖、权重和实验预测不同层次的实例，不作为完整物理真值。[S1–S3]

复用现有开发评分记录，补齐本次问题需要的评价条件；不要重写整篇论文分析。合理的替代方法可以获得同样评价，不把开发者熟悉的唯一脚本设为正确答案。

## 7. Step 5：先用 Luna 跑六份开发答复

Q05 和 T4L 各运行 A/B/C 一次。用事先确定的顺序运行，六次均为新会话、独立目录，不共享上一组的答案。先使用同一个 `gpt-5.6-luna`、medium 及共同资源设置。

开发者只能处理进程、配额和文件访问，不能在中途指出“你漏了这张图”“下一步应该拟合”。Agent 自己修正代码属于它的能力，开发者帮它补步骤则是人工介入，必须记录，不能当独立产出。

六份完成后一起查看，不依据第一份答案立即改 B 的规则。到预算或时间上限，保存当前成果和未完成部分，不重试到成功。

本阶段先判断四件具体事情：

1. 工具是否真的执行，返回结果是否进入模型，而不是打印一个计划。
2. Q05 是否至少有一条路径自行选择并完成相关计算，把结果用在一个重要科学答案上。
3. T4L 是否至少有一条路径依据实际读取的正文和必要图像，给出重要正面结论和相关限制。
4. 失败主要在运行装置、模型的资料／方法理解，还是指导与检查误导。

**不要求 A 两题全对，也不以 B−A 越大越好来选模型。** A 犯错而 B 能完成，可能就是值得测量的指导作用。C、B 的失败也保留，不因处理组不好看而宣布便宜模型不合格。

这是最低的可分析性判断，不是可靠率验收。报告至少列出一个 Agent 真正完成的科学判断和一个实际困难，而不只报“工具调用成功率”。

## 8. Step 6：只允许一次合并调整，然后固定下来

按六份开发记录，采用下列对应处理：

| 看到的情况 | 下一步 |
|---|---|
| 能开展真实分析，也有有依据的正面答案；仍有普通科学错误 | 继续使用 Luna。不要求所有错误修到零 |
| 资料、工具、图像或返回接口有一个明确共同缺陷 | 用唯一一次调整修复共同缺陷，保持三组公平；再完整跑六份 |
| 指导措辞或检查器存在一个具体、通用的误导或误拦原因 | 用唯一一次调整修正或收窄该内容，再完整跑六份；不按蛋白添加答案分支 |
| 装置正常，但三组整体仍无法形成所需分析；主要卡在基础理解或连续工具使用 | 仅在事先允许时，利用唯一一次调整统一改为 Terra medium，再完整跑六份 |
| 同时存在明确接口缺陷和模型问题 | 可以合并在同一次调整中，但不把前后差异单独归因于模型升级 |
| 调整后仍不能开展可评价的科学分析 | 结束在开发报告，不进入四来源正式比较 |

模型升级不能因为 Rules 的差异“不够大”，也不能因为 A 太强而换一个更弱模型。若 Luna 已经可用，禁止再跑多个便宜模型挑出最有利于假设的一个。

模型或接口调整只允许发生在开发阶段。全轮正常开发答复最多十二份，不在十二份之外再追加“几个小诊断”。价格核对、短连接检查等不算科学答复，但所有费用与请求仍计入账本。

若第二批统一使用 Terra，正式阶段三组也统一使用 Terra；第一批 Luna 成绩只保留为开发信息，不与 Terra 合并。便宜模型失败，只说明该配置下未满足当前任务需要，不等于整个 harness 方向无价值。

如果第一次没有需要调整的事项，不为凑满十二份重跑。冻结模型、推理设置、工具、三组提示、七条指导、实际执行的检查、预算、输出形式和通用评分逻辑。

**阶段结束应交付一句明确结论：**“保持低价模型进入下一段”“在允许范围内统一升级后进入下一段”，或“停在开发，原因是……”。不默认请求下一轮 Pro 获批。

## 9. Step 7：之后才准备四个新来源和评分依据

由没有继承开发答复上下文的整理者，按预先固定标准准备来源。可以用工具帮助整理，但科学评分依据仍需领域人员确认。不能让同一个有隐藏答案的上下文一边调系统一边制作正式答复。

四个来源分别覆盖：可直接从证据给出正面比较；需要现成方法补算；跨观测或结构到信号比较；局部可答但更强解释仍未解决。至少两个主问题应需要有内容的计算或多步证据结合，不把全部题目缩成字段填写。

沿用项目层面的开发排除范围：原 20 题及共享数据、规则来源、Q05/Q15、已暴露的 T4L、博客和实质参与现有分析的来源不能冒充新测试。相同原始轨迹、实验样品或预测矩阵的再分析归为同一来源。不能保证基础模型预训练从未见过论文。

每类最多考察两个候选，按预先记录的顺序选择符合资料、任务和共同工具范围的一份。不得根据 Agent 输出挑题。备用只能在正式运行前因资料或题目无效而使用，不能在运行后替换难题。

**来源准入不以七条规则是否足够作标准。** 现成资料与共同工具能够支持任务，但规则遗漏或误导的情况仍应保留。复杂到必须新增 MD、大规模重建或新的科学方法的题，可以不属于这一轮。

隐藏评分页为每题写清 2–4 个实质性的可回答结论、重要程度、证据位置、需要时的单位与数值容差、合理替代方法、严重错误，以及真正未解决的部分。

隐藏的是参考答案和评分，不是任务语义。实质性相容阈值、观测定义或必须满足的交付要求若不在来源和公开问题里，不能藏进评分页处罚 Agent。评价应依据证据，允许原作者的解释被有依据地质疑。

两类不同“未解”要分开：数据与模型下确实无法区分的解释，与当前分析尚未完成的部分。不能奖励把工具没跑完写成不可辨识性证明。

在看正式输出之前，记录两个检查各有多少潜在适用来源。适用机会不足两个来源时，明确本轮对执行检查只能形成探索性描述；不靠后补诱导题取得成功。

领域专家确认这四页，不需要先复现四篇论文全部数值。两位评分人员中至少一位应具有相关方法经验。若人员未落实，就停在开发交付；不能把模型互相打分改称领域验证。

## 10. Step 8：固定后运行二十四份前瞻答复

运行单位是来源 × 组别 × 重复：4 × 3 × 2 = 24。两个重复不等于两份新论文。

每个来源的每个重复区块包括 A/B/C 三个新会话，事先打乱组别顺序并交错来源。每组使用同一已经选定的模型，不允许 A 用 Luna、C 用 Terra，也不允许某组失败后调用强模型兜底。

模型能读取全部公开材料，但不能读隐藏要点、其他运行答案或本计划。运行中只监控实际请求、工具和费用，不边评分边改提示，不提醒遗漏，不因为前十二份结果好或坏而提前选结论。

模型访问的原始信息、调用参数、实际工具输出、答案、错误和费用原样保存。若服务只提供别名而没有可固定快照，如实记录这个限制及返回标识；不把同一别名承诺成后台版本永远相同。

一次正式错误可能是有用研究结果。规则误导、工具选择错误、自己写的代码出错、检查器误拦、时间耗尽和没有形成答案，都不能因为“需要修复”而退出评分。

真正的实验实施问题，例如某组少挂文件、泄露答案、装错模型或严重服务故障，应与系统失败区分。整轮最多允许两次符合事先政策的基础设施替代尝试，保留原尝试；不得把科学答错改名为服务错误重跑。

发生会破坏比较的资料、模型或组别版本变化时，停止受影响区块并报告，不把修复前后的结果拼成单一冻结实验。若参考评分本身有错误，由未看组别的评审处理对应单元，对三组一致应用。

## 11. Step 9：先评分，再看组别

将答复改成随机编号，去掉组名和执行器标识，保留实际科学文字、引用及结果。不能为盲评润色、删除错误或改写弃权。C 的科学限制文字也不能为伪装组别而更改；风格可能破盲，按实际情况记录。

两位评审先独立评分，再讨论分歧、锁定分数，最后揭示 A/B/C。先锁定答案评价，再核对可能暴露 C 的执行轨迹。

主指标是**有依据的正确答案覆盖**：每题预先列出的可回答单元，只有结论正确且被实际证据支持才得分；需要当前计算的单元必须有可核对执行。格式正确、引用多、恰好猜对数值和复述作者结论都不能替代这一条件。

同时分别报告：严重科学错误、无必要弃权、纯遗漏、方法选择与实际执行情况、模型及计算成本、人工准备与维护投入。严重错误包括方向、单位、对象和证据角色错误，不只包括夸大的机制结论。不要将这些合成一个可以互相抵消的总分。

已有结果足以回答一部分时，整题拒绝应丢失对应可答分数；明确回答该部分、保留另一部分不确定性，则正常得分。纯遗漏不自动叫弃权。

先逐来源、逐重复比较 B−A 与 C−B，再对同一来源的两次结果平均，最后四来源等权。不能让观测点多、帧多或评分单元多的论文占更大权重。没有最终答案的运行保留在计划分母中，实际可核对的部分按预定交付口径评价；基础设施缺失另列。

C 另报：适用机会、可核对情况、真实冲突、误拦截、反馈后模型纠错，以及仅发生展示限制的情况。被拦截的错误原稿不销毁；风险控制收益与补出科学答案的收益分开。不给“没触发”自动记成功。

人类实际节省时间本轮默认未测。评分时间不是平常分析时间，token 少也不等于节省人工。人工费用可能远高于模型费用，必须如实列出，不能用低价模型掩盖大量手工准入。

## 12. Step 10：作出投入决定，并结束本轮

下面是预先选择的管理阈值，不是统计显著性或普遍有效性标准。

### 12.1 继续研究这份指导包的条件

B 相对 A，至少在两个有效新来源上出现实质改善。改善可以是两次平均多回答一个预先标为重要、且有证据的单元，两个区块方向不为负；也可以是前组出现的严重错误在后组两次都没有出现，同时该来源的正确答案覆盖不下降。

还必须同时满足：四来源等权的有依据答案覆盖不下降；严重错误的答复数量不增加；无必要弃权的来源等权平均增加不超过 0.05；不得在某一来源两次都丢掉原本可以回答的重要内容。各来源的损失与收益都列出，不能只讲有利案例。

达到这些条件，只支持继续研究**这份指导、这个模型和当前任务范围**。不宣传七条规则普遍有效，更不说明昂贵模型一定有同样收益。

### 12.2 继续研究有限检查的条件

C 相对 B，至少两个具有真实适用机会的来源出现可归因的错误减少或正确纠正，且整体与各重要局部答案没有因拦截而丢失，严重错误与弃权满足上述限制。

分别报告整体政策的配对结果与保存轨迹中可见的直接纠错。C 初稿已正确可以属于政策表现，但没有直接证据时不能说是检查函数把它改对。只有展示限制而无推理改善时，可描述为窄的风险控制用途，不宣称科学分析能力提高。

### 12.3 最终选择

| 结果 | 本轮之后怎样做 |
|---|---|
| B 有明确增益，C 没有额外收益 | 保留可读指导和简单 Agent；停止扩建确定性执行层 |
| B 和 C 都有明确增益 | 保留当前七条指导和确有收益的窄检查；不自动扩大规则库 |
| B 无增益，C 有收益 | 只保留受支持的窄用途；以后需要新来源对照才能判断是否还需要整张 Table |
| A 已经很好，三组相近 | 使用简单 Agent；本轮没有支持额外规则成本，不人为制造更难题重测 |
| 三组都很弱但实验有效 | 记录所选配置的低水平表现；停止宣称 Rules 增益，不转化为完整 harness 无价值 |
| 资料、环境或评分使比较无法成立 | 交付已有有效结果及具体不足，不把研究未完成写成 Rules 科学无效 |

效果不明确时，不再自动加两题、换模型或微调规则。四来源不足以证明普遍无效，但足以允许负责人暂时停止为没有实证收益的额外层投入。

后续若继续研究 harness，只选实际记录暴露的一项能力，例如已获得结果的保存与使用、根据新计算调整行动，或局部失败后的有效答案保留。固定其余条件，再用新来源检验。不能一次改五项能力后把收益全部算给 Rules。

只维护一份协议、同一份指导文本、公共／隐藏案例资料、实际运行输出，以及最终结果报告。沿用现有目录和状态记录，不为本轮新增文档治理系统。

每次汇报围绕四件事：**Agent 实际得到了什么科学答案；它自己完成了哪些分析；哪些部分仍由人准备；花费多少以及还缺什么才能作出本阶段决定。** 不以测试数量、JSON 数量或“Pro 已审”代替这些内容。

## 附录 A：B/C 共同读取的七条科学指导

以下是本版拟采用的整理文本，保留旧计划的七个主题并吸收审阅修正，不冒充原作者原话。可在唯一开发修订中作一次有理由的调整。它们是适用时使用的指导，不是七个必须顺序执行的步骤。[P2]

**1．先明确要回答的量。** 区分结构覆盖、模型权重、观测预测、物理时间性质和功能解释。现有证据支持哪一部分，就回答哪一部分；不要从某类结构存在直接推出真实占比、交换速率或唯一机制。依据：博客的 ensemble resolution 讨论及 T4L 主文／SI。[S1–S3]

**2．比较前说明对象和条件。** 核对构建体、突变、配体、组成、环境、标签和制备。存在差异时指出当前比较依赖什么假设；不把不同物理对象无说明合并，也不因一处未明就取消其他可回答部分。依据：博客关于目标分布和源分布的区别；具体方法以任务原文为准。[S1]

**3．识别测量和处理后的量。** 看清单位、平均、筛选及反演。两个字段都叫距离不等于测量同一对象；一个平均量或处理后图像不等于完整分子分布。必要时返回更接近原观测的资料。依据：博客的测量与后处理两节。[S1]

**4．区分采样、独立单位和时间证据。** 大量相关帧不是等量独立实验；静态候选出现次数不是自动校准的平衡概率；无序结构本身不提供转换速率。模型条件下的估计可以报告，但须写出条件，不能用计算完成代替采样和动力学诊断。依据：博客与 T4L 的 MD/MSM 方法、SI 诊断。[S1–S3]

**5．说明证据对具体结果的角色。** 区分拟合、校准、候选生成、方法选择和后续检验，绑定所评价的结果与观测子集。参与该结果拟合的观测不能作为它的独立验证；未参与本次拟合也不自动证明整个研究独立。依据：Bengtsen 原文设计及来源历史。[S4]

**6．核对候选范围和结构到信号的关系。** 说明前向模型、探针、非线性平均、误差及参数范围。平均信号通常不能由平均结构直接替代；重新分配已有候选权重不会产生缺失构象。比较结果始终受候选池和观测模型约束。依据：博客与 BME／nanodisc 方法。[S1、S4]

**7．区分已排除、仍可行与尚未完成。** 一个好拟合不是唯一真分布；某部分未解决不取消其他正确答案。确实不可分、精度不足、采样缺失和当前计算没完成不是同一个问题。只有存在具体信息价值时才提出下一步，不以更多分析本身当进步。依据：博客的 ensemble resolution 及 T4L 多层结果。[S1–S3]
