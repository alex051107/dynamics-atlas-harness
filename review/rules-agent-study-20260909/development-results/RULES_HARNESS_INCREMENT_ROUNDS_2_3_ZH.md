## 1. 三个组别到底测什么

| P 手写协议 | D + 一段人手写的 7 条科学分析协议，原文用 9 月 9 日开发运行用过的 `TASK0/runtime/ACTIVE_RULES_ZH.md`，冻结不改；文首加"以下为分析提醒，可质疑" | **协议的贡献**（P−D） |
| R 注册表规则 | D + 选择器为本题从 33 条注册表选出、按修复后渲染的规则提示（原条款与本题检查分开；不要求引用编号）；文首同一句 | **Rules Table 加选择器相对手写协议的增量**（R−P） |

**本轮不设 Harness 组。** Pro 9 月 8 日明确"本轮不再增加 Rules + Agent 第六组"；确定性检查加一次反馈（原 C 组设计，四项检查：上限词、数字溯源、统计单位、输入合理性）保留为后续单独一轮的设计，等 R−P 有结论后再决定是否测。

## 4. 评分（跑之前冻结，跑之后盲评）

每份答复一行，六个数，全部可数不可感：

| 指标 | 怎么数 | 方向 |
|---|---|---|
| 核心正确 | 评分依据里的核心单元（每题 4–6 个）答对几个 | 越多越好 |
| 核心错误（CORE） | 数值错、内部矛盾、把作者结果当自己算的 | 越少越好 |
| 过强结论 | 上限词表命中且无条件的句子数 | 越少越好 |
| 不必要弃权 | 评分依据说能答却没答的单元数 | 越少越好 |
| 缺陷检测（只 Q-D-defect） | 是否指出输入异常并降级：是/否 | 是 |
| 有信息价值的下一步 | 针对剩余问题、有方法依据：是/否 | 是 |
| 成本 | 每份答复的模型费用；每组特有的人工时间（协议撰写、规则选择与渲染、事后核对）单列，资料整理的共享成本另记 | 越低越好 |

- 盲评流程：Codex 把 60 份答复去掉分组、按随机编号命名到 `blind/`，评分表 `blind_scores.csv` 填完并哈希后才读 `blind_key.json` 揭盲。数值类指标（核心正确、CORE 错误）另由独立脚本 `independent_recompute.py` 从原表重算核对；我（Claude）在揭盲前用同一评分依据独立评 12 份抽样，与 Codex 一致率进报告。
- 规则覆盖记录另做，不参与评分。P、R 组是否引用了协议条目或规则编号只记录，不计分。

## 5. 判定规则（跑之前定死，跑之后不改）

按题配对比较：对每道题，把 P 组 4 份与 D 组 4 份的六个指标分别取中位数比较（P−D），R 组与 P 组比（R−P）。判定用 Pro 9 月 8 日给的两条路径，任一条成立才算"值得继续投"：

| 结论 | 条件（R−P，即 Rules Table 加选择器相对手写协议） |
|---|---|
| **Rules Table 值得继续（质量路径）** | 在 ≥ 2 道题上纠正了 P 组出现的核心错误或补出 P 组缺的核心正确单元，且没有任何一道题过强结论或不必要弃权更多；ADK 两题中至少一题成立 |
| **Rules Table 值得继续（效率路径）** | 六项不劣于 P，且计入规则选择、渲染和维护后，每题人工时间比 P 省 ≥ 25% |
| **Rules Table 无增量** | R 与 P 在 ≥ 3 道题上六项中位数相同，或差异互有胜负且无一题满足质量路径 |
| **Rules Table 有害** | R 在 ≥ 2 道题上过强结论、不必要弃权或核心错误多于 P |
| **协议本身有用 / 无用** | P−D 按同样标准另判一次，单独报告；它决定"要不要写协议"，不决定"要不要这张表" |

结果不清楚时按 Pro 的原话处理：**"暂不继续为它支付中心架构的成本"**，Rules Table 保留为文献索引与检查清单，不再维护选择器。

不做显著性检验来下结论；可以附一个预注册的置换检验作探索性描述，标明 n=4 每组。任何结论都限定在"这个模型（Luna medium）、这五道题、这套规则版本"。ADK 那两道题单独再报一次，因为只有它是注册表和选择器没见过的；独立测试组只有一个，这是投入决定，不是正确率估计（你 9 月 8 日报告的口径）。

## 9. 结果的意思（提前写好，免得事后解释）

- 出"R 值得继续（质量或效率路径）"：Rules Table 加选择器保留，进入下一体系时继续带；表的内容按 8 月 17 日与 9 月 8 日的意见改成"适用条件、科学理由、对应方法、结论边界"；仍不叫"Engine 有效"，因为只测了"规则作为提示"这一种用法。
- 出"R 无增量、P 有用"：写协议有价值，表不值得配选择器；Rules Table 转为文献索引与检查清单，工程投入停。
- 出"R、P 都无增量"：整理好的资料加普通 Agent 加成熟方法就够了；继续做科学，规则相关投入停；这不是项目失败，是把问题回答了。
- 出"R 有害"：先查是规则正文（专用条件迁移）还是评分依据的问题，再决定；不自动重跑。
- ADK 两题与前三题结论不一致：以 ADK 为准报告泛化，以前三题报告开发内表现，不合并。
- Harness 的确定性检查是否值得，另开一轮单独测；本轮不下结论。
