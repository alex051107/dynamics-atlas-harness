## 1. 三个组别到底测什么

| 组 | Agent 拿到什么 | 测的是什么 |
|---|---|---|
| A 普通 | 共同资料 + 题面 + 共同系统提示 | 基线 |
| B Rules | A + 选择器为本题选出、按修复后渲染的规则提示（不要求引用编号） | **Rules Table 的增量** |
| C Rules + Harness | B + 提交后一次确定性检查，检查结果作为一次反馈返回，Agent 可修订一次（运行器已支持一次修订） | **Harness 的增量**（在 Rules 之上） |

C 组的确定性检查 `harness_checks.py`（运行前冻结，四项，全部只查不改答案）：

1. **上限词检查**：答复里出现"占比 / population / 速率 / rate / 平衡 / 收敛 / 机制"等词的句子，必须同句带条件（窗口、n、统计单位）或标为作者报告；否则返回"第 X 句需要条件或来源"。
2. **数字溯源检查**：`claims[]` 里的每个数字必须能在本次 `events.jsonl` 的工具输出里找到（容差 1%），找不到返回"第 X 条数字无工具来源"。
3. **统计单位检查**：答复必须写明比较条件、时间窗口、统计单位；缺哪项返回哪项。
4. **输入合理性检查**（只对给了坐标派生量的题）：任一距离大于盒长一半、帧数与来源卡不符、单位可疑，返回"输入第 X 列有物理异常，请检查"。

反馈文本模板冻结；检查器不给答案、不给数值、不改分。C 组测的是"确定性检查加一次反馈"这一片 Harness，不是整个路由与证据包系统，报告里这样写。

## 4. 评分（跑之前冻结，跑之后盲评）

每份答复一行，六个数，全部可数不可感：

| 指标 | 怎么数 | 方向 |
|---|---|---|
| 核心正确 | 评分依据里的核心单元（每题 4–6 个）答对几个 | 越多越好 |
| 核心错误（CORE） | 数值错、内部矛盾、把作者结果当自己算的 | 越少越好 |
| 过强结论 | 上限词表命中且无条件的句子数 | 越少越好 |
| 不必要弃权 | 评分依据说能答却没答的单元数 | 越少越好 |
| 缺陷检测（只 Q-D-defect） | 是否指出输入异常并降级：是/否 | 是 |
| 有信息价值的下一步 | 针对剩余问题、有方法依据：是/否 | 是 |

- 盲评流程：Codex 把 60 份答复去掉分组、按随机编号命名到 `blind/`，评分表 `blind_scores.csv` 填完并哈希后才读 `blind_key.json` 揭盲。数值类指标（核心正确、CORE 错误）另由独立脚本 `independent_recompute.py` 从原表重算核对；我（Claude）在揭盲前用同一评分依据独立评 12 份抽样，与 Codex 一致率进报告。
- 规则覆盖记录另做，不参与评分。B、C 组是否引用了规则编号只记录，不计分。

## 5. 判定规则（跑之前定死，跑之后不改）

按题配对比较：对每道题，把 B 组 4 份与 A 组 4 份的六个指标分别取中位数比较，C 组同样与 B 组比。

| 结论 | 条件 |
|---|---|
| **Rules 有增量** | B 相对 A：在 ≥ 4/5 道题上核心错误更少或核心正确更多，且没有任何一道题过强结论或不必要弃权更多 |
| **Harness 有增量** | C 相对 B：同上标准；另加缺陷检测在 Q-D-defect 上 C 的"是"多于 B |
| **无增量** | B 或 C 在 ≥ 3 道题上与基线持平（六项中位数相同） |
| **有害** | B 或 C 在 ≥ 2 道题上过强结论或不必要弃权更多，或核心错误更多 |
| **混合** | 其余情况；逐题写清收益与损失 |

不做显著性检验来下结论；可以附一个预注册的置换检验作探索性描述，标明 n=4 每组。任何结论都限定在"这个模型（Luna medium）、这五道题、这套规则版本"。ADK 那两道题单独再报一次，因为只有它是 Rules 没见过的。
