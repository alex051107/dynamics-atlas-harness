# Rules Table 在系统里该放在哪：四层角色设计

2026-09-10 · 依据：9 月 8 日博文深读《Ensemble 博客深入解读》§7–9、Pro 概念审查 §五–六、Pro 战略审查 §二–三、8 月 17 日 Pro 对 Rules Table 的最小表示建议，以及 9 月 9–10 日六个已经发生的错误 · 供 PM 决定，供 Codex 执行

## 0. 一句话答案

**不是"额外加成信息塞给 Agent"。** 这张表里的 33 条其实是四种不同性质的知识，分别该在四个位置起作用：框题（问什么）、准入（数据能不能答）、分析（怎么算）、结论（能说到哪）。只有"怎么算"这一层是以文字形式给 Agent 的，而且要按方法族检索、短、带来源；其余三层要么在 Agent 之前由代码执行，要么在 Agent 之后由代码和评分执行。我们首轮测的"整段规则贴进提示"，恰恰是四层里最弱的一种用法。

## 1. 三份材料给出的三条约束

**博文（§7–9）：** 先问"要区分的是哪一种差异"（主要状态、比例、少数态、联合关系），再问"测量和处理有没有保留这个差异"。它提出的动作是把"数据来源、测量模型、处理记录、待回答性质"连起来；规则可以记录这些关系的适用条件，但博文没有规定必须做成规则表、概率图还是工作流引擎。它的设计例子：先定义状态，确认样品对应，检查数据能否约束比例（直接可分的个体观测，还是要从平均信号反演），在同一前向模型下比较权重方案，保留不确定范围；规则在这里的作用是"触发候选比较、误差传播或下一项有区分力的观测分析"。

**Pro 概念审查（§五–六）：** 规则要围绕"待区分的科学差异"组织，不围绕论文、软件或缺项清单；规则约束的是推断关系（来源报告了什么、当前计算得到什么、能排除什么、不能排除什么），不给来源整体打"高可靠/低可靠"；不能识别完整系综不等于只能弃权；一项计算值不值得做，看"无论结果是什么，它能不能改变对某个候选解释的判断"。

**Pro 8 月 17 日审查：** 现有 20 栏要拆成三张：`papers`（论文事实）、`source_rules`（有来源的候选规则：要求、算子策略、判据策略、验证义务、停止类别、适用范围、指导文字）、`rule_index`（可重建的检索标签）。案例级的判定（是否可观测、关系枚举、claim ceiling）只能由评价程序在运行时算出来，不能预填进输入。最高风险的三种假成功：全部安全弃权、在暴露案例上 100% 覆盖、路由结果靠硬编码。

三条合起来的意思：**表要保存的是"关系的适用条件与边界"，判定要由程序在案例上算，Agent 拿到的不该是判定，也不该是全部条款。**

## 2. 四层角色：每条规则该在哪起作用

| 层 | 回答什么问题 | 谁执行、什么时候 | 以什么形式到达 Agent | 33 条里属于这一层的（按 `rule_class`） |
|---|---|---|---|---|
| **A 框题层** | 这道题要区分的是哪种差异？哪些子问题要分开答（覆盖 / 比例 / 实验预测 / 机制）？哪个层级的结论被请求？ | 案例准备时：确定性模板 + 人（PM/Soojung 定竞争解释） | **不直接给 Agent。** 变成题面里的子问题列表和评分依据里的"能答什么 / 不能答什么" | claim_ladder、state_semantics、estimand_non_equivalence ×2、identifiability、benchmark_contract（C010-001/002、C005-001、C009-003、C012-001/002）**6 条** |
| **B 准入层** | 数据能不能回答这个问题？对象与条件对不对得上、时间语义、统计单位、观测窗口、证据角色是拟合还是验证、候选池谱系、物理合理性（周期性、单位、帧数） | 冻结之前：代码逐项检查，输出 PASS / FAIL / UNKNOWN 的"准入卡"；FAIL 不冻结 | **作为数据给 Agent**（准入卡 JSON 在 `common/`），不是提醒文字 | measurement_semantics ×2、uncertainty_provenance、measurement_quality、source_quality、multi_source_semantics、cross_validation、diagnostic_controls、candidate_design、held_out_validation（C001-001/002/003、C002-001、C007-001、C008-001、C009-001/002、C003-001/003）**10 条** |
| **C 分析层** | 这种数据该怎么算？平均律、前向模型、探针几何、重加权的正则与先验、不确定性分解、伪影排除 | 运行时：按案例的方法族检索，只取相交的；同时作为确定性算子的参数 | **唯一以文字给 Agent 的一层**：每条 ≤ 10 行的"方法卡"，带来源、适用范围、可质疑声明 | forward_bridge ×3、forward_implementation、inverse_model、reweighting、integration_operator、uncertainty_integration、uncertainty_decomposition、artifact_exclusion ×2（C002-002/003、C006-001/002、C008-002/003、C011-001/002、C005-003、C003-002、C007-002）**11 条** |
| **D 结论层** | 这个结果能说到哪？哪些升级不允许（帧数→占比、拟合→验证、几何接近→状态、差值符号→绝对吻合）；证据角色是否分开；下一项有区分力的观测是什么 | 提交之后：代码做确定性检查（上限词带条件、数字可溯源、统计单位在、证据角色未混），一次反馈；评分时作辅助清单；报告时给允许/禁止措辞 | **作为一次反馈给 Agent**（不是预先提醒），并进入报告措辞 | claim_ceiling ×3、complementary_evidence、integration_validation、functional_validation（C006-003、C011-003、C012-003、C005-002、C007-003、C010-003）**6 条** |

`rule_index` 里加一个 `layer` 标签就够，不用重写规则；选择器的工作从"科学推断"缩成"按方法族和层取卡"，这正是 8 月 17 日审查说的可重建检索视图。

## 3. 为什么"贴进提示"是最弱的用法：用本项目已经发生的错误回看

| 已发生的错误 | 提醒文字能防吗 | 哪一层、什么形式本可以防 |
|---|---|---|
| DHFR：坐标周期性包装造成 60–90 Å 假距离，两份 Agent 都没发现，还有一份用"构象切换"解释长尾 | 不能（提示里没有、有也未必看） | **B 准入层**，代码："任一原子对距离 > 盒长一半 → FAIL，不冻结" |
| HSP90 A2：0 次计算，读表把 50 点阈值的 11/7 写成 5 点的 11/9，同段先 4/20 后 5/20 | 不能 | **D 结论层**，代码："claims 里的数字必须能在本次工具输出里找到；写明统计单位与阈值"；A2 会被退回一次 |
| HSP90 B 组：FRET 的 R0、dye/AV、RMP restraint 被当成本题必填 | 提示本身就是病因 | **C 分析层**，按方法族检索：案例方法集合 ∩ 规则来源方法 = ∅ 就不取卡 |
| HSP90："出现开放方向"被读成"接近开态"，NOE 对照才发现 9/10 仍同时偏离两套参照 | 不能 | **A 框题层**：题目一开始就拆成"方向变化 / 接近状态 / 完整转变"三个子问题；**D 结论层**新规则："差值读数的符号丢失绝对吻合度，声称接近某状态前必须看两套绝对读数"（这条是本项目自己在数据上发现的，来源 = v4 轨道 B 报告） |
| HSP90 首轮 5/4/1 与 10/20 是两种事件定义，四份答复没有一份写出 5/5/10 分区 | 部分（协议第 4 条提到采样单位） | **A 框题层**："先持续 X 后持续 Y"与"曾出现 Y"分别成题；评分依据按子问题给分 |
| B1 把 420 个箱叫常规箱 | 不能 | **D 结论层**（轻）："分箱统计须注明箱长与端点箱" |

六个错误，零个能靠"多贴几条提醒"防住；五个能靠 B 或 D 层的代码防住，两个要靠 A 层把题问对。这就是为什么 D/P/R 测试测的是最弱一层。

## 4. 每一层怎么落地（最小实现，不建引擎）

- **A 框题层 → `question_split.md` 模板。** 每道题固定四栏：要区分的差异、每个子问题需要什么证据约束、同样读数还有哪种解释、请求的结论层级。由 Codex 从论文和数据填，PM 确认竞争解释（8 月 17 日审查说这是唯一必须由人定的事）。产物进 `common/QUESTION.txt`（子问题列表）和 `hidden/grading_rubric.md`。
- **B 准入层 → `admission_check.py`。** 逐条规则变成一个可执行检查：对象与条件对应表、时间语义（有序/无序）、统计单位、观测窗口、证据角色（运行前按 Methods 定）、候选池谱系、物理合理性（周期性、单位、帧数、盒子）。输出 `ADMISSION_CARD.json`，任一 FAIL 不冻结（收官令第 2 步的"物理硬门"就是它的一部分）。Agent 在 `common/` 里能读到这张卡。
- **C 分析层 → `method_cards/`。** 每条 C 层规则改写成一张 ≤ 10 行的卡：适用方法族、要核对的量、常见错误、来源与 locator、transfer_scope、"可质疑"声明。检索规则只有一条：案例元数据档里的方法集合与卡的方法族相交才取。这就是 Track C 渲染修复的完成形态。
- **D 结论层 → `ceiling_check.py` + 报告措辞表。** 四项确定性检查（上限词带条件、数字溯源、统计单位、证据角色分离）在提交后跑一次，结果作一次反馈；评分时作辅助清单（不定义评分范围）；报告的 EvidenceBundle 用它给"允许措辞 / 禁止升级"。
- **表本身：** 按 8 月 17 日建议拆 `papers / source_rules / rule_index`，`rule_index` 加 `layer` 与 `method_tags`；`proposed_project_rule` 改写成"适用条件 · 科学理由 · 对应方法 · 结论边界"四句。不新增规则，不改科学内容。

## 5. 这对正在跑的测试意味着什么

1. **D/P/R 照跑，但要说清它测的是 C 层作为提示的价值。** 结果无论如何，都不回答 B、D 层作为代码值不值。
2. **加一步零成本的回溯审计**（放在一口气总令第 7 步之前，半天）：把 §3 的表做全，对三个体系已经发生的每个错误标"哪一层本可以防、以什么形式"，并数出"提醒能防 / 代码能防 / 框题能防"三个数。这比再跑一轮更早告诉我们表该往哪层投。
3. **B + D 层作为代码单独测一轮**（原来"C 组"的想法，按 Pro 意见不混进 D/P/R）：同一批题，D 组 vs "D + 准入卡 + 提交后一次反馈"，看核心错误和缺陷检测的变化。这轮的假设是"规则作为代码比作为文字有用"，可以被否定。
4. **A 层先在 ADK 上用**：ADK 题面按 `question_split.md` 模板写，这是它对 Rules 来说是新体系的另一层意义。

## 6. 不做什么

- 不把 33 条整段贴给 Agent；不按论文取卡；不用"覆盖了多少条"衡量进度。
- 不让规则生成评分依据（评分依据来自公开问题 + 数据 + 论文，规则只作辅助清单）。
- 不建通用规则引擎、不迁 SQLite、不做 top-8 检索。
- 不把"全部安全弃权"当成功；D 层检查只退回一次，不替 Agent 改答案。
- 不用 A 层模板替人决定竞争解释。

## 7. 一句话

Rules Table 是四种知识的账本：框题模板、准入检查、方法卡、结论上限。前两种在 Agent 之前由人和代码用，第三种按方法族给 Agent 看，第四种在 Agent 之后由代码和评分用。它的价值要按层测，不按"有没有贴进提示"测。
