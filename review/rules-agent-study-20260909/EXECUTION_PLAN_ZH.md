# 科学规则是否改善 Agent 回答

Dynamics Atlas 下一阶段逐步执行计划 · 2026年9月9日 · 待 Pro 审阅草案

**Dynamics Atlas tests whether explicit, source-grounded scientific rules improve a tool-using LLM agent’s ability to produce useful, evidence-bounded answers from heterogeneous protein-dynamics data.**

**Dynamics Atlas 研究显式、可追溯的科学规则，能否让使用工具的 LLM Agent 在异质蛋白动力学资料中给出更多正确、有用、不过度的科学回答。**

本轮交付是实验计划。尚未启动开发比较或正式测试，未选择正式题，未改 Q05/Q15，也没有把本稿提交给外部模型。用户将本稿交给 Pro 审查，收到通过意见后再进入执行。下文所有预算、阈值和运行安排均为本次待审提案。

## 先读这一页

我建议采用 Pro 的主方向，将接下来的工作集中在两项可失败的比较上。第一项比较 Agent 单独工作与获得七条科学规则后的回答。第二项比较 Agent 已经读过这些规则时，少量确定性拦截是否还带来额外收益。原有科学分析保留为开发资料，不能继续作为正式验证样本。

这次需要做出的研究判断很具体。研究者交给 Agent 一份真实蛋白资料，Agent 要自己阅读、选择已有分析工具、执行并形成答案。我们观察规则是否帮助它多回答一个重要问题、避免一项真实科学错误，同时有没有增加无谓弃权和成本。规则数、运行成功数及拦截次数都不是主要成果。

计划保留三组、两个开发案例、四个新来源组和每组两次独立运行。正式输出为24份，独立来源单位仍只有4个。开发先跑6份；若需要修订，只能合并改一次，再完整重跑6份。因此正常研究运行最多36份，另允许最多两次有记录的基础设施替代尝试。

## 1. 两份新材料核对结果及其对设计的影响

### 1.1 你所指的两份材料

第一份是 Minhuan Li、F. Emil Thomasen、Pilar Cossio 的博客 **Are We Capturing the Ensemble?**，日期为2026年8月31日，副标题讨论结构生物学实验会保留、模糊或丢弃哪些分子分布信息。[S1]

第二份是 Soumendranath Bhakat 的 **Benchmarking Generative AI and Physics-Based Molecular Simulation for Sampling Conformational Heterogeneity in T4 Lysozyme**，JCIM，2026年9月3日在线发表，DOI为10.1021/acs.jcim.6c02044。分析时必须同时使用主文和Supporting Information。[S2、S3]

它们分别是一篇概念性博客和一篇具体系统研究。Pro原稿提到的Data Agents、DataSpace、Toolathlon等属于额外的Agent方法文献，不是这次所指的两份材料。本稿没有重新核验这些额外论文的原始实验，因此不把其中的层级或性能数字作为本研究设计成立的证据。

本轮复用了已有、来源匹配的Markdown衍生件，重新阅读博客全文相关段落，并核对JCIM主文Fig.4及SI的S1、S6、S7原图。公开检索确认了JCIM题名及发表日期；博客的在线重开失败，其内容依据本地完整正文和此前来源记录。[S1至S3]

### 1.2 博客讨论的核心是可区分性

蛋白质可以处于许多构象，每种构象可能有不同出现比例。博客把科学问题写成一条信息传递过程。研究者感兴趣的分布，未必等于样品制备后进入仪器的分布；仪器把构象转换成信号，后续筛选、重建、聚类或平均又把信号转换成我们实际分析的数据。每一步都影响哪些分布差异还能够被分辨。[S1，What distribution enters the experiment?及How processing can wash out the source distribution]

博客用前向关系解释为什么“测了平均值”仍可能约束多个状态。两个构象的平均信号一般是各自预测信号的加权和，不能用平均结构的预测代替。单分子测量也需要经过探针、噪声及处理模型；保留单分子观测并不等于直接看到了真实构象分布。单分子FRET时间轨迹可能包含粗状态转换信息，而单颗粒冷冻电镜通常不保留同一分子的时间顺序。[S1，How experiments constrain the source distribution]

原文提出的ensemble resolution，是对“当前测量和处理还能区分哪些分布差异”的提问。它没有给出适用于所有实验的一个分数，也没有提出Rules Engine。两组系综可能主要状态相同、比例不同，或边缘分布相似、相关运动不同；一种数据能够辨认其中某种差异，不代表它也能辨认其余差异。[S1，The question of ensemble resolution]

**对本计划的修改**是先定义要区分的科学解释，再评价Agent。每个隐藏评分要点都必须写清“哪些解释已被证据区分，哪些仍等价”，而不能只列应触发的规则。公开资料必须保留必要的测量和处理说明。只提供共识密度图时，不能要求Agent恢复已经丢失的群体信息；提供原始分布且足以比较时，也不能奖励它一概弃权。

一个仅用于讲清设计的构造例子是，两套候选分布给出几乎相同的平均读数，却在一段实验可分辨的分布尾部有差异。评分要点应检验Agent是否利用尾部信息，或是否明确尾部噪声使两者仍无法区分。这个例子不是博客中的实测结果，也不会充当正式蛋白案例。

### 1.3 T4L论文给出正面采样证据，同时留下不同层次的问题

T4溶菌酶是一种具有域间开闭运动的蛋白。作者将域间几何与Phe4侧链的暴露程度结合，划分暴露/开放、暴露/闭合、埋藏/开放、埋藏/闭合四个区域。生成模型、生成结构与分子模拟结合的AMS，以及增强分子模拟EMD，在这些区域中的覆盖不同。四区划分便于比较，但会省略每个区域内部的连续差异。[S2，Fig.2至Fig.3及Methods]

论文确实有相同生产模拟时长的比较。Fig.4将常规MD的20条1 μs轨迹，与AMS首轮100条200 ns轨迹比较，总生产模拟时间均为20 μs。完整AMS方案还包括第二轮80条200 ns，总计36 μs。因此可以讨论给定播种策略在有限生产模拟预算内的覆盖优势；不能把它说成所有生成、预处理和计算开销均相同的总体效率排名。[S2，Fig.1、Fig.4]

作者使用马尔可夫状态模型，即利用状态之间的时间转换估计状态权重的模型，给出群体估计和相关诊断。SI中暴露/闭合区域的作者报告值为AMS 0.7%，95%区间0.6%至0.8%；EMD 3.9%，区间3.5%至4.2%。这两个数是各自分析下的模型估计，不是该物理系统已经确定的唯一真值，也不能直接把EMD设为全局标准答案。[S3，PDF第5页S6、S7]

SI的S1同时呈现了与实验单分子FRET分布的相同部分和差异。高效率区域有对应信号，约0.6附近仍可看到AMS与实验的分布结构不同。图形差异尚未在本项目中经统一误差模型量化，不能直接判定整体方法失败；同样，覆盖到稀有闭合区域也不足以认定完整实验分布已复现。[S3，PDF第1页S1]

**对本计划的修改**是给T4L开发题同时设置正面与限制性评分单元。好的答案应保留给定预算下的覆盖证据，区分估计权重与真实平衡比例，并说明FRET和时间诊断分别支持什么。只写“没有完全验证，所以不能判断”会丢失已知成果，也会被计为无必要弃权。开发题读取主文和SI即可，不要求重新生成轨迹或复建MSM。

## 3. 两个研究问题、比较对象和可能的误判

| 比较 | 要估计的效果 | 可以支持什么 | 尚不能区分什么 |
|---|---|---|---|
| B−A | 给Agent七条可读、带来源的科学指导包 | 指定任务和模型下，指导包是否提高有用正确回答或减少错误 | 额外知识、提醒、组织方式、增加阅读文本各自的贡献 |
| C−B | 同样指导包之上增加两个有限确定性检查及一次反馈 | 这套具体执行政策是否进一步改善最终交付 | 所有Rules Engine或任意自动科学审查的效果 |

B与C同时观察，第二个问题的继续投入决定以第一个问题的结果为主要前提。若B没有增益而C有增益，必须如实报告这个混合结果，不能硬写成所有规则都无用。可能需要另外设计不含完整Table的小检查对照，见第12节。

目标Agent是在给定成熟工具和资料范围内，自己安排阅读与分析步骤。研究者给科学问题，Agent选择方法，运行后按证据回答。当前已有的Profiler/Planner调用和确定性路径不能直接当作符合这个条件的完整Agent基线。第一天必须确认存在真实的多步工具调用，而不是开发者先选好算子，再让模型填配置。[S7]

本稿不以L2或L3标签作为通过标准。可观察标准是工具选择、真实执行和最终科学答复，不要求Agent发明算法、写新科学算子或拥有最终领域认可权。

## 3A. 第一步为什么可以小，Agent能力却不能被做小

用户补充的担心成立。如果所谓Agent只是读一张表，再按预写步骤调用一个函数，这个实验测到的主要是提示词遵循，难以说明科学Agent的价值。第一步应当简化处理差异，同时保留完整的工具使用能力。

**本计划将harness理解为支撑Agent持续工作的运行系统。** 它负责把资料和工具接给模型，执行模型选择的动作，返回结果，控制资源并保存证据。模型在这个系统内安排分析过程。Rules Table是一种可加入的科学指导，确定性检查是另一项可加入的执行政策，两者都不等于完整harness。

### 本轮三组都应有的能力

| 共同能力 | 可以观察到的行为 | 不应由开发者代做的部分 |
|---|---|---|
| 理解任务与定位资料 | 从科学问题选择要读的文件和片段 | 不先把关键图和预期答案提取给某组 |
| 自主安排分析 | 在现有工具之间选择有信息价值的步骤；资料够用时直接回答 | 不把Q05的SAXS-only路线写成固定工作流 |
| 执行并读取真实结果 | 调用工具，检查输出含义和错误，必要时修正自己的代码 | 不把预计算结论伪装成Agent自行完成 |
| 根据结果调整下一步 | 数值或文件结果不支持原判断时，改变下一项检查或缩小结论 | 不由外部开发Codex及时提示它遗漏了什么 |
| 保存并使用证据 | 同一会话内保留所读来源、计算输出和未解问题，最终形成有用答案 | 不由另一个有隐藏答案的整理器补齐最终结论 |

这些能力都属于A/B/C共同基础。正常工具错误反馈、会话内工作笔记和预算内的分析修正三组都保留。C只多两项预定的科学角色检查，不能独享更强的规划器、更好的记忆、更长的反思流程或额外工具。

一个具体开发过程可以是Agent先读数据角色，提出一个可区分的科学问题，选择已有计算，读到与预期不同的结果，再决定补查误差或只报告局部答案。这个过程的实际路径由Agent产生；评判者评价它是否有效，不把某条开发者预想路径作为唯一正确路线。

### 后续科学harness怎样发展

第一步回答最小增量问题，后续才决定哪一种运行能力值得专门研究。可能的候选包括来源与条件追踪、跨工具结果传递、根据数值证据调整计划，以及在局部失败时保留可答部分。每个候选都需要由真实运行失败支持，不能因为听起来完整就一起开发。

后续比较应把同一基础Agent接到两个harness版本上，固定模型、数据、工具和资源，只改变一个具名能力，再用新的来源评价。规划或证据追踪模块如果多用了模型调用，其成本也必须计入。不能把五项能力一起改进后的收益全部归因于Rules。

因此，第一轮Table没有增益，只会削弱“这七条指导值得作为研究中心”的依据；它不否定工具执行、证据追踪或更好的harness设计。若Table有益而两项拦截无益，最自然的方向可能是保留科学指导和一个能工作、易检查的harness。若当前共同harness本身经常丢工具结果，应先报告运行基础的缺口，本轮不把它包装为Rules失败。

这部分是后续研究路线，不增加本轮实验数量，也不批准新框架开发。第一步结束后仍须依据实际结果决定继续研究哪个具名功能。

## 4. 七条 Active Rules 草案

以下七条是将已有科学原则整理成可执行提问的**候选文本**，不是七条作者原话，也尚未冻结为实验v1。每条只保留同一组八个字段。B与C读取完全相同文本；A不读取该表。来源在文末，正文不含内部规则编号、绑定号或执行状态码。

### 规则一　明确要回答的科学量

- **Rule**　当前问题要求区分哪一种科学结果？
- **Why**　几何、群体比例、动力学、观测信号和功能机制所需证据不同。
- **Applies when**　提问或答案在这些结论之间发生转换时。
- **Evidence needed**　目标量、适用对象，以及直接支持它的观测或计算。
- **Allowed conclusion**　给出已被支持的那一层结果及条件。
- **Forbidden upgrade**　从闭合样结构存在直接推出其平衡比例、转换速率或功能机制。
- **Possible action**　把问题拆成可回答和仍待证据的部分，保留已回答内容。
- **Source**　[S1] The question of ensemble resolution；[S2、S3]覆盖、权重与实验比较。

### 规则二　明确物理对象和条件之间的关系

- **Rule**　这些资料的蛋白对象和实验条件支持怎样的比较？
- **Why**　构建体、突变、配体、寡聚状态、温度、环境、标记及制备会影响实际样品。
- **Applies when**　合并或比较不同实验、模拟或样品时。
- **Evidence needed**　来源中的对象和条件说明，差异及需要使用的桥接假设。
- **Allowed conclusion**　明确适用对象及假设后的比较，或不依赖未解差异的局部结果。
- **Forbidden upgrade**　把不同对象无说明合并；也不能仅因一个条件缺失而否定所有可比结果。
- **Possible action**　核对原始方法和对应关系，说明哪一项差异实际影响当前问题。
- **Source**　[S1] What distribution enters the experiment?；[S8]标记、条件与跨观测解释。

### 规则三　识别实际观测量及其处理过程

- **Rule**　数据实际记录什么，处理后仍保留什么信息？
- **Why**　同叫distance的字段可能表示骨架距离、探针距离或由效率反演的量；分布和均值也不同。
- **Applies when**　解释表格、分布、密度图或跨技术比较时。
- **Evidence needed**　原生读数、单位、聚合方式，以及筛选、重建和转换说明。
- **Allowed conclusion**　在该读数与处理保留的信息范围内作判断。
- **Forbidden upgrade**　把字段同名当作测量等价，把处理后表示直接当作完整分子分布。
- **Possible action**　优先在可比的观测空间比较，必要时回看原始或更少处理的数据。
- **Source**　[S1] How experiments constrain…及How processing can wash out…。

### 规则四　区分统计单位、采样和时间证据

- **Rule**　这些数据的独立单位是什么，是否保留支持时间结论的顺序和采样信息？
- **Why**　相关帧、不同起点或无序结构集合不能自动提供独立重复或转换速率。
- **Applies when**　报告置信区间、状态比例、稀有状态或动力学时。
- **Evidence needed**　重复单位、时间顺序、采样政策、观察窗口及所用模型诊断。
- **Allowed conclusion**　描述覆盖、模型条件下的估计，或在足够时间证据下报告动力学量。
- **Forbidden upgrade**　把帧数当独立样本，把静态覆盖当平衡概率，把有限轨迹直接当可靠速率。
- **Possible action**　按合适单位比较、检查相关性或时间诊断；缺时间证据时保留几何结果。
- **Source**　[S1]单分子与单颗粒之别；[S2、S3] AMS及MSM方法与诊断。

### 规则五　标明证据的使用角色

- **Rule**　当前证据是否已用于拟合、校准、候选生成或方法选择？
- **Why**　同一数据上的拟合改善与新信息上的预测检验支持不同强度的判断。
- **Applies when**　评价模型、更新权重或宣称验证时。
- **Evidence needed**　实际拟合目标、训练或校准信息及重复使用记录。
- **Allowed conclusion**　准确标注的拟合结果、条件性预测或有充分独立性依据的验证。
- **Forbidden upgrade**　把已参与拟合的数据称为独立验证；信息角色未知时不能推定独立。
- **Possible action**　检查输入与目标函数，寻找未参与选择的证据或明确保留角色不确定。
- **Source**　[S9]联合与单观测重加权设计。

### 规则六　检查前向模型和探针关系

- **Rule**　如何从候选结构预测当前实验读数，该关系适用于此问题吗？
- **Why**　结构到信号可能涉及探针、非线性平均、取向、时间尺度和模型误差。
- **Applies when**　用结构解释FRET、DEER、NOE、散射或其他实验时。
- **Evidence needed**　前向关系及单位、平均方式、参数适用范围和不确定性。
- **Allowed conclusion**　在该关系与误差假设下的预测比较。
- **Forbidden upgrade**　未经模型把结构距离等同于FRET效率，或先平均结构再替代平均信号。
- **Possible action**　选择给定成熟工具或等价计算，解释残差，指出前向模型未解决的部分。
- **Source**　[S1]平均观测公式；[S9]纳米盘前向预测与重加权。

### 规则七　说明能排除什么，以及下一步怎样区分

- **Rule**　当前证据排除了哪些解释，哪些解释仍然都成立？
- **Why**　符合若干观测不保证唯一结构、唯一权重或唯一机制。
- **Applies when**　多个模型都能解释结果，或答案涉及完整ensemble解释时。
- **Evidence needed**　被比较的解释、预测差异、误差和可辨认范围。
- **Allowed conclusion**　明确已确定部分、仍等价的解释，以及有区分力的下一项证据。
- **Forbidden upgrade**　从一个好拟合选出唯一真分布；或因某部分未解而取消已有正确答案。
- **Possible action**　比较替代解释，提出能区分它们的具体读数或分析；证据已经够用时直接回答。
- **Source**　[S1]ensemble resolution；[S2、S3]不同层次的采样与实验结果。

本表把不确定性放入相关规则，避免漏掉误差模型；不新增第八条通用“再检查一次”。通过开发冻结时，目标是控制为2至4页可读材料。

## 5. 三组Agent到底看到什么、做什么

### 5.1 共同可见内容

三组得到同一科学问题、同一原始论文和SI、同一数据、同一工具及其方法文档、同一输出格式。文件索引只说明文件类型和来源，不提供应使用的分析、目标数值、错误提示或规则对应。完整论文中本来就包含作者解释，这是任务证据；额外的开发结论摘要和标准答案不进入工作区。

公共资料中的事实必须有定位。例如某个数据集是否参与拟合，只能引用作者方法或实际输入记录。若curator为方便读取制作事实清单，它必须对三组相同，逐项有来源，未知项保留未知，不能写“因此应弃权”之类判断。清单及处理成本计入人工准备。

正式运行默认离线阅读已封装来源，不开放自由联网。模型服务连接单独开放，科学工具不访问模型以外的网络。这样避免不同运行获得不同论文、答案网页或Rules。它检验给定资料中的分析能力，不能解释为开放网络文献发现能力。

### 5.2 共同工具范围

第一天锁定同一小工具包，优先复用现有文件读取、PDF/Markdown检索、Python、NumPy/SciPy、绘图及已验证的数值函数。需要重加权、误差传播或已有前向矩阵评价时，工具描述只说明输入、输出、适用条件和错误信息，不指定某个case应调用它。

不把旧Q05的“推荐SAXS-only”“联合目标配置”作为Agent可见的任务安排。旧科学结果和配置留在开发参考区。各组可以自己编写短分析代码调用已有方法，但不能安装包、生成新科学算子供后续case复用、启动新MD或访问集群。

当前机器有Codex及Docker命令入口；这只证明程序存在。已查看的旧运行模块主要是Profiler/Planner提案传输，正式研究所需的端到端隔离、计量和工具循环尚未验收。[S7]第一天优先核实并复用已有完整工具型Agent运行入口，只允许做一个小的运行适配；不要求四小时内从头开发harness。四小时内若无法证明公平隔离和预算约束，就停在环境未就绪，不以现有半预写流程代替Agent实验。

### 5.3 共同输出及其测量代价

最终答案保留五部分。

1. `bounded_answer`，逐条有用的科学结论及条件。
2. `evidence_used`，使用的原始来源或真实计算输出。
3. `analysis_performed`，实际做过的分析；不要求提交私有推理过程。
4. `unresolved_alternatives`，资料仍无法区分的解释。
5. `next_action_if_needed`，有必要时的具体下一步；证据足够时允许为空。

为使C的有限检查可以确定性执行，五部分中的结论记录还需附相同的简短字段，见附录B。三组都使用这些字段。它们会让A也注意到证据类型和角色，因此本实验的A准确名称是“具有共同证据输出格式、没有七条Rules的Agent”。B−A是在这个较强基线上增加规则文本的效果，不能宣传成与完全无科学结构提示的Agent比较。

### 5.4 唯一处理差异

| 项目 | A | B | C |
|---|---|---|---|
| 问题、来源、数据、工具、预算、输出格式 | 相同 | 相同 | 相同 |
| 七条规则及其引用 | 无 | 有 | 与B相同 |
| 公开的两项确定性检查定义 | 无 | 包含在规则附注，可自行遵循 | 同样附注，并由程序执行 |
| 最多一次固定提交后修订机会 | 有，共同格式反馈 | 有，共同格式反馈 | 有，共同格式反馈及实际冲突信息 |
| 额外科学工具、人工帮助或隐藏评分要点 | 无 | 无 | 无 |

B/C附注不能加入第八条知识，只把规则4和5中的两个明确禁止升级写成可执行条件。C−B估计的是这些检查、反馈与发布限制的组合效果。它没有覆盖完整旧Engine，因此结果不能外推到33条规则及其全部执行系统。

### 5.5 C只先检查两种明确矛盾

**拟合与独立验证冲突。** 结论把一个具名数据对象标为独立验证，而该对象公共记录明确显示参与了本次拟合。系统指出冲突及来源，要求修改该结论的角色。它不判断没有参与拟合就一定独立，候选生成与历史选择的泄漏仍需Agent解释。

**静态资料与新推断速率冲突。** Agent声称从所引用资料重新推得转换速率，而引用对象全部明确为无时间顺序的静态集合，且不存在时间或其他有效速率证据。系统限制这条升级。若Agent是在准确转述论文已报告的速率，或引用实际时间资料，不能按静态集合规则拦截。

未知元信息不能自动转为负面事实。字段和文本矛盾、引用遗漏、委婉绕开标签等情况仍可能漏检，全部保留给盲评分。一次确定性检查通过不等于科学正确。

C保留提交前原稿、冲突反馈、修订稿及最终展示内容。修订后仍冲突时，只限制那一条结论，并保留其他答案及受限原因。主评分看用户最终可见内容，同时报告原稿与拦截效果；删掉正确结论会降低有用答案分数，增加无必要弃权。不能用“拦截成功”覆盖这些损失。

## 6. 隔离、人员和工具准备怎样落地

### 6.1 开发者与被测Agent的边界

Development Codex可以读取科学答案、准备工具和评判标准。Evaluation Agent每次从空白消息和新工作目录启动，只能读取封装的公共case、共同方法文档及本组允许的规则文件。

隔离需要真实文件与网络权限。只换聊天窗口、使用worktree或把答案放在相邻目录，都不够。测试进程不能看到项目根目录、AGENTS.md、记忆目录、旧任务历史、开发报告、隐藏评分要点及其他运行的输出。模型认证由受信任的启动端处理，不把凭据或整个用户目录挂到科学工具工作区。

优先用现有运行设施的受限文件挂载和网络控制。实施时只允许一个薄启动脚本和一个小的确定性检查模块，不建立多Agent框架。启动脚本负责新会话、预算、工具转发和日志；科学步骤由Evaluation Agent选择。

在任何开发模型调用前，运行一次合并的非模型检查。放置一个工作区外的诱饵文件，验证读取失败；检查符号链接逃逸、隐藏目录和禁止网络访问；确认A只缺规则处理，其余公共文件一致。未通过则所有组都不能开始。这项检查的成本是隔离验收，不是规则科学增益。

### 6.2 角色与人力

| 角色 | 负责内容 | 不负责什么 | 预计投入，待确认 |
|---|---|---|---|
| Development Codex | 七条规则、公共工具、运行适配、评价规范及开发修改 | 不在正式运行中指导Agent | 约1至2个工作日 |
| 独立curator | 冻结规则后选择新来源，准备问题、公共资料和隐藏要点 | 不改Rules，不查看实验表现挑题 | 约8至12小时 |
| Soojung或领域专家 | 审四份隐藏要点的科学边界 | 不逐条审33条候选规则 | 初审约2至3小时，复杂项另计 |
| 两位盲评分者 | 各自评价24份输出，再讨论分歧 | 不提前看组别或规则执行记录 | 按每份约10分钟估算，每人约4小时，另加分歧处理 |
| 结果整理者 | 执行已冻结脚本，评分锁定后揭盲 | 不因结果不好更换题或阈值 | 约半个工作日 |

人员尚未约定。独立curator可以是没有继承开发上下文、只读固定选择标准的独立会话，但它制作的科学要点仍须领域专家确认。两位盲评分者优先为能够读该类资料的人；AI可作第二意见，不能未经声明替代计划中的人类确认。缺少人员时，先交付开发结果和未完成条件，不称已完成正式研究。

## 7. 四个新来源怎样选，怎样防泄漏

Day 2冻结七条规则、提示、工具说明和评分逻辑后，独立curator才开始筛正式来源。本次只写选择标准，不先搜索候选论文，也不准备隐藏答案。

排除表至少包含原20题涉及的论文及数据、33条候选规则的11个来源、Q05、Q15、新T4L、博客及本项目已有59项文献分析中的实质暴露来源。共同的轨迹、实验样品、预测矩阵或同一数据的再分析属于同一来源组，即使DOI不同也不能拆成独立测试。仅蛋白名称相同不自动证明数据重叠，但必须检查其谱系。

“新”只表示未用于本项目规则设计或开发，不能保证从未进入底层模型预训练。无需隐瞒论文身份；最终报告明确这是项目层面的未见来源。

按四类各筛最多两个候选，合格者按预先记录的筛选顺序选一个，另一个作正式调用前的备用。排除理由记录为资料可得性、谱系、题目边界或工具适配；不能根据A弱或B强来选。正式开始后不启用备用来源替代难题。

| 来源类型 | 需要包含的真实科学任务 | 准入条件 | 评分容易失真的地方 |
|---|---|---|---|
| A　可以直接回答的比较 | 根据现成图、表或数据给出有限正面结论 | 不需新增计算也有2至4个明确可答单元 | 不能把“没有调用工具”判错 |
| B　可以补算的证据缺口 | 已有资料不足以直接回答，但现有工具能给出有信息的结果 | curator用给定工具验证至少一种可行分析，保留等价替代法 | 不能把唯一预想算子写成正确答案 |
| C　跨观测与前向关系 | 结构与FRET、DEER、PRE、SAXS等信号的关系 | 必要参数或成熟前向预测已可获得，缺口不会要求新增方法 | 不能因两者都叫距离就视为相同 |
| D　局部可答、关键解释未解 | 有明确正面结果，但至少两个解释无法被现有资料区分 | 隐藏要点同时给出可答内容和不可分解释 | 不能用整题弃权换取低错误率 |

题目的难度来自真实分析依赖。例如需要识别不同观测的含义、从多个可用方法中选出有区分力的计算，并把结果解释为科学答案。curator不能先把这些步骤写成教程，也不能为提高难度删掉本来存在的关键元数据。直接可答题仍保留，用来检查Agent是否把有限的不确定性扩大成整题弃权。

这是按关键困难有目的选择的挑战性小样本，会偏向规则可能相关的情景；它不是蛋白动力学工作的代表性随机抽样。四类是采样分层，不是已验证的完整能力分类。

每份case包含一个科学问题及公共材料。公开文件保留真实表头、单位、方法与来源，但去掉开发者生成的“expected analysis / expected rule / conclusion summary”。原始论文自己的结论正常保留，要求Agent根据证据评价它，而不是只复述它。

## 8. 隐藏评分要点怎样写和验收

每题不超过一页，主表只有五部分。

| 部分 | 必须写清楚的内容 |
|---|---|
| Answerable | 2至4个可单独判断的科学结论；明确哪一个对任务重要，不把措辞同义词拆成多个分数 |
| Not supported | 具名的严重升级及其不成立原因，如未支持的速率、唯一机制或独立验证 |
| Required evidence | 支持每个结论的图、表、数据、对象条件或真实计算；给精确位置 |
| Acceptable analyses | 一种已核准方法及允许的等价路线；需要数字时预定单位、误差和容差依据 |
| Legitimately unresolved | 仍同时符合资料的解释，以及当前已知部分为何仍可回答 |

该页由curator先完成，再由领域专家逐项确认。它不是把论文结论当标签。专家需要检查论文中的方法和限制，必要时质疑作者叙述；也不能把个人偏好的分析工具设为唯一答案。

先验证评判工具能接受一份正确的有限答案、一份错误升级、一份只说不能判断的答案和一份使用合理替代方法的答案。开发阶段把这四类构造样例作为一次合并评分校准，之后不根据正式输出改评分逻辑。

正式来源的精确阈值和容差写入该来源的隐藏页，是评分数据，不是新增Rules。Day 4发现资料不支持原问题时，可以在任何正式运行前改curation材料或换用预定备用；若必须新增科学工具或改变七条规则才可作答，该来源不满足本版准入。不能把这种修改藏进“补元数据”。

## 9. 逐步执行顺序

### Step 0　审查后建立一个小实验入口

输入是本计划及用户转回的Pro审阅结论。按用户本轮授权，收到明确通过意见后进入已审范围；先核实是否还有尚未解决的执行条件。有实质改动时形成修订版并说明差异，不把条件通过当作所有问题已经解决。

冻结Q05/Q15引用，给原20题和现有来源加开发用途标签，在现有目录中写最多两页的Experiment Charter。把本阶段统一目标放到README的当前阶段说明。自动任务继续暂停，不开启循环。

完成条件是所有人知道本阶段的两个比较、不能继续扩展的旧工作和待完成的实验。此时没有正式Agent结果。

### Step 1　把公平比较变成可检查的输入

以第4节七条规则为起点，形成可读草案和对应来源。将公共工具描述从旧case特定配置中分离，准备A/B/C提示及共同输出。实现第5节两个有限检查；不能复用会额外安排科学步骤或读取隐藏信息的旧Engine行为。

锁定候选模型和预算，在运行环境完成一次隔离、预算计量及两项检查的合并验收。检查包含允许发布、真实冲突、缺失信息以及部分答案保留四种路径，不跑整套历史规则测试。

完成条件是三组只有预定处理差异，共同harness支持多步自主工具调用和结果反馈，隐藏答案不可读。开发阶段还需实际看到至少一个需计算的题由Agent完成阅读、选工具、执行和解释；缺少此证据不能将一次模型答复称为科学Agent比较。若四小时内做不到，记录具体技术缺口，停止模型运行。

### Step 2　运行六份开发答案

两个开发题分别使用Q05和T4L，每题A/B/C各一次，六次都是新会话。问题只给高层意图，不能出现“先做SAXS-only”或“重点找0.7%和3.9%”。

Q05输入含原始方法、实验/预测矩阵及公共工具，不含本项目结果表。开发参考中的具体数值用于核对科学正确性，但不强制Agent必须重复唯一分析。若它选择其他合理、可复核且回答问题的方法，也可得分。

T4L输入含完整主文及SI，评价其对采样、模型权重、实验信号和时间结论的解释。开发参考允许转述作者报告值，但不把“发现四区”与“全分布正确”合并评分。

全部六份完成后统一审阅。只修一次相关批次，可涉及规则措辞、提示、工具说明或执行器明显软件错误；每项修订都写明它解决哪个测量问题。若需要改变科学问题或另建算子才能跑通，应停止并修订整个提案，不伪装成这一次小修。

### Step 3　一次修订后冻结

有修订时完整重跑两题三组，再得到六份独立开发答案。未修订时不为凑数重复。第二轮仍不能满足基本隔离、工具调用和评价一致性，就不进入正式测试。

冻结七条规则、三组提示、共同格式、两个检查、模型/推理设置、工具包、网络政策、计量规则和通用评分逻辑。源数据身份首次建立一份文件清单摘要，正式启动前只再核对一次；不反复计算普通文稿的hash。

开发成绩保留，永不并入24份正式结果，也不用于宣称未见来源增益。

### Step 4　准备四个新来源及专家评分页

独立curator按第7节选题并准备公共材料和四页隐藏要点。Development Codex接收公共格式和技术错误报告即可，不依据隐藏答案添加规则或改变提示。把共享来源归组、资料可访问性、允许分析和量纲逐项确认。

领域专家完成四页科学边界确认。公共资料及隐藏页冻结后再生成正式运行序列。专家未确认的题可以做资料准备，不能叫正式评价题。

### Step 5　运行24份正式答案

运行单位是来源组×Arm×重复。四个来源各有两个运行区块，每个区块运行A/B/C三个新会话。使用事前固定随机种子打乱区块内Arm顺序，并交错来源，减少模型时段或服务变化与某一组重合。两次重复不是新的独立论文。

全部运行使用相同模型、推理设置、公共工作区和预算。实时监控只看进程、预算和文件错误，不评价答案，不进行补提示。出现超预算、模型拒答或分析失败时按第10节保存结果，不人工救场。

正式开始后冻结项不得改变。需要改变Rules、工具或问题的实质错误会使受影响比较退出本次有效样本；保留全记录，进入以后另行批准的vNext和新来源，不能同题修后再称正式验证。

### Step 6　先盲评分，再揭示组别

输出复制为随机编号。去掉Arm标签、系统名、开发说明和规则执行轨迹，保留科学答案和其中的真实引文、计算路径。不能为盲法润色、删掉错误或改写弃权内容。

两位评分者使用固定评分页独立评价，分歧先讨论并保存各自原始评分，然后锁定结果，再揭盲。风格可能泄露组别，因此附记录评分者对组别的猜测和信心，不能声称盲法必然成功。

证据使用与计算真实性另依据经过去标识的工具输出核对。如果工具记录本身暴露执行器，先锁定答案质量评分，再核对执行；不要让看到C拦截记录影响对答案好坏的初评。

### Step 7　做投入决定并结束本轮

分别报告每个来源的B−A与C−B、两次重复的变化、严重错误、遗漏、无必要弃权、工具选择及成本。逐项解释增益是否只是少说了话，或是否来自额外的公开事实准备。

完成第12节的效度检查和投入判定后，出具KEEP、SIMPLIFY或STOP路线建议。没有结果支持的新实验不自动启动，不恢复旧Q05/Q15修复循环。

## 10. 同预算、超时与失败怎样定义

下表给出可以直接讨论和冻结的建议默认值。模型端点、实际token计量和总费用尚需在Step 1核实，本轮不调用收费模型。

| 设置 | 建议冻结值及执行方式 |

| 会话 | 每次新进程或会话，独立目录，无历史会话、记忆和上一运行结果 |

36次正常运行的token上限算术为576万输入和108万输出；两次替代尝试的额外上限为32万输入和6万输出。实际价格与配额可能使100美元无法覆盖这些理论上限。Step 1必须用当前端点信息核算，选择一个既公平又付得起的冻结方案；不能用此处候选值虚报已可运行。若端点不能计量或限制累计token，就先报告计量缺口，不声称已经完成同token预算实验。

Rules的阅读token正常计费。A不填充无意义文字以匹配长度，B/C使用相同规则全文。这样测的是实际部署这份指导的收益与成本。固定上限不要求三组实际消耗相同，实际消耗本身就是结果。

**基础设施错误**包括文件本应存在却无法读取、模型服务在返回内容前失败、工具进程因环境损坏无法启动。先保留原尝试与错误，可按固定政策替代一次，整项研究最多两次。启动替代会话不给上一答案或额外提示。已经产生答案后的模型推断错误、超时、主动选错工具、脚本计算错误都属于Agent表现，不能借基础设施标签清除。

共同软件缺陷影响不同组时，暂停受影响区块。若修复改变了资料、方法或处理差异，本次正式比较无效；不能以修复为理由继续把混合版本平均。服务端模型版本改变也需停止并记录，不能把新旧版本当完全同一处理。

缺失最终答案分别报告完成率及按计划分母计算的有用答案覆盖。超时或模型失败的运行没有完成的结论记零；纯基础设施缺失另列，不能直接当科学错误，也不能从结果表消失。没有足够有效配对时不触发正面的继续阈值。

## 11. 评分与分析细则

### 11.1 六项分开报告

**有用正确答案覆盖率。** 设来源g的隐藏页有m个可答结论单元，m为2至4。每个单元明确且正确回答记1，未答、错误或与自身答案矛盾记0；语义等价表达接受。该份回答的覆盖率是正确单元数除以m。额外文字没有加分，不能通过把一句话拆成多句提高分数。

**严重过度结论。** 对每个具名、会改变科学判断的错误升级记有/无，并报告类别。单份答案的有无指标与错误类别数都保存；同一句话重复不多次计错。不能用更多轻微正确点抵消严重错误。

**无必要弃权。** 对一个本来可答的单元，若回答明确声称资料不足、拒绝判断，或因其他未解部分取消它，记1。分母仍为m。纯遗漏单列在覆盖损失中，不冒充弃权；整题拒答会同时损失所有可答单元。

**关键证据使用。** 逐项检查隐藏页要求的证据是否真正支撑相应结论，保存引文及工具输出定位。浏览过文件或列出参考文献不等于使用证据。答案碰巧正确可以得到科学正确单元，但证据使用不通过，该单元不能被用来证明本研究的实质增益。

**分析选择。** 对不需计算的题，准确判断无需新增计算是合理选择。需要计算时分别记方法有信息价值、执行正确、解释正确三项。接受预定等价方法；多调用工具或复述“建议计算”不算完成分析。计算依赖单元没有实际运行或可核对输出时不得计为实质增益。

**成本。** 分别保存模型输入/输出及可见推理token、工具调用、工具CPU或运行时间、墙钟、错误/重试，以及curation、Rules整理和软件开发投入。基础设施成本与科学分析成本分开，不用一个总分隐藏权衡。

人类修正时间如要使用，必须另行在揭盲前安排同一修正目标和操作计时。不能把阅读评分的时间冒充修正时间；也不能让刚看过B答案的人马上修同题C，再说C节省时间。建议本次以质量和真实错误为H2主要依据，修正时间先作次要探索性指标。

### 11.2 差异怎样计算

先对同一来源、同一运行区块计算B−A和C−B，再对该来源的两次结果求平均。全研究摘要对四个来源等权，不让结论单元多的论文或更多帧获得更大权重。各来源的原始两次分数必须和平均同时显示。

一张主结果表就足够。

| 来源组 | 两次A结果 | 两次B结果 | 两次C结果 | B−A多/少回答了什么 | C−B阻止/造成了什么 | 错误与弃权 | 成本 |
|---|---|---|---|---|---|---|---|
| 四行，正式完成后填写 | 待运行 | 待运行 | 待运行 | 待运行 | 待运行 | 待评分 | 待记录 |

不对4个来源作可靠总体显著性或等效性声称。两次重复只能揭示一部分随机波动；结果相近应写“本轮没有观察到满足预设门槛的增益”，不能写“Rules无效已被证明”。模型预训练曝光无法排除，结论始终受项目层面新来源和当前工具环境限制。

## 12. 投入阈值、混合结果和停止条件

以下阈值用于决定本项目是否继续投入，不是统计显著性标准。通过Pro审阅后可在任何开发或正式结果出现前调整；正式开始后不能修改。

### 12.1 什么算一个来源上的实质改善

满足下面任一种，同时新增正确单元必须有关键证据，且不得依靠新增人工提示或额外工具。

- **增加答案**，相比前一组，两次运行平均至少多一个重要正确结论单元，两个运行区块的覆盖差异均不为负。
- **减少真实科学错误**，至少一种原有严重升级在后一组两次输出中均消失，前一组至少一次出现；该来源的平均有用覆盖不降低，不能靠整题弃权实现。

“重要”由隐藏页在运行前标注。只有文风更谨慎、更多状态文件、引用更长或拦截次数更多，不计为实质改善。

### 12.2 H1，继续研究Rules Table

至少两个有效新来源达到B相对A的实质改善；四来源全部有效完成。全体严重过度结论的输出数量不增加；无必要弃权的来源等权平均增加不超过0.05，并且不得在某一来源的两次运行中都丢掉预先指定的重要可答单元。

若A在所有题几乎已经完全正确，B很难改善，应如实记为基线出现上限效应。本轮不支持继续扩大Rule中心投入，也不由此证明其他问题上永无作用。不能当场挑更难的题重测。

### 12.3 H2，继续研究有限执行器

相对B，C至少在两个有效来源阻止真实错误，且平均有用覆盖不降低、严重错误不增加、弃权满足H1相同约束。错误必须能在保存的提交前文本中定位，并与已公开的两项检查建立直接关系。另报两项检查可适用的来源数、B已经正确的次数、真实冲突数及误拦截数。若正式题没有提供检查机会，H2证据不足，暂停扩建；不能因未触发就否定其他harness能力，也不能临时补一个易触发的新case。

Pro原稿中的“同质量下人工修正时间下降约25%”保留为可选投入理由，但本稿建议不作为默认替代通道。只有在正式运行前已冻结计时任务、盲法分配和相同质量终点，并且B的修正时间非零，才允许使用。至少两个来源显示改善、整体下降达到25%，也仍仅为小样本投入信号。人员或计时未到位时记未测，不能用token下降替代。

### 12.4 最终路线与科学结果分开写

| 有效结果 | 路线决定 |
|---|---|
| H1和H2都达到门槛 | KEEP RULES ENGINE，继续研究当前七条指导和两个有限检查；不自动扩成旧大Engine |
| H1达到，H2未达到或C有额外损失 | KEEP RULES TABLE BUT SIMPLIFY，保留可读科学指导和成熟工具，停止扩建确定性执行层 |
| H1未达到，C也无可靠额外作用 | STOP RULE-CENTRIC PATH，规则保留为清单、教学及来源资料，研究重心转向工具与实际分析能力 |

另有两个不能强行塞进三种科学结论的情况。

**B没有增益、C却有明确增益。** 先报告实际模式，暂停完整Table/Engine扩建。它可能支持更小的检查机制，而不是七条文本指导；以后若要归因，需要另行批准“Agent加小检查”的新对照和新来源。本轮不能写成Rules全无作用，也不自动取得KEEP完整Engine的依据。

**实验缺失、污染或评判失效。** 标记本轮不可判定，暂停扩建，列出未满足条件。这是研究状态，不是Rules科学无效的第四种结论。若七天内没有条件修复，不启动无期限修补；交付实际有效部分和停止原因。

任何需要逐蛋白新增规则、正式结果出现后改Rules再用同题验证、为某组补工具、或开发者提供预想分析而产生的“改善”，都不能通过H1/H2。

## 14. 只保留五类交付

1. **Experiment Protocol**，包含Charter、步骤、组别、预算、提示、工具约定、评分和冻结记录。本稿是其待审初版。
2. **Frozen Active Rules Table**，七条规则、简短执行附注和来源，单独阅读目标2至4页。
3. **Six case packets**，两份明确暴露的开发case和四份项目未见来源；公共材料与开发答案严格分离。
4. **Hidden expert keys**，四页正式评分要点及确认记录，保存在测试进程无法访问的位置。
5. **Results + Decision report**，24份答案的逐来源对照、六项评价、成本、有效性及路线建议。

底层日志只保留实际模型最终答案、工具调用和输出、文件访问、计量、错误、重试和人工介入。沿用现有项目状态文件承接阶段，不增加数据库、DAG、MCP、RAG或新的治理层。展示给合作者的材料围绕这五类组织。

## 附录B　一次运行怎样从资料走到最终答案

以下为计划中的接口示意，不是已经实现的框架或实验结果。

```json
{
  "bounded_answer": [
    {
      "text": "A scientific statement, with its conditions.",
      "quantity": "geometry | population | transition_rate | observable | mechanism | other",
      "evidence_ids": ["source-or-output-id"],
      "inference_role": "author_reported | fitted | conditional_prediction | independent_validation | descriptive | unknown"
    }
  ],
  "evidence_used": [],
  "analysis_performed": [],
  "unresolved_alternatives": [],
  "next_action_if_needed": []
}
```

`quantity`和`inference_role`是三组共同的科学类型标签，不包含应有答案；它们仍可能构成共同提醒效应，须按第5.3节解释A的基线。只填写合法标签不会获得科学分数。文本与标签冲突照样算错。

```python
workspace = mount_only(public_case, common_tools, arm_allowed_guidance)
session = start_fresh_model(frozen_model, frozen_budget)
draft = session.solve(question, workspace)  # Agent自行阅读和选工具
format_feedback = check_common_format(draft)
conflicts = check_two_public_rules(draft, public_facts) if arm == "C" else []
revised = one_optional_revision(draft, format_feedback, conflicts, remaining_budget)
final_conflicts = check_two_public_rules(revised, public_facts) if arm == "C" else []
visible = publish_with_claim_level_restrictions(revised, final_conflicts, arm)
save_answer_and_actual_tool_records(draft, revised, visible)
```

这里真正需要Agent完成的是从资料和目标自行选择步骤。公共事实用于核对角色和时间类型，隐藏评分要点只由评分者读取。检查器在最终修订后重新判断仍存在的明确冲突；未知事实和无关结论不被整体删除。保存原稿与展示稿，才能判断C是在帮助形成正确答案，还是仅仅减少可见内容。
