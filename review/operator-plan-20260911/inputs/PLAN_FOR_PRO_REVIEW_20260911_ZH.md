## 1. 背景与约束计划的证据

### 1.2 做到了哪

33 条规则（11 篇方法论文各 3 条）、一个按方法族取规则的选择器、一个隔离运行框架（gpt-5.6-luna，无网络容器，两个工具，40 次调用上限）、四个真实案例、74 次预注册对照运行（1.20 美元）。

## 2. 计划

### 2.0 总纲

科学交付物是 HSP90 的"量 × 可信 × 依据"表，由六个冻结算子按固定流程算出，不等 Agent。规则表拆三张、每条改写成四句，内容进算子的前置条件、参数范围和结论上限，不再以文字给模型。Agent 从"自由写代码回答"改为"选算子、配参数、解释输出"，提交门要求每条数值主张绑定一次算子运行。最后用 16 份答复回答：算子 Agent 比固定脚本多做出什么，比自由 Agent 少错什么。

### 2.1 规则表

拆成三张：`papers`（11 行）、`source_rules`（33 + 3 行）、`rule_index`（`layer` ∈ A/B/C/D，`operation_tags`，`method_tags`）。每条 `proposed_project_rule` 改写成四句：适用条件（当前操作是什么才触发）、科学理由、对应操作（算子名）、结论边界。示例：

| 规则 | 现在 | 四句版 |
|---|---|---|
| C007-RULE-002（Bengtsen 2020） | 要求 BME/MaxEnt operator, MD prior, perturbation/entropy and source weights；否则 INTEGRATION_OPERATOR_UNVERIFIED | 适用：当前操作是用实验数据重新分配已有构象权重。理由：重加权只在候选池内移动权重，造不出缺失构象，不给动力学。操作：`reweight_ensemble`，须写明先验、正则强度、来源权重。边界：拟合改善只能说"在此候选池和误差模型下更一致"。 |
| C001-RULE-002（Hellenkamp 2018） | 要求 correction, R0, dye/AV and propagated uncertainty；否则 UNCERTAINTY_UNRESOLVED | 适用：当前操作是 FRET 效率换算距离或 FRET 距离与结构比较。理由：直方图宽度不等于距离不确定性。操作：`fret_efficiency_to_distance`。边界：无校准来源时只报相对次序。 |

加三条本项目在数据上发现的规则，来源写我们的报告，标"未经专家审"：P-RULE-001 差值符号丢失绝对吻合度（HSP90 NOE 对照）；P-RULE-002 跨分子距离取最近映像、分子内距离补整分子（DHFR 与 ADK）；P-RULE-003 转述数字必须绑定计算输出（首轮 A2、DHFR A1）。

送审 11 条（C007 三条、C012 三条、C006-RULE-003、C010-RULE-001、P-RULE 三条）给合作者，每条选保留 / 改写 / 删除并附一句理由。

### 2.2 六个算子（HSP90）

| 算子 | 回答什么 | 参数（冻结默认） | 前置条件 | 结论上限 | 实现 |
|---|---|---|---|---|---|
| OP1 `direction_runs` | 首个持续方向与相反段 | 持续点数 {5, 20, 50} | 时间单调；1 ns 步长；符号规则已写明 | 相反段 ≠ 完整转变；单位是轨迹；不报速率 | 封装现有 `run_time_anatomy_v0.py` |
| OP2 `noe_reference_crosswalk` | 开放方向点落在开态 NOE 参照内的比例 | τ {0.5, 1, 2} Å；一致 ≥ 0.8；相对 ≥ 0.5 | 第 2 列是原生违例（非第 3 列伪距离）；80 × 1001 点 | 同源再分析；容差是操作定义 | 封装现有 `noe_crosswalk_v1.py` |
| OP3 `state_population_convergence` | 占比随时间收不收敛 | 状态定义编号；块长；bootstrap 1000 次按轨迹重采样 | 状态定义冻结；单位是轨迹 | 单向进入后驻留 ≠ 平衡 | 新写 ~80 行 |
| OP4 `transition_count` | C→O、O→C 各几次，有无返回 | 滞后阈值 | 状态定义含进入与离开阈值 | 无往返不能说收敛 | 新写 ~50 行 |
| OP5 `excursion_detection` | 离开一簇未到另一簇的片段 | 两簇半径（取参照系综半径） | 半径由 NMR 系综定 | 中间态 ≠ 转变；1 ns 采样漏短片段 | 新写 ~60 行 |
| OP6 `coverage_vs_reference` | MD 采到两个 NMR 系综都没覆盖的区域 | 半径 | NMR 系综是模型不是 ground truth | MD 独有 ≠ 新状态 | 新写 ~40 行，用现有列 |

六个都是成熟方法（RMSD 状态指派、块 bootstrap、NOE 违例分类）。OP3 到 OP6 从现有派生表算，不重读原始轨迹。固定流程 F 是六个算子按默认参数顺序跑，输出 D1 表；它在第一次 Agent 运行前就存在，既是科学交付物也是评分依据。

### 2.3 运行框架改四处

1. 工具：`list_operators`、`run_operator(name, params)`（越界拒绝并返回范围）、`workspace`（read/search/python 只用于探索和画图）、`submit`。
2. `submit` 里每条 `origin=current_calculation` 的主张必须带 `result_id` 指向本次某次 `run_operator` 的输出；自由 Python 的数只能标 `exploratory`，报告单列。
3. 提交门：题面模板里每个子问题指定必需算子；缺哪个退回一次，退回信息只写"子问题 2 需要 OP2，未运行"，不给数值。替代现在的数字出现检查。
4. 系统提示加一句：每个子问题必须通过 `run_operator` 得到结果后才能回答。

Agent 保留的判断：选哪几个算子、参数在范围内怎么取、结果怎么解释、与论文的关系、下一步。

### 2.4 框题模板四栏

要区分的差异 / 子问题与必需算子 / 竞争解释（人填） / 请求的结论层级。HSP90 草案：三件事分开（方向、到达、占比与转变）；(1) OP1；(2) OP2；(3) OP3 + OP4；(4) OP5 + OP6；竞争解释写"相反段可以是真实转变、部分倾转、初始模型不确定、读数越过符号边界；占比不收敛可以是非遍历也可以是状态定义太细"；允许有限窗口内的方向与到达，不允许占比、速率、机制。评分依据从四栏、论文和 F 的输出写，不从规则写。

### 2.5 准入进建包脚本

`admission_check.py`（已能检 6/6、0/3）改为在冻结前由建包脚本调用，任一 FAIL 不写 `FREEZE.json`；准入卡只给人看，不再放进 `/source`。补一项：从原始轨迹抽 3 帧重算派生读数，差 > 0.01 Å 判 FAIL（HSP90 这项现在是 NOT_ATTEMPTED；DHFR 出事的根源就是派生表和坐标之间无核对）。

### 2.6 结论检查改成主张绑定，先在历史答复上证伪

每条数值主张按 `result_id` 找算子输出的对应字段，按容差（距离 0.02 Å，计数 0）比较；单位和窗口从算子输出继承。先在 8 份历史答复上重放：13 处错误里 7 处数值错误（E0 审计表第 1、2、3、8、9、11、12 行）至少抓到 5 处，干净答复零误报；达不到不上线。

| 结果 | 条件 | 决定 |

## 5. 请审查者回答

对每一条给出 成立 / 不成立 / 证据不足，加一到三句理由。

1. **形式判断。** 把规则内容改写成算子的前置条件与结论上限，并让 Agent 只能通过算子产生数值主张，是否比"文字贴进提示"更可能减少 1.2 节那类错误（不适用前提迁移、零计算转述）？有没有一种它会引入的新错误是本计划没防的？
2. **算子清单。** 六个算子是否覆盖 7 月 28 日要的分析（转变次数、占比收敛与 bootstrap、excursion、覆盖度）？哪一个的默认参数或前置条件写得不对？OP5 用参照系综半径定两簇边界、OP6 用 nearest_open / nearest_closed 判覆盖，这两处是否是成熟方法的合理最小版本？
3. **占比的可信判断。** OP3 对闭合起始组预期"不收敛、单向进入"，对开放起始组预期"全程停留"。用"前 N ns 与全长占比之差按轨迹 bootstrap"来判断收敛，在 40 条各 1 μs、单向且论文自认非遍历的数据上，是否是可辩护的判据？有没有更标准的做法应当替换？
4. **评测设计。** 三组（F / D / O）、两题、每组 4 次、五核心单元、双人盲评，能否区分"算子设计有效"与"题目变具体了"这两种解释？拆题实验已经显示明确要求会提高覆盖；O 组的题面和 D 组完全相同，这一点是否足以隔离？
5. **判定规则。** 3 节的三行判定有没有漏掉一种结果？"O 比 F 多给出一条正确且有信息的内容"这个条件是否太弱或太模糊，应如何写成可数的标准？
